## 0. 结论摘要

在 `/blocks` 页面增加一个对话窗口，用**树莓派本机 Ollama** 把自然语言变成积木，并支持修改当前工作区。

核心结论：

1. **只走本地**。助手模块直接调用 `OLLAMA_HOST`（默认 `http://localhost:11434`），不读取 `LLM_BACKEND`，**没有任何切换到豆包 / 云端的路径**。
2. **模型不直接输出 Blockly JSON**。模型输出受约束的「动作计划 JSON」，由后端确定性代码组装成 Blockly 工作区 JSON。小模型只负责填动作和参数，结构正确性由代码保证。
3. **两种修改模式都做**：`rewrite`（整份重写，可撤销）和 `append`（追加到主链，不碰已有积木）。
4. **三道保险**：Ollama 结构化输出约束 → `compile_program()` 白名单校验 → 中文规则解析兜底。任何一步失败都不会把坏程序塞进工作区。
5. **生成结果永不自动运行**，必须人工点「运行」。
6. **积木 ↔ Python 对照**用前端确定性生成器，不调用模型；只展示、可复制，不执行。

预期效果（板载 0.5B 或局域网 7B）：

| 指令类型 | 路径 | 预期耗时 |
|---|---|---|
| 短指令（≤2 个动作，无嵌套） | 规则快速通道 | < 50 ms |
| 多动作 / 含重复、条件（树莓派 0.5B） | 板载模型 | 15 ~ 60 s |
| 多动作 / 含重复、条件（局域网 7B） | 笔记本 GPU | 3 ~ 8 s |
| 模型不可用 / 超时 | 规则兜底 / 明确报错 | < 100 ms |

## 1. 背景与目标

### 1.1 背景

积木页当前是纯手工拖拽：学生要把「看到人脸→前进→说话」翻译成积木，先要想清楚动作顺序，再找积木、改参数。对低龄学生，这个翻译过程比编程本身还难。

设备上已经部署 Ollama（`qwen2.5:0.5b`），语音对话链路已经在用，但能力只停留在「聊天 + 调技能」，没有进入积木编辑。

### 1.2 目标

| 编号 | 目标 |
|---|---|
| G1 | 对话框输入中文，生成可编辑、可运行的积木程序 |
| G2 | 能把当前工作区作为上下文，按指令**重写**或**追加** |
| G3 | 全程离线，只调用本机 Ollama，不联网、不调用云端模型 |
| G4 | 生成的程序必须通过白名单编译校验，非法内容不落地 |
| G5 | 生成结果可预览、可撤销，绝不自动运行 |
| G6 | 模型不可用时功能仍可用（规则兜底），不能白屏或长时间转圈 |
| G7 | 提供「积木 ↔ Python」对照视图，确定性生成，与积木语义一致（不走模型） |

### 1.3 非目标（本期不做）

- 不做变量、列表、表达式（当前积木引擎本来就不支持）
- 不做多轮复杂推理（最多带 3 轮历史，不做工具调用 / Agent 规划）
- 不做云端模型（豆包 / 通义）接入
- 不做「AI 解释积木」「AI 排查错误」（原设计文档 11.2 / 11.3，另行排期）
- 不做项目云同步、多人协作
- 不自动修复运行期错误
- 不做「自然语言直接生成 Python 脚本」（本期只做积木 ↔ Python 对照）

### 1.4 使用场景

```text
场景 A（新手）：输入「前进两秒，然后笑一下」
        → 生成 2 块积木，点运行

场景 B（改写）：已有「前进→表情」，输入「把速度改慢一点，再拍张照」
        → 整份重写：前进 100 2秒 → 表情 开心 → 拍照

场景 C（追加）：已有巡逻程序，输入「最后加一句你好呀」
        → 主链尾部追加「说 你好呀」，前面不动

场景 D（模型没开）：输入「看到人脸就打招呼」
        → 规则解析失败但匹配到模板 → 生成「如果看到人脸 → 表情开心 + 说你好呀」
```

## 2. 现有基础与约束

### 2.1 可复用的能力

| 模块 | 位置 | 复用方式 |
|---|---|---|
| 积木白名单 | `petcar/blocks/catalog.py` | 作为 Prompt 里允许的动作清单 + 组装时的枚举来源 |
| 编译校验 | `petcar/blocks/compiler.py` | 生成后调用 `compile_program()` 做最终门禁 |
| 工作区序列化 | Blockly `serialization.workspaces.save/load` | 前端整份提交、整份载入 |
| Ollama 客户端 | `petcar/core/llm_backends.py` `OllamaBackend` | 直接复用，增加可选生成参数 |
| 运行时配置 | `petcar/core/runtime_config.py` | 复用 `OLLAMA_HOST` / `OLLAMA_MODEL` 面板值 |
| 学生 Python 接口 | `petcar/student_api/emoji_robot.py` | 作为 Python 对照代码的目标 API（需补 2 个薄方法，见 18.4） |
| 前端日志 | `app.js` `appendLog()` | 对话结果与错误写进控制台 |

### 2.2 关键约束

| 约束 | 说明 |
|---|---|
| 内存 | Pi 4B 2G。0.5B q4 约 400MB，叠加摄像头、OpenCV、可能还有 MediaPipe，余量不大，禁止并发推理 |
| 模型位置 | 推荐放局域网 GPU 笔记本（见 17 章），此时树莓派只负责 Web 与硬件，内存约束大幅缓解 |
| 速度 | 0.5B 在板上约 7 token/s，300 token 输出 ≈ 45 s，必须控制输出长度 |
| 模型能力 | 0.5B 无法稳定输出嵌套 JSON，必须用结构化约束 + 短输出 + 兜底 |
| 网络 | 教室可能无外网；功能不能依赖任何 CDN / 云端接口 |
| 运行态 | 积木运行期间改工作区不影响已提交的程序，但会造成高亮错位，应用按钮需禁用 |
| 安全 | 生成内容只走白名单，不存在 `eval` / `exec`；必须限制动作数、嵌套深度、文本长度 |

## 3. 设计原则

1. **模型只做翻译，不做结构**。动作结构、ID、字段类型、数值钳制全部由代码生成。
2. **一个内部契约**。无论模型还是规则引擎，都产出同一个 `plan` 对象，后续组装、校验只有一份实现。
3. **失败要快、要能看懂**。超时、模型未启动、输出格式错误，都要在 1 秒内给出明确提示，不能无限转圈。
4. **预览即真相**。对话只展示摘要和动作清单，真正落地必须点「应用」，应用前先存快照。
5. **本地优先，规则兜底**。简单指令不排队等模型；模型不可用不影响基本可用性。

### 4.2 一次「重写」的完整时序

```text
1. 用户输入「看到人脸就前进两秒然后打招呼」，模式 = 重写
2. 前端 save(workspace) 得到当前程序 JSON，POST /api/blocks/assist
3. 后端把当前程序压平成文本（最多 30 行）
4. 策略判断：含「如果 / 重复 / 一直」等嵌套关键词 → 走模型
5. 调 Ollama /api/chat，format = JSON Schema，temperature=0.1，num_predict=320
6. 模型返回 {"actions":[...]}（结构由 grammar 约束）
7. 解析 + 语义校验 + 数值钳制，得到 plan
8. plan → Blockly 工作区 JSON（生成 ai_* ID）
9. compile_program() 校验；失败则把错误回喂模型重试 1 次
10. 返回前端：program + summary + notes + source
11. 前端存快照 → load(program) → 控制台打印摘要
12. 用户确认无误后点「运行」（或点「撤销」回滚）
```

### 4.3 「追加」模式的差异

- 前端仍提交完整工作区（用于理解上下文）。
- 第 4 步 Prompt 追加一句：`只输出需要新增的动作，不要重复已有动作`。
- 第 8 步不是重建，而是把新动作接到主链尾部；遇到尾部是 `forever` 时插到 `forever` 之前，并在 `notes` 里说明。
- 第 9 步校验的是「拼接后的完整工作区」。

## 5. 动作计划契约（plan）

### 5.1 为什么不用 Blockly JSON 作为模型输出

Blockly 工作区 JSON 需要正确维护 `next.block`、`inputs.DO.block`、`fields`、`id`、坐标，0.5B 模型几乎必然写错一个层级。让模型输出**扁平、无 ID、无坐标**的动作计划，结构风险全部转移到后端代码。

### 5.2 plan 结构

```json
{
  "actions": [
    {"type": "move_for", "dir": "forward", "speed": 150, "seconds": 2},
    {"type": "show_emotion", "emotion": "happy"},
    {"type": "say", "text": "你好呀"},
    {
      "type": "if_sees",
      "target": "face",
      "body": [
        {"type": "say", "text": "你好呀"}
      ]
    }
  ]
}
```

### 5.3 动作与积木的映射

| plan.type | Blockly type | 字段 | 取值范围 | 缺省 |
|---|---|---|---|---|
| `move_for` | `move_for` | `dir` / `speed` / `seconds` | 见枚举 / 50–255 / 0.1–30 | speed=150, seconds=2 |
| `move_stop` | `move_stop` | — | — | — |
| `look` | `look` | `dir` / `degrees` | up,down,left,right,center / 1–45 | degrees=10 |
| `show_emotion` | `show_emotion` | `emotion` | 12 种表情枚举 | happy |
| `say` | `say` | `text` | 1–100 字（建议 ≤30） | — |
| `photo` | `photo` | — | — | — |
| `wait` | `wait` | `seconds` | 0–600 | 1 |
| `if_sees` | `if_sees` | `target` / `body` | face,tennis,color / 动作数组 | — |
| `repeat` | `repeat` | `times` / `body` | 1–100 / 动作数组 | times=3 |
| `forever` | `forever` | `body` | 动作数组 | — |

枚举值必须与 `catalog.py` 完全一致（`MOTIONS` / `PTZ_DIRS` / `EMOTIONS` / `TARGETS` 的英文 value）。

### 5.4 plan 限制

| 项 | 限制 | 处理 |
|---|---|---|
| 动作总数 | rewrite ≤ 30，append ≤ 15 | 超出截断并记 `notes` |
| 嵌套深度 | ≤ 2（`if_sees` 里放 `repeat` 已经是第 2 层） | 超出丢弃该分支 |
| `say` 文本 | ≤ 100 字 | 截断 |
| 数值越界 | 统一钳制，不报错 | 记 `notes`，例如「速度已限制为 255」 |
| 非法枚举 | 拒绝该动作 | 计入 `errors`，触发重试 |
| `repeat.times` 为 0 或负数 | 钳制为 1 | 记 `notes` |

## 6. 后端设计

### 6.1 新增模块

```text
petcar/blocks/
├── plan.py         # plan 契约、workspace ↔ text、plan → workspace、校验与钳制
├── assistant.py    # 策略选择、Prompt、Ollama 调用、解析、重试、降级
└── rules.py        # 中文关键词规则引擎（与模型输出同一 plan 格式）
```

### 6.2 `plan.py`

职责：

- `PLAN_SCHEMA`：给 Ollama 结构化输出用的 JSON Schema（与 5.3 表一致）
- `workspace_to_text(workspace, limit=30) -> str`：把当前程序压平成带序号的清单，供 Prompt 使用
- `plan_to_workspace(plan, mode, base=None) -> dict`：生成 Blockly 工作区
- `validate_plan(plan) -> (clean_plan, errors, notes)`：枚举、范围、深度、数量
- `find_chain_tail(workspace)`：追加模式定位主链尾部

压平格式示例：

```text
当前积木（3 块）：
1. 前进 速度150 2秒
2. 表情 开心
3. 一直重复
   3.1 前进 速度100 1秒
   3.2 左转 速度100 0.5秒
```

超过 30 行时在末尾追加 `...（其余 N 块已省略）`。

### 6.3 `assistant.py`

```python
class BlockAssistant:
    def __init__(self, host=None, model=None, timeout=None):
        ...

    def status(self) -> dict:
        """返回 {available, model, models, schema_supported, last_error}"""

    def assist(self, message: str, program: dict | None,
               mode: str = "rewrite",
               strategy: str = "auto",
               history: list | None = None) -> dict:
        """返回 {ok, source, program, summary, notes, elapsed_ms, attempts}"""
```

内部流程：

```text
assist()
 ├─ 输入校验（message 非空、≤200 字；program ≤64KB）
 ├─ 拿不到非阻塞锁 → {"ok": False, "code": "busy"}
 ├─ strategy = auto 时判断是否走规则快速通道
 ├─ 走模型：
 │    ├─ 构造 messages（system + few-shot + 当前程序 + 指令）
 │    ├─ POST {host}/api/chat，format=PLAN_SCHEMA
 │    ├─ 解析 JSON（去代码围栏、全角修正、容错逗号）
 │    ├─ validate_plan
 │    ├─ plan_to_workspace + compile_program
 │    ├─ 失败 → 带错误重试 1 次（最多 2 次调用）
 │    └─ 仍失败 → 降级规则
 └─ 规则：rules.parse(message, current_text) → plan → 同一条组装/校验路径
```

**并发控制**：`threading.Lock()`，非阻塞获取。已有请求在跑时直接返回 `busy`，前端禁用发送按钮。避免 2G 板上两个推理把内存打爆。

**超时**：`requests.post(..., timeout=(3, BLOCKS_AI_TIMEOUT))`，默认 60 s。前端另有 90 s AbortController 兜底。

**keep_alive**：请求体带 `"keep_alive": "10m"`，避免每次生成都重新加载模型（首次加载慢，后续快）；内存紧张时可通过配置改成 `"0"` 用完即卸。

### 6.4 Prompt 设计

System Prompt（固定，约 400 token）：

```text
你是积木编程机器人的「动作规划器」。只输出 JSON，不要输出解释、Markdown、代码围栏。

可用动作（type 只能取下列值）：
1. move_for  参数 dir, speed, seconds
   dir: forward 前进 / backward 后退 / leftSlide 左移 / rightSlide 右移 /
        turnLeft 左转 / turnRight 右转 / spin 原地旋转
   speed: 50-255 整数，没说就用 150
   seconds: 0.1-30，没说就用 2
2. move_stop 无参数
3. look  参数 dir(up/down/left/right/center), degrees(1-45，默认10)
4. show_emotion 参数 emotion，只能取：
   neutral happy sad angry surprised sleepy love wink laugh thinking scared confused
5. say  参数 text，不超过 30 个汉字
6. photo 无参数
7. wait 参数 seconds(0-600)
8. if_sees 参数 target(face 人脸 / tennis 网球 / color 颜色), body(动作数组)
9. repeat 参数 times(1-100), body(动作数组)
10. forever 参数 body(动作数组)

输出格式：{"actions":[...]}
硬性规则：
- 只能使用上面 10 种动作，不许发明新动作
- 嵌套最多 2 层，动作总数不超过 30
- 「打招呼」= show_emotion(happy) + say("你好呀")
- 「一直 / 不停地」用 forever；「重复N次」用 repeat
- 不要输出坐标、id、颜色、积木类型名
```

Few-shot（3 条，固定）：

```text
用户：前进两秒然后笑一下
输出：{"actions":[{"type":"move_for","dir":"forward","speed":150,"seconds":2},{"type":"show_emotion","emotion":"happy"}]}

用户：看到人脸就打招呼
输出：{"actions":[{"type":"if_sees","target":"face","body":[{"type":"show_emotion","emotion":"happy"},{"type":"say","text":"你好呀"}]}]}

用户：一直往前走，每走一秒就左转半秒
输出：{"actions":[{"type":"forever","body":[{"type":"move_for","dir":"forward","speed":150,"seconds":1},{"type":"move_for","dir":"turnLeft","speed":150,"seconds":0.5}]}]}
```

User Prompt（每次拼接）：

```text
当前积木：
{workspace_to_text(program)}

修改方式：{整份重写 | 只输出需要新增的动作}
用户指令：{message}
```

历史消息只保留最近 3 轮，且只保留纯文本 `user/assistant`；不把上一轮的 program 放进历史，避免上下文膨胀。

### 6.5 模型输出解析

按顺序尝试：

1. 去掉 ```json / ``` 围栏
2. 全角转半角：`，：｛｝［］""` → ASCII
3. 从第一个 `{` 开始做括号配对（跳过字符串内的括号），截取第一个完整对象
4. 删除对象/数组结尾多余逗号
5. `json.loads(..., strict=False)`
6. 如果顶层是数组，自动包成 `{"actions": [...]}`
7. 如果字段名是中文（`动作`/`类型`），做一次简单别名映射

任何一步失败都算 `parse_error`，进入重试。

### 6.6 校验与重试

```text
第一次输出 → parse → validate → assemble → compile
   │             │         │          │
   │             └─ 失败 ──┴──────────┴─→ 收集错误列表
   ▼
重试一次：messages += [assistant(上次输出), user("你上次的输出有这些问题：... 只输出修正后的 JSON")]
   │
   └─ 仍失败 → 规则引擎兜底 → 仍失败 → {"ok": false, "code": "generate_failed"}
```

重试只带错误摘要（最多 3 条），不重发整个 Prompt，减少 token。

### 6.7 规则引擎 `rules.py`

目标不是理解自由语言，而是覆盖高频教学指令，保证「模型挂了也能用」。

**预处理**

- 全角转半角，去掉语气词「请 / 帮我 / 让小车 / 能不能」
- 按 `然后|接着|再|，|。|；` 切分子句
- 数字归一：「两秒」→ 2 秒，「半秒」→ 0.5 秒

**关键词表**

| 意图 | 关键词 | 产出 |
|---|---|---|
| 前进 | 前进、向前、往前走、往前 | `move_for dir=forward` |
| 后退 | 后退、向后、往后走 | `move_for dir=backward` |
| 左移 / 右移 | 左移、右移、横着走 | `leftSlide` / `rightSlide` |
| 左转 / 右转 | 左转、右转、拐弯 | `turnLeft` / `turnRight` |
| 转圈 | 转圈、旋转、原地转 | `move_for dir=spin seconds=3` |
| 停止 | 停、停下、停止 | `move_stop` |
| 表情 | 开心、难过、生气、惊讶、困、爱心、眨眼、大笑、思考、害怕、困惑 | `show_emotion` |
| 说话 | 说、讲、喊、打招呼 | `say`（引号内文本，否则默认「你好呀」） |
| 拍照 | 拍照、照相、拍一张 | `photo` |
| 等待 | 等、等待 | `wait` |
| 云台 | 抬头、低头、向上看、向下看、左看、右看、回正 | `look` |
| 条件 | 看到、如果看到、一看到 | `if_sees`（目标取人脸/网球/颜色，后一个子句作为 body） |
| 重复 | 重复N次 | `repeat` |
| 循环 | 一直、不停地、反复 | `forever`（其余子句作为 body） |

**宏**

| 说法 | 展开 |
|---|---|
| 打招呼 | `show_emotion happy` + `say "你好呀"` |
| 巡逻 | `repeat 4 [前进 2秒, 右转 1秒]` |
| 表情秀 | `happy → surprised → love → laugh` 依次 |
| 追球 | `if_sees tennis [前进 1秒]`（不承诺真实追踪） |

**匹配率判定**：所有子句都能匹配才算成功；否则返回 `None`，由上层报「没听懂，请换一种说法」。绝不猜测性生成。

### 6.8 对 `llm_backends.py` 的改动

`OllamaBackend.chat()` 目前写死 `num_predict` / `temperature`，且不支持 `format`。增加可选参数，保持向后兼容：

```python
def chat(self, messages, tools=None, *,
         num_predict=None, temperature=None,
         response_format=None, keep_alive=None) -> dict:
```

- `num_predict` 默认仍读 `config.LLM_NUM_PREDICT`
- `response_format` 非空时写入 payload 的 `format`
- 结构化输出返回 400（Ollama 版本过旧）时，本次降级为 `format="json"`，并记 `schema_supported=False`

**不新增后端类型**，`assistant.py` 只实例化 `OllamaBackend`。

## 7. API 设计

### 7.1 `POST /api/blocks/assist`

请求：

```json
{
  "message": "看到人脸就前进两秒然后打招呼",
  "program": {"blocks": {"languageVersion": 0, "blocks": []}},
  "mode": "rewrite",
  "strategy": "auto",
  "history": [{"role": "user", "content": "..."}]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `message` | 是 | 1–200 字 |
| `program` | 否 | Blockly 工作区 JSON，≤64KB；缺省视为空程序 |
| `mode` | 否 | `rewrite`（默认）/ `append` |
| `strategy` | 否 | `auto`（默认）/ `model` / `rules` |
| `history` | 否 | 最近 3 轮纯文本 |

成功响应（HTTP 200）：

```json
{
  "ok": true,
  "source": "llm",
  "model": "qwen2.5:0.5b",
  "mode": "rewrite",
  "program": {"blocks": {"languageVersion": 0, "blocks": []}},
  "summary": "如果看到人脸 → 开心 + 说「你好呀」",
  "action_count": 3,
  "notes": [],
  "attempts": 1,
  "elapsed_ms": 21340
}
```

失败响应（HTTP 200，`ok=false`，前端当聊天消息展示）：

```json
{
  "ok": false,
  "code": "model_unavailable",
  "message": "本地模型没有响应，已尝试规则生成但没匹配上。",
  "hint": "请确认 Ollama 正在运行，或换一种更简单的说法。",
  "source": "rules",
  "elapsed_ms": 320
}
```

错误码：

| code | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| `empty_message` | 400 | 指令为空 | 不发送 |
| `bad_program` | 400 | 工作区 JSON 非法或过大 | 提示刷新页面 |
| `busy` | 200 | 上一次生成还没结束 | 禁用发送按钮，提示稍等 |
| `model_unavailable` | 200 | Ollama 连不上 | 提示 + 建议用快速模式 |
| `timeout` | 200 | 超过 `BLOCKS_AI_TIMEOUT` | 提示缩短指令 |
| `parse_error` | 200 | 模型输出无法解析（重试后） | 提示换说法 |
| `generate_failed` | 200 | plan 校验/编译失败且规则兜底也失败 | 提示换说法 |
| `append_after_forever` | 200 | 追加点落在 `forever` 之后 | 已自动改插到 `forever` 前并提示 |

> 不用 5xx，是因为这些都属于「助手没帮上忙」，不是服务异常，前端统一按对话气泡展示更自然。

### 7.2 `GET /api/blocks/assist/status`

```json
{
  "enabled": true,
  "available": true,
  "host": "http://localhost:11434",
  "model": "qwen2.5:0.5b",
  "models": ["qwen2.5:0.5b"],
```

`flask_app.create_app()` 增加 `block_assistant=None` 参数，`block_service` 存在时一并注册：

```python
if block_service is not None:

```

`register_block_api(app, service, assistant=None)`，`assistant is None` 时 `/assist` 返回 `{"ok": false, "code": "disabled"}`，保持向后兼容。

### 8.3 应用与撤销

```javascript
let undoStack = [];   // 最多 5 份快照

function applyProgram(program) {
  if (running) { toast('程序运行中，请先停止'); return; }
  const snapshot = Blockly.serialization.workspaces.save(workspace);
  undoStack.push(snapshot);
  if (undoStack.length > 5) undoStack.shift();
  Blockly.serialization.workspaces.load(program, workspace);
  saveDraft();
  appendLog({ level: 'info', text: '已应用 AI 生成的积木（可撤销）' });
}

function undoApply() {
  if (!undoStack.length) return;
  if (running) { toast('程序运行中，请先停止'); return; }
  const prev = undoStack.pop();
  Blockly.serialization.workspaces.load(prev, workspace);
  saveDraft();
  appendLog({ level: 'info', text: '已撤销，恢复上一版积木' });
}
```

约束：

- 运行中禁用「应用 / 撤销」
- 应用后自动居中视图（`workspace.scrollCenter()`）
- 不清空控制台，保留操作痕迹
- 对话记录只放内存，刷新即清空（避免 localStorage 无限膨胀）

## 10. 失败与降级矩阵

| 环节 | 失败情况 | 处理 | 用户看到 |
|---|---|---|---|
| 状态检查 | Ollama 未启动 | 标记规则模式 | 黄色徽标 |
| 策略 | 简单指令 | 直接规则 | 秒回，来源「规则」 |
| 模型调用 | 连接拒绝 | 规则兜底 | 「本地模型没响应，已用规则生成」或失败提示 |
| 模型调用 | 超时 60s | 规则兜底 | 「生成超时，已尝试规则」 |
| 模型输出 | 非法 JSON | 修复 → 重试 1 次 → 规则 | 成功或失败提示 |
| 模型输出 | 枚举非法 | 记录错误 → 重试 | 成功或失败提示 |
| plan 校验 | 动作超限 | 截断 + notes | 正常应用，notes 说明 |
| plan 校验 | 深度超限 | 丢弃深层分支 + notes | 正常应用，notes 说明 |
| 组装 | 生成 ID 冲突 | 服务端统一 `ai_` 前缀 + 计数 | 无感 |
| 编译 | 白名单校验失败 | 重试 → 规则 → 报错 | 失败提示，不落地 |
| 追加 | 主链无 `event_start` | 自动创建 | 正常 |
| 追加 | 主链尾部是 `forever` | 插到 `forever` 之前 | notes 说明 |
| 并发 | 已有生成在跑 | 返回 `busy` | 提示稍等 |

## 11. 性能预算

| 项 | 预算 | 说明 |
|---|---|---|
| 规则生成 | < 50 ms | 纯字符串处理 |
| 模型首 token | 2–8 s | 已加载时；冷加载可能 10–20 s |
| 模型整体 | 15–60 s | 输出 ≤ 320 token，0.5B ≈ 7 token/s |
| 内存 | 模型 ≤ 600 MB | 0.5B q4 + 上下文 |
| 请求体 | ≤ 64 KB | 工作区 JSON |
| 并发 | 1 | 非阻塞锁 |
| 前端等待 | ≤ 90 s | AbortController 兜底 |

**降耗措施**

1. 输出上限 320 token，Prompt 里要求「不要空格、不要解释」
2. `workspace_to_text` 最多 30 行
3. 历史只留 3 轮纯文本
4. 结构化输出只传精简 schema（不含描述文字）
5. 简单指令不走模型

## 12. 安全设计

| 风险 | 对策 |
|---|---|
| 生成任意代码 | 只组装白名单积木，无 `eval` / `exec` |
| 通过文本注入让模型输出越权内容 | 输出受 JSON Schema 约束 + 枚举校验 + 白名单编译 |
| 动作数爆炸导致长时间运行 | 动作 ≤ 30，运行时长仍有 `MAX_RUNTIME_S=600` 兜底 |
| 文本超长 | `say` ≤ 100 字，请求 ≤ 200 字 |
| 隐私 | 只发往 `localhost` 或教师指定的 Ollama 地址；不接云端 |
| 误执行 | 只载入工作区，不自动运行；运行中禁止应用 |
| 内存耗尽 | 单并发 + 超时 + `keep_alive` 可调 |

## 15. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 0.5B 语义理解差 | 复杂指令生成错误 | 结构化输出 + few-shot + 重试 + 规则兜底；建议 4G 板换 `qwen2.5-coder:1.5b` |
| 生成太慢 | 用户以为卡死 | 显示已等待秒数、可取消、简单指令走规则 |
| 内存紧张 | OOM / 视频流卡顿 | 单并发、`num_predict` 限制、`keep_alive` 可配 |
| Ollama 版本旧 | `format` schema 不支持 | 探测后降级 `format="json"`，再失败走规则 |
| 模型输出方言化 | 动作名/枚举错 | 别名映射 + 枚举校验 + 重试 |
| 追加产生死代码 | 学生困惑 | 检测尾部 `forever`，自动插到其前面并提示 |
| Blockly 序列化版本变化 | 载入失败 | 固定 `languageVersion: 0`；应用前 try/catch，失败回滚快照 |
| 与语音助手抢模型 | 语音和积木同时推理 | 共用一把生成锁；语音侧已有自己的限流，必要时共用 `BlockAssistant._lock` |

## 17. 局域网 GPU 服务器部署形态（已定）

### 17.1 选型结论

| 项 | 值 |
|---|---|
| 笔记本显存 | 6–8 GB |
| 模型 | `qwen2.5-coder:7b`（Q4_K_M，约 4.7 GB） |
| 上下文 | 4096 |
| 显存占用 | 约 5.2 GB（模型 + KV cache） |
| 输出速度 | 40–60 token/s（RTX 4060 级） |
| 300 token 计划 | 6–10 s |
| 备用模型 | 6 GB 显存吃紧时退到 `qwen2.5-coder:3b`，或 `num_ctx=2048` |

6 GB 显存跑 7B + 4096 上下文约剩 1 GB 余量，够用，但生成时不要同时跑游戏或浏览器硬件加速。8 GB 可以开到 8192 上下文，不过积木生成用不到，保持 4096 更省显存、首 token 更快。

模型放笔记本后，树莓派不再承担推理，2 GB 内存的 OOM 风险与「生成时视频流卡顿」问题一并消失。

### 18.2 生成方式

### 18.4 EmojiRobot 需要补的两个薄方法

`EmojiRobot` 现有 `forward()` 等方法不接受速度/时长，也没有 `sees()`，直接映射会丢参数或无法表达条件积木。需要补两个薄封装（不改现有方法签名）：

```python
def move(self, direction: str, speed: int = 150, seconds: float | None = None):
    """与积木 move_for 语义一致：设速度 → 启动 → 计时 → 停。"""
    if not self.mecanum:
        return
    self.mecanum.set_speed(int(speed))
    getattr(self.mecanum, direction)()
    if seconds:
        time.sleep(seconds)
        self.mecanum.stop()

def sees(self, target: str) -> bool:
    """与积木 if_sees 语义一致，复用积木引擎的感知结果。"""
    if self.perception is None:
        from petcar.blocks.perception import PerceptionCache
        self.perception = PerceptionCache(self.camera)
    return self.perception.sees(target)
```

`self.perception` 在 `__init__` 里初始化为 `None`，惰性创建，不改变现有启动路径。

### 18.5 语义一致性保障

1. **字符串 golden**：固定工作区 fixture → 期望 Python，逐字比对；积木改文案或参数格式时测试会立刻失败。
2. **行为一致性**：同一程序分别走积木解释器与生成代码（mock 硬件，记录调用序列），断言动作顺序、方向、速度、时长一致。
3. 生成器只做「翻译」，不做优化（不合并动作、不删死代码），保证与积木一一对应。

### 18.6 界面

右侧栏标签从两个变三个：`控制台 / AI 助手 / Python`。

- Python 标签内容是只读 `<pre><code>`，深色主题下用等宽字体
- 顶部一行提示：「这是积木对应的 Python 参考代码，不会自动执行」
- 右上角「复制」按钮（`navigator.clipboard`，失败时回退 `document.execCommand`）
- 空程序显示注释 `# 还没有积木`
- 工作区有游离积木时，顶部提示「有 N 个积木未连接，未生成代码」

### 18.7 边界

| 情况 | 处理 |
|---|---|
| 存在未连接的积木 | 不生成，显示提示 |
| `forever` 后面还有积木 | 生成时注释标记为不可达 |
| `say` 文本含引号 / 换行 | 转义后再输出 |
| 表达式/变量（本期没有） | 无需处理 |
