## 0. 结论摘要

先给结论，后续章节展开论证。

1. **积木编辑器采用 Blockly（Zelos 渲染器），本地打包，不依赖 CDN。**
   面向 PC / 笔记本浏览器（Chrome、Edge），不做平板 App，不做小程序。原因：Blockly 的拖拽、吸附、嵌套、撤销、序列化、无障碍都是成熟能力，自研成本远高于收益；Zelos 渲染器接近 Scratch 的圆润外观，适合儿童。
2. **积木只在浏览器里"编辑"，执行在车端（树莓派）完成。**
   浏览器把整份程序一次性提交给 Flask，由车端解释器执行。不能"一个积木一次 HTTP"——网络抖动会毁掉运动控制时序。
3. **新增一层"积木 IR + 解释器"，不执行生成的 Python 代码。**
   积木先编译成受控 IR（JSON AST），由车端调度器解释执行。避免 `eval`、避免任意代码执行，同时能精确实现"停止/急停/超时/高亮当前积木"。
4. **程序执行通道与现有 `drivers`、`skills`、`student_api` 复用，但新增 `RobotRuntime` 门面。**
   现有 `SkillManager` 返回字符串、`move` 用 `threading.Timer` 自动停，不适合积木的精确时序与取消语义，因此积木执行走新的运行时门面，底层仍调用同一批驱动。
5. **教学闭环：积木 → 只读 Python 视图 → 导出 `.py`。**
   Python 视图由 Blockly 生成器产出，映射到现有 `petcar.student_api.EmojiRobot`，让学生能从积木平滑过渡到 Python。代码视图只用于教学和导出，不参与实际执行。
6. **通信采用 REST + SSE。**
   控制指令用 REST；运行状态、积木高亮、控制台、传感器快照用 SSE 单向推送。SSE 在 Flask 上零额外依赖，比 WebSocket 更适合树莓派课堂环境。
7. **安全优先：急停、运动租约、程序超时、步数预算、块数/嵌套限制。**
   积木引擎面向学生，必须假设程序会写出死循环、连续前进、并发抢电机等情况。

## 1. 背景、目标与范围

### 1.1 背景

现有 `petcar` 已经具备完整的"硬件 + AI 宠物"能力：

- 驱动层：麦轮底盘、二自由度云台、USB 摄像头、OLED、TTS、ASR。
- 核心层：表情引擎、情绪引擎、LLM 对话、技能管理、PID 追踪。
- Web 层：Flask 中控面板、MJPEG 视频流、REST API、检测标注。
- 学生接口：`petcar.student_api.EmojiRobot`，提供表情、动作、云台、说话、拍照、对话等极简方法。

但目前面向学生的入口只有两种：改 Python 代码，或使用中控面板点按钮。缺少一套"低门槛、可组合、可保存、可展示"的图形化编程入口。

### 1.2 目标

构建一套运行在 Web 上的积木编程引擎，使学生能够：

1. 用中文积木拼出"看到人脸 → 前进 → 打招呼 → 开心"这类程序。
2. 在 PC 浏览器中完成编辑、运行、停止、保存、导入导出。
3. 实时看到小车画面、当前执行到哪一块积木、控制台输出。
4. 把积木程序一键切换成 Python 代码查看/导出，衔接现有 `EmojiRobot` 教学体系。
5. 教师可以把作品保存到小车本地，下节课继续。

### 1.3 非目标（本期不做）

- 不做平板 App、不做微信小程序、不做原生客户端。
- 不做多车协同调度、不做云端账号体系。
- 不做 3D 仿真或虚拟小车（可作为后续独立课题）。
- 不做 Scratch 社区式的作品分享平台。
- 不追求"任意 Python 代码可视化"，只覆盖本项目硬件能力。

### 1.4 使用场景

| 场景 | 设备 | 描述 |
|---|---|---|
| 课堂演示 | 教师 PC + 投影 | 浏览器打开小车页面，现场拼积木、运行、讲解 |
| 学生练习 | 学生机浏览器 | 通过局域网访问小车，编辑并运行自己的程序 |
| 作品保存 | 小车本地 | 程序以 JSON 存在树莓派，断电不丢 |
| 课程衔接 | 学生机浏览器 | 积木视图 / Python 视图随时切换，导出 `.py` |
| 离线环境 | 无外网局域网 | 所有前端资源本地打包，不访问 CDN |

## 2. 现有基础与约束

### 2.1 可复用的能力

| 现有模块 | 位置 | 积木引擎中的用途 |
|---|---|---|
| `MecanumDriver` | `petcar/drivers/mecanum.py` | 前进/后退/平移/转向/旋转/停止、调速 |
| `PTZDriver` | `petcar/drivers/ptz.py` | 云台上下左右、回正 |
| `CameraDriver` | `petcar/drivers/camera.py` | 最新帧、拍照、人脸检测、人脸追踪 |
| `detectors.py` | `petcar/drivers/detectors.py` | 人/宠物/杯子/球/屏幕/网球/运动/颜色检测 |
| `EmotionEngine` | `petcar/core/emotion_engine.py` | 12 种表情、眨眼、说话嘴动、气泡文字 |
| `TTSDriver` / `ASRDriver` | `petcar/drivers/` | 说一句话、听一句话 |
| `ChatAgent` / `LLMBackend` | `petcar/core/` | AI 对话积木、AI 生成积木 |
| `PIDTracker` | `petcar/core/pid_tracker.py` | 人脸/颜色自动追踪积木 |
| `Flask` 应用 | `petcar/api/flask_app.py` | 新增积木页面与 API |
| `EmojiRobot` | `petcar/student_api/emoji_robot.py` | Python 代码视图/导出的目标 API |

### 2.2 关键约束

1. **硬件约束**：树莓派 4B / 2GB，I2C 上同时挂 PCA9685（电机 + 舵机）和 OLED。OLED 全帧刷新会占用 I2C 总线，导致电机指令排队，因此积木执行不能高频刷屏。
2. **网络约束**：课堂往往是局域网甚至无外网。前端资源必须本地化，不能依赖 `cdn.jsdelivr.net`。
3. **交互约束**：主要使用鼠标键盘。大屏投影时字号要大；不需要触屏手势。
4. **安全约束**：学生程序可能写出死循环、持续前进、并发抢电机。必须有独立于积木逻辑的兜底停止机制。
5. **兼容约束**：不破坏现有中控面板与 REST API；积木引擎以新增模块方式接入。
6. **现有语义不足**：`MoveSkill` 用 `threading.Timer` 在后台自动停，无法被程序取消或查询；`SkillManager.execute()` 返回中文字符串，无法拿到结构化结果。积木执行需要新的运行时抽象。

## 3. 关键设计决策

### 3.1 前端积木库：Blockly vs Scratch Blocks vs 自研

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Blockly** | 成熟拖拽/吸附/嵌套/撤销/缩放/序列化；支持自定义积木和代码生成器；Apache-2.0；可完全离线 | 默认外观偏工程化，需要主题定制 | **采用** |
| Scratch Blocks | 外观最接近 Scratch，儿童熟悉 | 与 Scratch VM/GUI 耦合深，单独使用文档少，体积大 | 不采用 |
| 自研 SVG/DOM 编辑器 | 完全可控、体积小 | 拖拽吸附、嵌套、撤销、无障碍全部要自己实现，风险极高 | 不采用 |

**具体选型**：

- Blockly 11.x，锁定版本，产物放入 `petcar/api/static/blocks/vendor/blockly/`。
- 渲染器使用 `zelos`，主题自定义为 PetCar 配色。
- 不引入 Node/npm 构建链。浏览器端使用原生 ES Module + 预编译 Blockly 产物，树莓派上无需安装前端工具链。
- 关闭 Blockly 的在线字体/音效外链，`media` 目录本地化。
- 中文语言包使用 `msg/zh-hans.js`。

### 3.2 执行位置：浏览器 vs 车端

| 方案 | 说明 | 问题 |
|---|---|---|
| 浏览器逐块调用 API | 每个积木发一次 HTTP | 网络抖动导致时序错乱；无法表达 50ms 级控制；并发和取消复杂 |
| 浏览器生成 Python 后 `exec` | 服务端执行生成的代码 | 任意代码执行风险；停止/超时不可控；错误栈难映射回积木 |
| **整份程序下发 + 车端 IR 解释器** | 浏览器只提交 JSON，车端编译成 IR 并调度执行 | 需要自研解释器，但可控性和安全性最好 | **采用** |

### 3.3 程序格式：Blockly JSON vs XML

采用 **Blockly JSON**（`Blockly.serialization.workspaces.save/load`）：

- 体积更小，易与元数据（项目名、作者、设置）放在同一个 JSON 文件。
- 便于服务端做结构校验、统计块数、做 AI 生成后的程序注入。
- Blockly 官方主推 JSON 序列化，XML 属于兼容路径。

### 3.4 实时通道：SSE vs WebSocket vs 轮询

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **SSE** | Flask 原生支持；单向推送足够；自动重连；实现简单 | 只能服务端 → 客户端 | **采用** |
| WebSocket | 双向、低延迟 | 需要 `flask-sock`/异步服务器；树莓派部署复杂度上升 | 不采用 |
| 轮询 | 最简单 | 高亮和日志延迟明显，请求量大 | 仅作为 SSE 不可用时的降级 |

浏览器 → 服务端的输入（网页按钮、键盘事件）用普通 `POST /api/blocks/input` 解决。

### 3.5 运行语义：解释器 vs 生成代码

采用 **IR 解释器**，理由：

1. 不需要 `eval` / `exec`，不存在任意代码执行。
2. 每个 IR 节点保留 Blockly block id，可实现"当前积木高亮"和"错误定位到积木"。
3. 取消、超时、运动租约、步数预算都可以在调度器统一实现。
4. 同一份 IR 可以同时驱动"真实执行"和"AI 解释/调试"。

Python 代码由前端 Blockly 生成器产出，仅用于教学展示与导出，不参与运行。

```text

  （PCA9685 电机）        （舵机 / USB 摄像头）     （OLED / 语音 / LLM）
```

### 4.2 一次运行的完整数据流

```text
1. 学生点击"运行"
2. 浏览器 POST /api/blocks/run {project_id 或 program}
3. 服务端：
   a. 校验项目（块数、深度、字段范围）
   b. Blockly JSON → IR（Compiler）
   c. RunController 进入 running，启动解释器线程
   d. SSE 推送 run_state
4. 解释器按 50Hz tick：
   a. 执行 IR 节点
   b. 通过 RobotRuntime 调用驱动
   c. 推送 block_enter / console / sensor
   d. 检查取消、超时、运动租约
5. 程序结束 / 停止 / 出错 / 超时：
   a. 停止电机、停止程序启动的追踪
   b. SSE 推送 done
   c. RunController 回到 idle
```

### 4.3 三条执行/呈现路径

| 路径 | 输入 | 输出 | 用途 |
|---|---|---|---|
| 积木运行 | Blockly JSON | IR → 解释执行 | 默认运行方式 |
| Python 视图 | Blockly JSON | Python 源码（基于 `EmojiRobot`） | 教学对照、导出 |
| AI 生成 | 自然语言 | IR → Blockly JSON | 降低起步门槛、课堂演示 |

三条路径共享同一份"积木目录"（`catalog.json`），保证类型、默认值、取值范围一致。

## 5. 积木语言设计

### 5.1 形状与类型约定

| 形状 | Blockly 结构 | 用途 |
|---|---|---|
| Hat（帽子块） | `hat: "cap"` | 事件入口，如"当程序开始" |
| Statement（语句块） | `previousStatement` + `nextStatement` | 顺序执行 |
| C 型块 | 带 `statement input` | 循环、条件 |
| Boolean | `output: "Boolean"` | 条件、感知判断 |
| Reporter | `output: "Number" / "String" / null` | 数值、文本、变量 |

类型系统：

- `Number`：整数/小数，统一按 `float` 存储。
- `String`：文本，最长 500 字符。
- `Boolean`：真/假。
- `Any`：仅变量与"AI 回复"等动态值使用。

编译器做静态类型检查；运行期再做一次宽容转换（例如数字块填入字符串 `"2"` 时给出明确错误，而不是静默失败）。

### 5.2 分类与配色

| 分类 | 颜色 | 说明 |
|---|---|---|
| 事件 | 黄色 | 程序入口与外部触发 |
| 运动 | 蓝色 | 底盘 |
| 云台 | 青色 | 摄像头朝向 |
| 表情 | 紫色 | OLED 脸、文字、动画 |
| 说话 | 粉色 | TTS、对话 |
| 感知 | 绿色 | 摄像头与检测器 |
| 控制 | 橙色 | 等待、循环、条件、停止 |
| 运算 | 紫蓝色 | 数学、比较、逻辑、文本 |
| 变量 | 红色 | 变量读写 |
| AI | 金色 | LLM 对话、AI 生成（进阶） |

### 5.3 积木清单（P0 + P1）

#### 事件

| Blockly type | 积木文案 | 形状 | 参数 | 语义 |
|---|---|---|---|---|
| `event_start` | 当程序开始 | hat | - | 启动主任务；每个程序必须有且仅有一个 |
| `event_key` | 当按下按键 %1 | hat | 空格 / 回车 | 浏览器按键经 `/input` 上报 |
| `event_button` | 当点击网页按钮 %1 | hat | 按钮名 | 右侧面板提供可命名按钮 |
| `event_face` | 当看到人脸 | hat | 冷却秒数 | 订阅感知快照；默认冷却 1 秒 |
| `event_wake` | 当听到唤醒词 | hat | - | 依赖语音主循环，P1 |

#### 运动

| Blockly type | 积木文案 | 形状 | 参数 | 语义 |
|---|---|---|---|---|
| `move_for` | 向 %1 以速度 %2 移动 %3 秒 | statement | 方向 / 速度 / 秒 | 设置电机，等待，自动停止；受运动租约保护 |
| `move_hold` | 开始向 %1 以速度 %2 移动 | statement | 方向 / 速度 | 持续移动，直到"停止运动"或程序结束 |
| `move_stop` | 停止运动 | statement | - | 立即释放电机 |
| `set_speed` | 把速度设为 %1 | statement | 0-255 | 只改变后续运动的速度 |

方向枚举：前进、后退、左平移、右平移、左转、右转、原地旋转。

#### 云台

| Blockly type | 积木文案 | 形状 | 参数 | 语义 |
|---|---|---|---|---|
| `look` | 云台向 %1 转动 %2 度 | statement | 上/下/左/右/回正 / 1-45 | 相对增量；回正忽略角度 |
| `look_center` | 云台回正 | statement | - | 水平/垂直归位 |
| `track_start` | 开始追踪 %1 | statement | 人脸 / 颜色 | 启动 PID 追踪会话 |
| `track_stop` | 停止追踪 | statement | - | 停止并清空目标框 |

#### 表情

| Blockly type | 积木文案 | 形状 | 参数 | 语义 |
|---|---|---|---|---|
| `show_emotion` | 显示表情 %1 | statement | 12 种表情 | `EmotionEngine.set_emotion` |
| `show_face` | 显示眼睛 %1 嘴巴 %2 | statement | 眼型 / 嘴型 | 复用 `Face/EyeStyle/MouthStyle` |
| `blink` | 眨一下眼 | statement | - | `blink_now()` |
| `oled_text` | 在屏幕显示文字 %1 | statement | 文本 | `oled.show_text`，截断到 21 字符 |
| `text_bubble` | 显示气泡文字 %1 持续 %2 秒 | statement | 文本 / 秒 | `emotion.text_bubble` |

12 种表情：中性、开心、难过、生气、惊讶、困倦、爱心、眨眼、大笑、思考、害怕、困惑。

#### 说话

| Blockly type | 积木文案 | 形状 | 参数 | 语义 |
|---|---|---|---|---|
| `say` | 说 %1 | statement | 文本 / 是否带表情 | TTS 异步播放 + 嘴动动画；按文本长度估算等待 |

### 5.4 变量与作用域

- 程序级全局变量，运行开始时初始化为 0 / 空字符串 / 假（依声明类型）。
- 变量名允许中文，长度 1-12 字符，不允许纯数字和关键字。
- P0 不做列表、字典、局部变量、函数；这些放到 P2。
- 变量值不跨运行持久化，避免"上节课的变量影响这节课"。

### 5.5 并发语义

积木程序天然会出现多个事件帽子块并发。规则如下：

1. `event_start` 启动一个主任务；其他事件帽子在运行期间按需派生任务。
2. 同一事件默认冷却 1 秒，最多同时存在 3 个实例；超过则丢弃并写日志。
3. 全局最多 8 个任务，超过则丢弃新任务并写警告。
4. 电机采用 **last-wins**：后发出的运动指令抢占当前运动权，前一个运动积木提前结束并在控制台提示"运动被其他积木接管"。
5. 云台、表情、说话不抢占，按调用顺序执行；说话不等待真实音频结束，只等待估算时长。
6. 追踪会话是独占资源：重复"开始追踪"不会叠加，重复"停止追踪"幂等。

## 7. 运行时设计

### 7.1 调度模型

采用 **协作式生成器调度**，单线程解释器 + 50Hz tick：

```text
Tick 循环（每 20ms）：
  for task in 任务表:
      if task.wait 已就绪:
          在 2ms 预算内反复推进 task
          until task 再次让出 / 结束 / 预算耗尽
  sleep 到下一个 tick
```

任务用 Python 生成器实现：

```python
def exec_move_for(self, node):
    self.rt.move_start("forward", speed)
    deadline = now() + seconds
    while now() < deadline:
        if self.ctx.cancelled or self.rt.motion_owner() is not self.task:
            break
        self.rt.renew_motion_lease()
        yield Wait(deadline)          # 让出到下一个 tick
    self.rt.move_stop_if_owner(self.task)
```

为什么不用 `asyncio`：

- 现有驱动全部是同步阻塞接口，改造为 async 收益有限。
- 生成器调度没有事件循环依赖，兼容 Flask 的同步线程模型。
- 取消、预算、单步调试都更容易实现。

### 7.2 等待与取消

| IR 操作 | 让出方式 | 取消响应 |
|---|---|---|
| `wait` | `Wait(deadline)` | 每个 tick 检查取消，立即返回 |
| `move_for` | `Wait(deadline)` + 续租 | 取消时立即停电机 |
| `wait_until` | 每 tick 求值条件 | 立即返回 |
| `repeat` / `forever` | 每轮结束让出一次 | 下一轮检查 |
| 纯计算 | 2ms 预算后强制让出 | 下一个 tick 检查 |

停止流程：

```text
RunController.stop(reason)
  → ctx.cancel_event.set()
  → 解释器线程在每个等待点检查并退出
  → runtime.release_all()（停电机、停追踪、清运动所有权）
  → 推送 done
  → 线程 join（最多 1 秒），超时则强制 runtime.emergency_stop()
```

### 7.3 运动租约与看门狗

这是积木引擎最关键的安全机制。

**问题**：解释器线程卡死、生成器异常、事件任务互相抢占时，不能让电机一直转。

**设计**：

1. `RobotRuntime` 维护 `motion_owner`、`lease_deadline`、`moving`。
2. 每次运动指令设置 `lease_deadline = now + 0.6s`。
3. 执行中的运动积木每个 tick 续租。
4. 独立的 `MotionWatchdog` 线程每 0.2 秒检查一次：若 `now > lease_deadline`，立即停电机，写警告日志。
5. `move_hold`（持续移动）由运行控制器在程序运行期间续租；程序结束、停止、出错时立即停止。
6. 急停直接绕过解释器，调用 `mecanum.stop()` 并清空租约。

**边界说明**：如果整个 Python 进程被 `kill -9`，看门狗线程也会消失，PCA9685 会保持最后的 PWM 输出。软件层无法覆盖这种情况。缓解措施：

- 硬件电源开关 / 急停按钮（必须有）。
- 可选 P2：独立看门狗进程（`petcar/blocks/supervisor.py`）通过心跳监督主进程，心跳丢失即通过 I2C 停电机。

### 7.4 设备门面 `RobotRuntime`

积木不直接调用 `SkillManager`，而是调用 `RobotRuntime` 的强类型方法：

```python
class RobotRuntime:
    # 运动
    def move_start(self, direction: str, speed: int, owner: object) -> None: ...
    def stop_motion(self) -> None: ...
    def renew_motion_lease(self) -> None: ...
    def motion_owner(self) -> object | None: ...

    # 云台
    def look(self, direction: str, degrees: float) -> None: ...
    def look_center(self) -> None: ...

    # 表情
    def emotion(self, name: str) -> None: ...
    def custom_face(self, eyes: str, mouth: str) -> None: ...
    def bubble(self, text: str, seconds: float) -> None: ...
    def oled_text(self, text: str) -> None: ...

    # 语音
    def say(self, text: str, emotion: str | None) -> None: ...
    def listen_once(self, timeout: float) -> str: ...

    # 感知（读缓存，非阻塞）
    def sees(self, target: str) -> bool: ...
    def face_count(self) -> int: ...
    def face_position(self) -> str: ...
    def photo(self) -> str | None: ...

    # 追踪
    def track_start(self, target: str) -> None: ...
    def track_stop(self) -> None: ...

    # 清理
    def release_all(self) -> None: ...
    def emergency_stop(self) -> None: ...
```

设计要点：

- 所有方法必须是**短耗时**的（毫秒级），检测类操作走缓存。
- 电机、云台、OLED 各自加锁，避免与中控面板同时操作导致 I2C 错乱。
- 程序运行期间，中控面板的运动/云台手动控制返回 `409`，只保留急停和状态查看。避免"程序在前进，老师又点了后退"。

### 7.5 感知快照 `PerceptionCache`

摄像头检测不能在解释器线程里同步跑（NanoDet / TFLite 单帧 100-200ms，会直接卡死 tick）。

设计：

- 独立采样线程，按需启动（有程序使用感知积木、或有事件帽子订阅时）。
- 采样频率默认 5Hz，可通过配置调整为 2-10Hz。
- 每帧结果缓存为不可变快照：

```python
{
  "ts": 1762380000.123,
  "frame_w": 640,
  "frame_h": 480,
  "faces": [{"cx": 320, "cy": 240, "w": 80, "h": 80, "score": 0.97, "pos": "center"}],
  "objects": {"person": 1, "cat": 0, "ball": 1},
  "color": {"found": true, "x": 100, "y": 80, "w": 40, "h": 40, "pos": "left"},
  "motion": true
}
```

- 感知积木读快照，不触发新推理。
- 快照过期（>1 秒）时返回上一帧并标记 `stale`，控制台只在首次出现时提示。
- 程序结束且无其他订阅者时，停止采样线程，释放 CPU。
- 颜色识别复用现有 `color_cfg`（`/api/color_cfg` 可调）。

### 7.6 感知语义

| 积木 | 判断依据 |
|---|---|
| 看到人脸 | `len(faces) > 0` |
| 看到人 | NanoDet/TFLite `person` 类存在 |
| 看到宠物 | `cat` / `dog` / `bird` 任一类存在 |
| 看到网球 | COCO `sports ball` 或 HSV 网球色检测 |
| 看到颜色 | `detect_color` 找到最大块 |
| 看到运动 | `detect_motion` 相邻帧差异超阈值 |
| 人脸在左/中/右 | 最大人脸中心 `cx` 落在画面三等分区间 |
| 颜色块在左/中/右 | 最大颜色块中心同上 |

所有检测失败（模型缺失、摄像头未开）统一降级为"看不到"，并在控制台给出一次原因说明，而不是让程序崩溃。

### 7.7 语音与表情协调

- `say`：设置表情 → `start_speak(估算时长)` → `tts.speak_async(text)` → 积木等待估算时长。
  估算公式：`max(1.0, 0.18 * len(text))` 秒，上限 30 秒。
- 已知限制：TTS 没有完成回调，等待时长只是估算。P1 可为 `TTSDriver` 增加 `speak_blocking(text, timeout)`，用真实完成事件替代估算。
- `show_emotion` 之后立即执行 `wait`，表情保持；不会被程序结束自动重置（保持最后一次表情），这与现有 `EmotionEngine` 行为一致。
- 程序停止时不清空表情，只停止运动与追踪。

### 7.8 错误模型

| 阶段 | 错误类型 | 处理 |
|---|---|---|
| 编译 | 结构/白名单/范围/类型 | 不运行，返回 `blockId` 列表，前端标红 |
| 运行 | 除零、变量未定义、类型转换失败 | 停止整个程序，控制台显示积木链路，SSE `error` |
| 运行 | 感知不可用、TTS 不可用 | 降级并继续，控制台警告一次 |
| 运行 | 超时、步数超限 | 停止程序，`done.reason=timeout` |
| 运行 | 运动被抢占 | 当前运动块提前结束，控制台提示，不中断整个程序 |
| 系统 | 解释器异常 | `emergency_stop()`，SSE 报错，运行状态回 idle |

默认策略是"运行错误停止整个程序"，对儿童更可预测。P1 可增加"出错时停止当前任务"选项。

### 7.9 运行状态机

```text
idle ──run──► compiling ──ok──► running ──done──► idle
                  │                │
                  └──error──► idle └──stop/estop──► stopping ──► idle
```

- 同一时间只允许一个运行实例；重复 `run` 返回 `409`。
- `estop` 在任何状态都可用，优先级最高。
- `stop` 在 `compiling` 阶段可直接取消编译。

- 工具箱分类与颜色来自 catalog，避免前端硬编码。
- 禁止删除 `event_start` 以外的约束由校验器保证，不在 UI 上做过度限制。
- 变量使用 Blockly 内置变量模型（`Blockly.Variables`），变量面板中文提示。

### 8.3 积木外观与儿童友好

- 大圆角、柔和阴影、分类色块；字号 15px，投影可见。
- 字段下拉使用中文；数字输入默认带影子块，学生可直接改，也可拖入变量。
- C 型块内部有足够的放置空间，避免嵌套后过窄。
- 关键动作块加图标（纯 SVG，不依赖外部图片）。
- 危险块（停止运动、结束程序）使用暖色描边，但不做成红色警报样式。
- 不使用 emoji 作为积木标签，避免不同系统字体差异。
- 支持 Blockly 自带键盘导航与屏幕阅读器标签。

### 8.4 运行高亮与控制台

- 解释器在进入/离开 IR 节点时发送 `block` 事件，前端调用 `workspace.highlightBlock(id)`，离开时清除。
- 高亮事件限流 20 次/秒，避免高频循环把浏览器打满。
- 控制台按级别着色：普通、成功、警告、错误；最多保留 500 行。
- 错误点击控制台条目可跳转到对应积木（利用 `blockId`）。

### 8.5 项目与草稿

- 本地草稿：每次编辑后 1 秒防抖写入 `localStorage`，key 为 `petcar.blocks.draft.<projectId>`。
- 服务端自动保存：编辑停止 20 秒后 `PUT` 项目；失败进入重试队列（最多 5 次）。
- 新建 / 打开 / 另存为 / 导入 / 导出（`.pcar.json`）。
- 导入时校验 `format` 和 `version`；版本不匹配给出迁移提示。
- 项目列表展示名称、作者、更新时间、块数。
- 内置 3 个模板：`基础动作`、`看到人就打招呼`、`颜色追踪`。

### 8.6 Python 视图

- 使用 Blockly 的 Python 生成器，自定义每个积木的 `forBlock` 生成函数。
- 生成代码面向 `petcar.student_api.EmojiRobot`，例如：

```python
from petcar.student_api import EmojiRobot
import time

robot = EmojiRobot()

robot.happy()
for _ in range(3):
    robot.forward()
    time.sleep(1)
    robot.stop()
    robot.say("你好呀", "happy")
```

- 顶部提示："这是积木对应的 Python 参考代码，用于学习，不会直接执行。"
- 支持复制和导出 `.py`。
- 生成器与解释器语义的一致性由"黄金样例测试"保证（见第 13 章）。

### 8.7 离线与容错

- 所有 JS/CSS/字体/媒体本地加载，禁止外链。
- 页面加载时并行请求 catalog 和项目；任一失败给出中文错误与重试按钮。
- SSE 断开自动重连（指数退避，最大 10 秒），重连后拉取 `/status` 对齐状态。
- 运行中关闭浏览器不停止程序（默认策略），重新打开后可继续观看状态。

### 9.5 SSE 事件流

`GET /api/blocks/events`，`Content-Type: text/event-stream`。

事件类型：

| event | 频率 | data |
|---|---|---|
| `run_state` | 状态变化 | `{state, run_id, reason}` |
| `block` | ≤20/s | `{id, phase: "enter"|"exit"}` |
| `console` | ≤20/s | `{level, text, ts}` |
| `sensor` | 5/s | `{faces, face_pos, sees, stale}` |
| `motion` | 状态变化 | `{moving, owner, dir, speed}` |
| `error` | 出错时 | `{blockId, message, stack: ["r1","m1"]}` |
| `done` | 结束时 | `{reason: "completed|stopped|error|timeout", elapsed_s}` |
| `ping` | 15s | 注释行，保持连接 |

示例：

```text
event: run_state
data: {"state":"running","run_id":"run-...","reason":"start"}

event: block
data: {"id":"m1","phase":"enter"}

event: console
data: {"level":"info","text":"前进 1 秒","ts":1762380612.5}

event: done
data: {"reason":"completed","elapsed_s":6.8}
```

实现要点：

- 每个客户端一个订阅队列，队列满时丢弃最旧的 `block`/`sensor` 事件，保留 `error`/`done`。
- 使用 `stream_with_context`。
- 响应头：`Cache-Control: no-cache`、`X-Accel-Buffering: no`（若有反向代理）。
- 服务端每 15 秒发送 `: ping` 注释行。

## 10. 安全设计

### 10.1 分层防护

| 层级 | 措施 |
|---|---|
| 前端 | 字段范围由 Blockly 约束；危险块二次确认；运行按钮在运行中禁用 |
| 编译器 | 白名单、类型检查、范围检查、块数/深度限制、`break` 位置检查 |
| 解释器 | 总时长限制、步数预算、每 tick 时间预算、取消检查、错误即停 |
| 运行时 | 运动租约、看门狗、设备锁、程序独占运动控制 |
| 系统 | 急停接口、电源开关、可选独立看门狗进程 |

### 10.2 具体限制

| 限制项 | 默认值 | 可配置 |
|---|---|---|
| 单程序最大块数 | 1000 | 是 |
| 最大嵌套深度 | 25 | 是 |
| 单项目文件大小 | 1 MB | 否 |
| 程序最大运行时长 | 600 秒 | 是（上限 1800） |
| 单次运动最大时长 | 30 秒 | 是（上限 60） |
| 速度范围 | 0-255 | 否 |
| 云台角度范围 | 1-45 度 | 否 |
| 文本最大长度 | 500 字符 | 否 |
| 最大并发任务 | 8 | 是 |
| 单事件最大实例 | 3（冷却 1 秒） | 是 |
| 任务每 tick 预算 | 2 ms | 是 |
| 全局每秒步数 | 200000 | 是 |
| 运动租约 TTL | 0.6 秒 | 是 |

### 10.3 停止与急停

- **停止**：程序正常收尾，停电机、停追踪、释放运动权；表情保持。
- **急停**：绕过解释器，立即停电机、清空租约、停止追踪；程序状态标记为 `stopped`。
- 中控面板与积木页面都提供急停按钮，且急停不依赖 SSE 连接。
- 急停后延迟 300ms 再允许新的运行请求，避免连点抖动。

### 10.4 访问控制

- 默认局域网无鉴权，符合课堂使用习惯。
- 可选环境变量 `PETCAR_BLOCKS_TOKEN`：设置后，项目写操作和运行接口要求 `X-PetCar-Token` 头或 URL token。
- 项目 id 使用 UUID；路径只允许 `[a-f0-9-]`，防止路径穿越。
- 不接受上传任意文件到项目目录；导入接口只接受 JSON，且大小受限。
- 不提供任意文件读取、任意 URL 访问、`eval`、`exec`、`subprocess` 相关积木。

### 10.5 课堂冲突控制

- 程序运行时独占运动/云台/追踪控制。
- 多浏览器同时打开时，默认"先运行者持有控制权"；其他标签页运行返回 `409`。
- P2 增加显式"控制权租约"：页面显示"当前控制者"，支持请求/释放/超时释放（30 秒）。

## 11. AI 能力集成

### 11.1 自然语言生成积木

目标：输入"让小车看到人脸就前进两秒然后打招呼"，生成可编辑、可运行的积木程序。

流程：

```text
自然语言
  → 取积木目录子集 + 少样本示例构造 Prompt
  → LLM 输出受控 DSL（与 IR 近似）
  → 服务端校验（白名单/范围/类型）
  → 失败则带错误信息重试 1 次
  → 输出 Blockly JSON
  → 前端确认后载入工作区（不自动运行）
```

设计原则：

- LLM 输出的速度、时长等参数必须经过编译器钳制，不能绕过限制。
- 生成结果只进入编辑器，必须由人确认后运行。
- LLM 不可用（Ollama 未启动、超时）时，使用关键词匹配的模板库兜底：
  - 看到人 → 前进/打招呼
  - 巡逻 → 前进 + 转向循环
  - 追球 → 感知球 + 转向 + 前进
  - 表情秀 → 依次展示表情
- 超时 10 秒；不阻塞运行中的程序。
- 复用现有 `petcar.core.llm_backends.create_llm_backend()`。

### 11.2 积木解释

- `POST /api/blocks/ai/explain`：把 IR 和中文积木文案发给 LLM，生成逐段解释。
- 输出到控制台"AI 导师"标签页。
- 失败时降级为规则模板解释（按块类型生成一句话）。

### 11.3 出错提示

- 运行错误时，把错误积木链、变量值、最近 20 行控制台发给 LLM，生成"可能的原因 + 修改建议"。
- 建议只展示，不自动修改程序。

### 11.4 隐私与离线

- 默认优先本机 Ollama；未配置时使用模板，不把学生作品发到公网。
- 若使用豆包/通义等云端后端，需要在教师端明确开启，并在页面提示。

### 13.3 验收标准

1. 新学生能在 5 分钟内完成"前进 1 秒 + 说你好 + 开心"并成功运行。
2. 点击停止后 300ms 内电机停止；急停 100ms 内停止。
3. `一直重复` 中按急停，程序立即结束，电机不残留转动。
4. 浏览器关闭后程序继续运行；重新打开页面能看到运行状态。
5. 拔掉网线 10 秒再插回，SSE 自动重连，状态一致。
6. 项目保存后断电重启，能完整恢复积木布局和变量。
7. 积木程序导出的 Python 能在 `EmojiRobot` 下运行（人工验证 3 个样例）。
8. 两个标签页同时运行，第二个收到明确的 `409` 提示。
9. 解释器被强制终止时，运动租约在 1 秒内停电机。
10. 树莓派上 10 分钟循环程序运行稳定，CPU 不持续打满。

## 15. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 进程崩溃导致电机继续转 | 安全 | 硬件电源开关；P2 独立看门狗进程；运动租约兜底线程级异常 |
| 学生写出死循环/高频循环 | CPU 占满、无法响应 | 每 tick 预算 + 每秒步数上限 + 总时长限制 |
| 多事件任务抢电机 | 行为不可预测 | last-wins + 控制台提示 + 运行期间禁止手动运动 |
| Blockly 升级破坏 API | 编辑器不可用 | 锁定版本、产物本地化、运行时 catalog 与前端解耦 |
| 解释器与 Python 视图语义漂移 | 教学误导 | 单一 catalog + 黄金样例测试 + 页面注明"参考代码" |
| LLM 返回非法程序 | 无法运行 | 白名单校验 + 自动修复 1 次 + 模板兜底 + 不自动执行 |
| 感知推理阻塞控制 | 卡顿 | 独立采样线程 + 快照读取 + 按需启停 |
| 局域网丢包/SSE 断开 | 状态不同步 | 自动重连 + 重连后拉取 `/status` |
| 摄像头未打开/模型缺失 | 感知积木永远为假 | 降级为"看不到" + 控制台一次性说明 |
| TTS 无完成回调 | 说话积木等待不准 | P0 估算时长；P1 增加阻塞式 TTS |

## 16. 待确认问题

以下问题建议在设计评审时确认，确认后再进入实现：

1. **前端积木库**：是否接受 Blockly（推荐），还是必须做成 Scratch 外观？若必须 Scratch，需要改用 `scratch-blocks` 并接受更高的集成成本。
2. **代码视图定位**：Python 视图只做"只读参考 + 导出"（推荐），还是希望支持"切到 Python 模式直接运行"？后者需要额外的代码沙箱与安全设计。
3. **AI 生成积木**：P0 是否就需要？若课堂环境没有稳定 LLM，建议 P1 再做，P0 先用模板。
4. **断线策略**：浏览器关闭后程序继续运行（推荐，适合课堂展示），还是立即停止（更安全）？可做成项目级设置。
5. **多客户端**：是否需要显式的"控制权租约"，还是简单的"先运行者持有、后运行返回 409"即可？
6. **项目归属**：是否需要学生姓名/班级字段与简单作品列表？还是只按项目名保存？
7. **是否需要平板/触屏适配**：本期按 PC 浏览器设计，若后续需要平板，需要调整右侧面板和工具箱布局。

## 附录 B：Blockly Python 生成器片段

```javascript
pythonGenerator.forBlock['move_for'] = function (block, generator) {
  const dir = block.getFieldValue('DIR');
  const speed = generator.valueToCode(block, 'SPEED', generator.ORDER_ATOMIC) || '150';
  const seconds = generator.valueToCode(block, 'SECONDS', generator.ORDER_ATOMIC) || '1';
  const method = {
    forward: 'forward', backward: 'backward',
    leftSlide: 'leftSlide', rightSlide: 'rightSlide',
    turnLeft: 'turnLeft', turnRight: 'turnRight', spin: 'spin'
  }[dir];
  return `robot.set_speed(${speed})\nrobot.${method}()\ntime.sleep(${seconds})\nrobot.stop()\n`;
};
```

> 说明：`EmojiRobot` 目前没有 `set_speed`，导出前需要在 `student_api` 增加该方法，或在生成器中省略速度。此差异应在实现阶段统一。
