## 1. 目标、学情与约束

### 1.1 教学目标

- **知识**：知道图像是数字；理解 HSV 三要素（色相/饱和度/明度）；知道"阈值 + 掩膜"如何把"红色"变成一块可数的区域。
- **技能**：能在中控面板调出稳定阈值；能用积木写出"看到颜色 → 做动作"的条件程序，并能用循环重复检测。
- **素养**：能说清识别失败的常见原因（光太暗、颜色太淡、目标太小、背景同色），并会用"改阈值 / 靠近 / 换背景"三种办法排查。

### 1.2 学情与课时定位

- 初二学生已具备顺序、循环、简单条件的图形化编程经验（对应第 8 课），但**没有变量和表达式**的使用经验。
- 因此本期积木**不使用 reporter（返回值）**，条件直接内嵌在 C 型积木里，与现有 `if_sees` 保持同一形态。
- 一节课 45 分钟，只做"颜色 → 判断 → 动作"，不做颜色分类/多色统计。

### 1.3 现有引擎约束（设计必须遵守）

| 约束 | 影响 |
|---|---|
| 解释器只支持 statement（无变量、无表达式） | 不做 `sees()` reporter，条件积木自带 C 型分支 |
| 感知走 `PerceptionCache` 快照（3.3Hz） | 积木读快照，不能每帧同步检测；响应延迟约 0.3~0.6s，教学上可接受 |
| 运动有 0.6s 租约 + 看门狗 | 颜色积木本身不直接驱动电机，学生用现有运动积木，安全机制自动生效 |
| 云台是独占资源（中控 PID 追踪 / 积木追踪） | 必须定义仲裁规则，否则两线程抢舵机 |
| 单实例运行、600s 上限 | 课堂演示足够，避免小车跑飞 |

### 2.2 重难点

- **重点**：条件判断与循环的组合；「看到」是一个"每 0.3 秒刷新一次"的状态，不是一次性事件。
- **难点**：阈值与光照的关系。破解办法：**先在中控面板调好，再进积木**，不要把调参和搭积木混在一起。

### 2.3 教具与场地

- 红/橙/黄/绿/蓝 色卡各 1 张（A5，哑光，避免反光）。
- 桌面铺白纸或浅灰纸（**不要用木色桌面**，木色接近橙色，是最大的误识别来源）。
- 小车四周留 40cm 活动区，桌沿加挡条；教师手机/遥控器守在急停旁（网页"急停"按钮或 ESC）。

### 3.3 IR 规范

```json
{ "op": "if_sees_color", "id": "b1", "color": "red",
  "body": [ ... ], "else": [ ... ] }

{ "op": "color_track_start", "id": "b2", "color": "red" }
```

- `body` / `else` 为空时用 `[]`，解释器直接跳过。
- `color` 只允许 `COLOR_PRESETS` 的 key 或 `"custom"`。

### 3.4 编译期校验

| 校验 | 行为 |
|---|---|
| `COLOR` 不在允许集合 | `CompileError`：「不支持的颜色: xx」 |
| `DO` 与 `ELSE` 都为空 | 允许，但运行到该块时日志提示「积木里没有动作」 |
| 程序中用了颜色积木但摄像头不可用 | 运行开始日志 warn：「摄像头未连接，颜色识别不会生效」，不阻止运行 |
| 深度/块数 | 复用现有 `MAX_DEPTH=15`、`MAX_BLOCKS=300` |

编译期顺便收集 `used_colors` 集合（`if_sees_color`、`color_track_start` 中出现过的颜色），写入 IR 顶层：

```json
{ "version": 1, "block_count": 8, "used_colors": ["red"],
  "hats": [ ... ] }
```

- 运行日志（每块 0.8s 去重）示例：
  - `检查是否看到红色`

## 4. 颜色判定设计

### 4.1 预设阈值（OpenCV HSV：H 0~180，S/V 0~255）

与中控面板 P1 的 7 色预设**完全一致**，作为唯一数据源：

| key | 中文 | H 范围 | S 范围 | V 范围 | 备注 |
|---|---|---|---|---|---|
| `red` | 红色 | 170~10（跨界） | 120~255 | 80~255 | `h_min > h_max` 表示跨 0°，需两段 inRange 后 OR |
| `orange` | 橙色 | 8~22 | 120~255 | 100~255 | 与木色/肤色接近，背景要干净 |
| `yellow` | 黄色 | 23~38 | 90~255 | 90~255 | 网球荧光黄偏绿，可能落到 30~40 |
| `green` | 绿色 | 45~80 | 80~255 | 70~255 | 最稳定，课堂首选 |
| `cyan` | 青色 | 85~98 | 80~255 | 70~255 | |
| `blue` | 蓝色 | 100~125 | 80~255 | 60~255 | 深蓝 V 会掉到 60 以下 |
| `purple` | 紫色 | 130~165 | 60~255 | 60~255 | 暗紫易与阴影混淆 |
| `custom` | 自定义 | 面板当前值 | 面板当前值 | 面板当前值 | 学生自己调出来的阈值 |

### 4.2 判定流程（复用 `detect_color`）

1. `cvtColor(BGR→HSV)`，**每帧只算一次**，多颜色共用。
2. 每个颜色一次 `inRange`；红色跨界时拆两段再 `bitwise_or`。
3. 形态学：`MORPH_OPEN 3×3` 去噪 → `medianBlur 5` 平滑边缘。
4. `findContours(RETR_EXTERNAL)`，`contourArea < 300` 丢弃（约等于 17×17 像素，滤掉噪点）。
5. 按外接框面积降序，取**最大块**作为该颜色的目标；`score = min(0.99, area/20000)`。

### 4.3 稳定性（迟滞）

课堂环境有手抖、反光、遮挡，直接"单帧命中"会让程序抖动。采用简单迟滞：

| 事件 | 处理 |
|---|---|
| 本帧命中 | `visible = True`，`miss = 0`，更新 `box` |
| 本帧未命中 | `miss += 1`；`visible = (miss < 2)` |

- 看到：**≤1 个采样周期（0.3s）** 即可响应。
- 丢失：需连续 2 次未命中（约 0.6s）才判为"看不到"，抑制闪烁。
- `stale` 仍按 1.2s 判定；过期后所有颜色视为未看到，并在控制台提示一次。

### 4.4 性能预算（树莓派 4B）

| 项 | 估算 |
|---|---|
| 单色 inRange + 形态学（640×480） | 3~5 ms |
| 4 色 + HSV 转换 | ≈ 20 ms / 次采样 |
| 采样频率 | 3.3 Hz（`INTERVAL = 0.3`） |
| CPU 占用 | < 10%，且只在程序运行期间开启 |
| 人脸 + 网球（原有） | 保持不变，按需执行 |

**按需采样**：`perception.set_needed(["red"])`；`custom` 仅当程序用到才计算，避免无谓开销。

## 5. 配置共享设计（本次必须修掉的坑）

### 5.1 现状问题

- 面板 P1 的可调阈值是 `flask_app.create_app()` 里的局部 dict（`color_cfg`），只服务于面板与 PID 追踪。
- 积木的 `PerceptionCache` 用的是 `DEFAULT_COLOR_CFG` 硬编码（H 25~45）。
- 结果：老师在面板上调好了红色，进积木里"看到颜色"仍然只认黄绿。

### 5.2 方案：新增 `petcar/core/color_cfg.py`

## 6. 运行时设计

### 6.1 感知快照结构（新）

```json
{
  "ts": 1731712345.67,
  "stale": false,
  "face": false,
  "tennis": false,
  "colors": {
    "red":    {"visible": true,  "hit": true,  "miss": 0, "box": [312, 180, 84, 80], "area": 5320, "cx": 354},
    "custom": {"visible": false, "hit": false, "miss": 2, "box": null, "area": 0, "cx": null}
  }
}
```

- `hit`：本帧是否命中；`visible`：迟滞后的对外结论（积木只读这个）。
- `box`：最近一次命中的框，用于 P2 的位置判断与调试叠加。
- 旧字段 `color` 保留一个版本（等于 `colors.custom.visible`），避免前端/第三方脚本立刻报错。

### 6.2 解释器新增分支（service.py）

```python
if op == "if_sees_color":
    color = node["color"]
    label = COLOR_LABEL.get(color, color)
    self.service.log_block(bid, f"检查是否看到{label}")
    if self.runtime.sees_color(color):
        self.service.log("info", f"看到了{label}")
        self._exec_list(node.get("body") or [])
    else:
        self._exec_list(node.get("else") or [])
    return

if op == "color_track_start":
    self.runtime.start_color_track(node["color"])   # 失败写 warn
    self.service.log("info", f"开始追踪颜色：{label}")
    self._sleep(0.2)
    return

if op == "color_track_stop":
    self.runtime.stop_color_track()
    self.service.log("info", "颜色追踪已停止")
    return
```

`_exec_list` 每轮开头仍走 `_check()`，保证停止/超时/急停可打断。

### 6.3 门面方法（runtime.py）

| 方法 | 说明 |
|---|---|
| `set_needed_colors(keys)` | 透传给 `PerceptionCache`，运行开始时由 `BlockService.run()` 调用 |
| `sees_color(key) -> bool` | 读快照 `colors[key].visible`；无摄像头直接 False |
| `color_box(key)` | 返回 `(x, y, w, h)` 或 None（P2 用） |
| `start_color_track(key)` | 调用共享 `PIDTracker`；`ptz`/`camera` 缺失则 warn 并返回 False |
| `stop_color_track()` | 停止并清空目标框，幂等 |
| `release_all()` | 追加 `stop_color_track()`，程序结束/急停时一定收敛 |

### 6.4 云台仲裁（必须实现）

- **同一实例**：PIDTracker 在 `main.py` 创建一次，同时注入 `BlockRuntime` 与 `create_app`，避免两条线程各转各的舵机。
- **规则 1**：`BlockService.run()` 开始时若中控追踪在跑 → 先 `stop()`，日志「中控追踪已停止，积木接管云台」。
- **规则 2**：积木运行期间，中控 `/api/pid/start` 返回 409：「积木程序正在运行，请先停止程序」。
- **规则 3**：程序结束不自动恢复中控追踪，由老师/学生手动点，避免"自己动起来"。
- **规则 4**：`estop` 先停电机、再停追踪、再终止采样线程（沿用现有快速返回策略）。

## 8. 三张任务卡（课堂直接用）

### 任务 1：红绿灯（条件判断）

目标：看到红色就停车并"吓一跳"，其他情况慢速前进。

```text
当程序开始
└─ 一直重复
   └─ 如果看到 [红色] 那么
      ├─ 停止运动
      └─ 显示表情 [惊讶]
      否则
      └─ 向 [前进] 以速度 [120] 移动 [0.3] 秒
```

- 观察点：把红色色卡慢慢靠近摄像头，小车会在 0.3 秒内停住；拿走色卡后继续走。
- 变式：把"红色"换成"绿色"，变成"绿灯行"；加上「说 "红灯停"」。
- 提示：`否则`里用**短时间**移动（0.3s），否则一停一走会很突兀。

### 任务 2：颜色巡逻（循环 + 条件 + 云台）

目标：小车自己转头找绿色，找到就报喜并停下来。

```text
当程序开始
├─ 云台向 [回正] 转动 [10] 度
└─ 一直重复
   └─ 如果看到 [绿色] 那么
      ├─ 停止运动
      ├─ 显示表情 [开心]
      └─ 说 "找到绿色啦"
      否则
      ├─ 原地旋转 0.25 秒
      └─ 等待 0.15 秒
```

- 观察点：控制台会不断打印"没有看到绿色"，找到后打印"看到了绿色"。
- 变式：用「云台向左转动 12 度」代替"原地旋转"，只动摄像头不动车身（更省电、更适合桌面）。
- 提示：`否则`里必须有"动作"，否则循环会空转，日志刷屏。

### 挑战：追色块（闭环控制，P1）

目标：云台自动对准色块，小车缓慢靠近。

```text
当程序开始
├─ 开始追踪颜色 [红色]
└─ 一直重复
   └─ 如果看到 [红色] 那么
      └─ 向 [前进] 以速度 [100] 移动 [0.3] 秒
      否则
      └─ 停止运动
```

- 安全：速度 ≤120，桌面必须留 40cm 活动区，老师手放急停。
- 观察点：云台会自己转，把红色保持在画面中心；车头方向由学生用"前进"控制。
- 结束：加一块「停止追踪颜色」，养成"用完就还资源"的习惯。

### 常见错误与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 一直"没看到" | 阈值不对 / 光太暗 / 目标太小 | 回面板 P1 调 S、V 下限；把色卡靠近；换到白底 |
| 一直"看到了" | 背景同色（木桌≈橙色）、S 设太低 | 提高 `s_min`；换背景；缩小 H 范围 |
| 红绿灯反复闪 | 单帧抖动、反光 | 迟滞已默认 2 帧；让色卡平整、避免灯光直射 |
| 车不动 | 放在"否则"外/条件块没连上 | 检查积木是否嵌在"一直重复"里 |
| 云台不转（挑战） | 中控追踪占着云台 / 摄像头没开 | 先停止中控追踪；看视频流是否有画面 |
| 程序跑一会儿自己停 | 600s 上限 / 运动租约超时 | 属正常保护，重跑即可 |

## 10. 验收与测试

### 10.1 编译/运行自检

| 用例 | 期望 |
|---|---|
| 拖入「如果看到 红色」空 DO/ELSE，运行 | 不报错，日志提示"积木里没有动作" |
| `COLOR` 传非法值（改 JSON） | 400 + 「不支持的颜色: xx」 |
| 程序只用红色，检查快照 | 只计算 `red`，`custom`/其他色不出现 |
| 连续 5 次采样无目标 | 第 2 次后 `visible=false`（约 0.6s） |
| 运行中按"停止" | 电机停、追踪停、采样停，状态回 idle |
| 运行中按"急停" | ≤200ms 返回，电机立即停 |
| 老草稿（含 `if_sees` 的 `color`） | 正常编译运行，行为等同"自定义颜色" |
| 积木运行中点中控"追踪" | 409 + 明确提示 |

### 10.2 课堂验收（5 分钟）

1. 用绿色色卡放在 60cm 处，任务 1 程序 3 秒内停车 → 通过。
2. 移走色卡，小车恢复前进 → 通过。
3. 学生能指着中控视频流说出"框在哪里、为什么框在这里" → 通过。

## 11. 风险与降级

| 风险 | 概率 | 降级方案 |
|---|---|---|
| 教室灯光偏黄导致黄色/橙色误判 | 中 | 只做红/绿/蓝三色；白纸垫底 |
| 摄像头曝光自动调节导致阈值漂移 | 中 | 面板调好后再运行；必要时固定曝光 |
| 多个小组同时调中控面板互相覆盖 `custom` | 中 | 每台车独立 Pi；或本课统一使用预设色，不用 custom |
| 云台仲裁遗漏导致"自己乱转" | 低 | P1 挑战默认不启用；启用前必须先做 6.4 的仲裁 |
| 感知线程占用 CPU 影响运动平顺 | 低 | 按需采样 + 3.3Hz；必要时降到 2Hz |
