## 〇、项目定位与教学示例分层（指导原则）

**PetCar 是集成面板应用，不是教学框架。** 它的首要目标是「大模型体验」：
把语音、表情、视觉识别、云台/底盘控制、技能调用、积木编程都组装进一个
中控面板，让人一次性感受到完整机器人的能力。面板可以持续加功能（技能、
积木、二次开发接口），但代码量和分层会越来越重，不适合作为 Python
课堂教学的阅读材料。

因此项目采用「两套代码、两种用途」：

| 目录 | 定位 | 面向 |
|------|------|------|
| `petcar/` | 集成体验应用：面板 + 大模型 + 技能系统 | 使用者 / 二次开发者 |
| `labs/` | 独立知识点例程：一个文件跑通一个概念 | 课堂教学 / 学生 |
| `demos/` `ai/` | 早期综合实验与 AI 视觉示例 | 拓展参考 |

教学原则：

1. **课堂教学永远用独立例程**：每个 lab 自包含（自带依赖路径、自带 main），
   不 import petcar，单独拷出去就能运行。
2. **例程从产品代码里「抠」出来**：PetCar 里验证过的算法，遇到教学需求时
   抽取成最小可读版本放进 labs。例如手势识别：面板优先 MediaPipe，板卡
   不支持时自动回退 OpenCV 凸包 (petcar/drivers/gesture.py)；纯凸包的最小
   教学版本保留为 labs/lab12_gesture_hull.py。
3. **不为教学拆解产品代码**：不在 petcar 里加教学开关或简化分支，
   产品代码保持工程完整；labs 例程允许删繁就简，只保留当前知识点。
4. **新增能力时预留教学出口**：先在 petcar 完成体验，再按需抽一个 lab
   例程，而不是让课堂直接读 petcar 源码。

### 2.4 帧动画

所有动画由 EmotionEngine 后台线程驱动，帧率 8fps：

| 动画名 | 触发时机 | 描述 |
|--------|----------|------|
| blink | 空闲时每 4-8 秒随机 | 双眼 line_h → open → line_h (0.15s) |
| speak | TTS 播放期间 | 嘴巴 open ↔ closed 循环 |
| think | LLM 推理期间 | 眼睛左右摇摆 + 问号闪烁 |
| happy_bounce | happy/laugh 时 | 整体上下跳动 2px |
| sleepy_nod | sleepy 时 | 头部缓慢下沉 |

### 4.1 BaseSkill 基类

```python
class BaseSkill(ABC):
    name: str           # 工具名，LLM 用这个调
    description: str    # LLM 看到的描述
    parameters: dict    # JSON Schema，function calling 用
    
    @abstractmethod
    def execute(self, **kwargs) -> str:
        """执行并返回人类可读的结果字符串"""
    
    def get_tool_prompt(self) -> str:
        """生成给 LLM 的工具描述"""
        return f"- {self.name}: {self.description}\n  参数: {self.parameters}"

    def get_openai_tool_spec(self) -> dict:
        """OpenAI function calling 格式"""
        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description,
                "parameters": self.parameters,
            }
        }
```

## 六、MoodEngine 情感引擎

### 6.1 情感状态机

```python
class MoodState:
    primary: Emotion          # 当前主情绪
    valence: float = 0.0      # [-1, 1] 正负性
    arousal: float = 0.5      # [0, 1] 唤醒度
    intensity: float = 0.5    # 情绪强度 [0, 1]
    last_update: float = 0    # 上次更新时间
    
    @property
    def emotion_label(self) -> str:  # 根据 valence/arousal 映射到 12 种表情之一
        ...

class MoodEngine:
    def trigger(self, source: str, emotion: str, intensity=1.0):
        """外部事件触发 (LLM 输出 / 用户说话 / 传感器)"""
    
    def tick(self):
        """定时调用 (每秒一次): 情绪自然衰减 + 空闲随机行为"""
    
    def random_idle_behavior(self):
        """空闲 30 秒以上: blink / 打哈欠 / 哼歌 / 左顾右盼"""
    
    def set_mood(self, valence, arousal, intensity=1.0):
        """直接设置情感 (学生 API)"""
```

### 6.2 情绪衰减模型

```
每 tick (1秒):
    valence   *= decay_v   (默认 0.98)
    arousal   *= decay_a   (默认 0.97)
    intensity *= decay_i   (默认 0.95)
    
    当 valence 和 arousal 都接近 0 → primary 自然回到 neutral
    空闲 > 30s 且 arousal < 0.2 → 进入 sleepy
```

## 九、main.py 启动流程

```python
def main():
    # 1. 初始化硬件驱动
    oled = OLEDDriver()
    mecanum = MecanumDriver()
    ptz = PTZDriver()
    camera = CameraDriver()
    
    # 2. 初始化核心引擎
    emotion = EmotionEngine(oled)
    mood = MoodEngine(emotion)
    asr = ASRDriver(mode="whisper")
    tts = TTSDriver(mode="espeak")
    voice = VoiceIO(asr, tts, chat=None, emotion=emotion)
    
    # 3. 初始化 LLM
    llm = OllamaBackend() if check_ollama() else MockBackend()
    chat = ChatAgent(backend=llm, mood_engine=mood, skill_manager=None)
    
    # 4. 注册 Skills
    sm = SkillManager()
    sm.register(MoveSkill(mecanum))
    sm.register(PTZSkill(ptz))
    sm.register(PhotoSkill(camera))
    sm.register(FaceDetectSkill(camera))
    sm.register(FaceTrackSkill(camera, ptz))
    sm.register(WeatherSkill())
    sm.register(AlarmSkill())
    sm.register(EmoteSkill(emotion))
    chat.skill_manager = sm
    
    # 5. 显示欢迎表情
    emotion.set_emotion("happy")
    emotion.text_bubble("我是小宝~")
    
    # 6. 启动后台线程
    threading.Thread(target=mood.tick_loop, daemon=True).start()
    threading.Thread(target=emotion.animation_loop, daemon=True).start()
    
    # 7. 可选: 启动 Flask Web API
    if args.flask:
        from petcar.api import create_app
        app = create_app(chat, emotion, mecanum, ptz, camera)
        app.run(host="0.0.0.0", port=5000)
    
    # 8. 启动语音交互 (前台阻塞)
    if args.voice:
        voice.run_loop()
```

## 十、错误处理与降级策略

| 故障 | 检测 | 降级行为 |
|------|------|----------|
| OLED 未连接 | `luma.oled` 抛异常 | 继续运行，EmotionEngine 改打印日志 |
| 摄像头打不开 | `cv2.VideoCapture().isOpened() == False` | 禁用所有视觉 Skill |
| Ollama 连不上 | HTTP 超时 | 自动切 MockBackend，打印提示 |
| 网络断开 (天气) | requests 超时 | 返回 "网络好像不太好，我稍后再查~" |
| 麦克风无输入 | 录音音量过小 | ASRDriver 返回 None，EmotionEngine 短暂疑惑 |
| USB 音箱没输出 | 尝试 espeak 失败 | 降级到 pyttsx3，再不行就只显示文字 |

## 十三、v1.1 待补能力规划（对标 MicroDuck）

当前 v1.0 已实现「对话 / 对话有动作 / 有表情」三大能力的骨架，但离 MicroDuck 的「活」感还差三块：**物体识别、主动情绪、表达性动作**。本节为下一阶段的实现清单。

### 13.1 物体识别（补第 4 条能力）

#### 13.1.1 现状与缺口

- 当前视觉链路只挂了人脸（YuNet cascade），没有通用物体检测能力
- 无法响应「这是什么」「帮我找红色的球」「跟着那个瓶子」这类指令

#### 13.1.2 方案选型（树莓派 4B 友好度排序）

| 方案 | 模型大小 | CPU 占用 | 识别类别 | 推荐场景 |
|------|----------|----------|----------|----------|
| **HSV 色块追踪** | 0 | <5% | 单色块（红/绿/蓝球） | 教学目标、找球 |
| **MobileNet-SSD (COCO)** | ~20MB | 30-40% | 80 类日常物体 | 通用识别主力方案 |
| **YOLOv8n (ONNX)** | ~12MB | 40-50% | 80 类 | 精度更高，需与 Whisper 错峰 |

**推荐策略**：色块追踪做实时跟踪（连续），MobileNet-SSD 做单帧识别（按需触发「这是什么」）。

#### 13.1.3 代码改动点

1. **`drivers/camera.py`** 新增：
   ```python
   def detect_objects(self, method="mobilenet") -> list:
       """返回 [(label, cx, cy, w, h, score), ...]"""
   def track_color(self, hsv_lower, hsv_upper) -> tuple:
       """返回最大色块的 (cx, cy, area)，用于实时追踪"""
   ```

2. **`skills/` 新增两个文件**：
   - `object_detect.py` — `ObjectDetectSkill`，响应「看到了什么」
   - `object_track.py` — `ObjectTrackSkill`，响应「跟着 XX」，后台线程持续检测 → 调整云台 + 底盘

3. **`main.py` 注册**：
   ```python
   sm.register(ObjectDetectSkill(camera))
   sm.register(ObjectTrackSkill(camera, ptz, mecanum))
   ```

4. **`MockBackend.RULES`** 增加：
   ```python
   (r"(这是什么|看到了什么)",     ("让我看看哦~", "thinking", "object_detect")),
   (r"(跟着|追踪)(.*)",          ("好嘞，我跟着它！", "happy", "object_track")),
   ```

#### 13.1.4 性能互斥策略

- 物体连续追踪时，**暂停 ASR 录音**（否则 CPU 抢占导致识别卡死）
- 单帧识别（拍照+识别）不受影响，可与 ASR 并行
- 在 [性能预算表](#十一性能预算-树莓派-4b-2gb) 追加一行：

| 模块 | 内存 | CPU | 备注 |
|------|------|-----|------|
| MobileNet-SSD | ~150MB | 35% (检测时) | 与 Whisper 互斥，需错峰 |

### 13.2 主动情绪触发（补「活」感）

#### 13.2.1 现状与缺口

- 当前 `MoodEngine.trigger` 只被 LLM 调用，不说话时情绪是「死」的
- MicroDuck 的关键体验：摸头会开心、撞到东西会委屈、被拿起会惊讶

#### 13.2.2 硬件 BOM 新增（低成本方案）

| 传感器 | 接口 | 成本 | 触发情绪 | 备注 |
|--------|------|------|----------|------|
| 轻触开关 ×2（头顶 + 背部） | GPIO | ¥2 | love / happy | 摸头、拍背 |
| 碰撞开关 ×2（前后保险杠） | GPIO | ¥3 | scared / confused | 撞墙、撞人 |
| MPU6050 IMU | I2C | ¥8 | surprised / scared | 被拿起、被推倒 |
| HC-SR04 超声波（前向） | GPIO ×2 | ¥5 | surprised | 前方突然出现障碍物 |

> **可选**：全部传感器加起来 < ¥20，都走 GPIO/I2C，不占 USB。

#### 13.2.3 代码改动点

1. **`drivers/` 新增 `sensors.py`**：
   ```python
   class SensorDriver:
       def __init__(self, mood_engine):
           # 注册 GPIO 中断 / I2C 轮询
       def on_head_touch(self):
           mood_engine.trigger("touch", "love", intensity=0.8)
       def on_collision(self, direction):
           mood_engine.trigger("collision", "scared", intensity=1.0)
       def on_pick_up(self):
           mood_engine.trigger("pickup", "surprised", intensity=0.7)
   ```

2. **`main.py` 初始化**：
   ```python

   sensors.start()
   ```

3. **降级策略**：传感器未接时 `SensorDriver` 自动禁用，不影响现有功能。

### 13.3 表达性动作基元（补「身体语言」）

#### 13.3.1 现状与缺口

- 当前动作只有麦轮移动 + 云台转头，全是「功能性」的
- MicroDuck 的招牌是待机小动作、情绪表达动作（高兴蹦跳、委屈低头）

#### 13.3.2 动作基元设计

| 动作名 | 组合 | 时长 | 情绪场景 |
|--------|------|------|----------|
| `nod` | 云台上下 5°×3 + 底盘前进 5cm 回退 | 2s | 同意、开心 |
| `shake_head` | 云台左右 10°×3 | 1.5s | 拒绝、困惑 |
| `dance` | 底盘左右交替 slide 10cm×4 + 云台摇摆 | 4s | 大笑、兴奋 |
| `wiggle` | 底盘原地小幅抖动（左右 2cm×8） | 1s | 撒娇、期待 |
| `lower_head` | 云台下压 15° + 底盘缓慢后退 3cm | 2s | 难过、委屈 |
| `lean_forward` | 底盘缓慢前进 8cm + 云台上抬 | 2s | 好奇、凑近看 |
| `spin_joy` | 底盘原地转 360° + 云台抬头 | 3s | 极度开心 |

1. **`skills/` 新增 `express.py`**：
