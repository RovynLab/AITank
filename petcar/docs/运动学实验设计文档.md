## 一、目标与范围

### 1.1 要解决什么问题

petcar 现在能"动"，但动的方式是**开环的**：给一个方向、给一个占空比、跑 N 秒、停。
跑得准不准，靠人眼看、靠运气。项目里唯一真正闭环的东西是云台 PID 追踪
（[pid_tracker.py](../core/pid_tracker.py)），它闭的是**云台角度**，不是**车体位姿**。

本设计要补的，是底盘这一层：**用摄像头当唯一的位置/姿态传感器，把开环底盘变成可用、
可测、可重复的闭环运动平台**，并在此基础上做一批"好玩"的运动学实验。

一句话概括：

> 底盘负责"执行"，视觉负责"看见自己执行得对不对"，控制器负责"下一次改多少"。

### 1.2 设计目标

| 目标 | 说明 | 可验收形式 |
|---|---|---|
| 可控 | 底盘支持连续速度 `(vx, vy, ω)`，不再只有 9 个离散方向 | 能以任意小速度斜向平移、边走边转 |
| 可测 | 视觉能量化"走了多远、偏了多少、转了多少度" | 面板实时显示误差、轨迹、收敛曲线 |
| 可重复 | 同一实验跑 10 次，结果差异可解释 | 定点停车成功率、闭合误差统计 |
| 好玩 | 每个实验都能"看见效果"，而不是看日志 | 循线、追球、画 8 字、回家、竞速挑战 |
| 可教学 | 算法能抽成 labs 最小例程 | 3 个自包含 lab 文件 |
| 安全 | 失控时能停、丢目标能停、超时能停 | 急停 + 丢失保护 + 租约看门狗 |

### 1.3 明确不做的事

- **不追求 SLAM 级定位精度**。没有编码器、没有 IMU，视觉里程计在长距离上必然漂移，
  本设计接受"短距离、有地标校正"的精度，不承诺建图。
- **不改动现有教学梯度**。`labs/lab06`（Class 版）与 `labs/lab07`（全局函数版）保持原样，
  新实验另起编号，不合并。
- **不替换现有云台 PID**。云台闭环继续用现有实现，本设计只**复用**它（见 E3"云台罗盘"）。
- **不为教学在产品代码里加分支**。产品代码保持工程完整，教学版本单独抽到 labs。

### 2.2 缺什么

1. **连续速度接口**。`MecanumDriver` 只有 `forward()` / `leftSlide()` 这类开关量，
   速度只有 `set_speed()` 一个全局值。闭环控制需要每 50~100ms 改一次
   `(vx, vy, ω)`，现有接口表达不了。
2. **运动学模块**。逆解公式停在 lab08，没有归一化、没有死区补偿、没有单轮增益补偿，
   产物是一个"打印出来看看"的函数。
3. **视觉伺服框架**。`PIDTracker` 与云台强耦合，检测逻辑、控制逻辑、驱动逻辑写死在一起，
   底盘闭环无法复用。
4. **标定数据**。占空比 → 实际速度、像素 → 角度、目标宽度 → 距离，一个都没有实测过。
5. **实验承载界面**。面板是"控制台"形态（按一下动一下），没有承载"跑一个实验、
   看一条误差曲线"的地方。

### 2.3 一个必须先解决的前置隐患

[drivers/mecanum.py](../drivers/mecanum.py) 的离散方向表里存在运动学上不可能同时成立的两组指令：

```python
"leftSlide":  ("B", "F", "F", "B"),   # 左移
"rightSlide": ("F", "B", "B", "F"),   # 右移
"turnLeft":   ("F", "B", "B", "F"),   # 左转
"turnRight":  ("B", "F", "F", "B"),   # 右转
"spin":       ("B", "F", "F", "B"),   # 顺时针旋转
```

`leftSlide` 与 `turnRight`、`spin` 的电机组合完全相同；`rightSlide` 与 `turnLeft`
完全相同。麦轮底盘上"横移"和"自转"是两条独立的自由度，电机组合不可能一样。

对照 [lab08_kinematic.py](../../labs/lab08_kinematic.py) 的逆解输出：

```
Kin_Inverse(0, 1, 0) → (-1, +1, -1, +1)   # 横移
Kin_Inverse(0, 0, 1) → (+1, -1, -1, +1)   # 自转
```

两者也不一样。说明**方向表里有一半的符号是错的，或者接线与表格假设不一致**。

因此本设计把"符号与接线校验"列为 Phase 0 的第一件事（见 6.1），
**在符号未确认之前，任何闭环实验都不许上车跑**——否则控制器会与底盘"对着干"，
表现为越调越偏，最后撞墙。

## 三、核心思路：三层闭环

### 3.1 三层结构

```
┌──────────────────────────────────────────────────────────────────────┐
│  第三层  任务环 (10 Hz)                                               │
│  状态机: SEARCH → APPROACH → ALIGN → HOLD → DONE                     │
│  回答"现在该干什么"                                                    │
├──────────────────────────────────────────────────────────────────────┤
│  第二层  位姿环 (10~20 Hz)                                            │
│  视觉误差 → (vx, vy, ω)                                               │
│  回答"该往哪个方向、多快修正"                                          │
├──────────────────────────────────────────────────────────────────────┤
│  第一层  执行层 (20~50 Hz)                                            │
│  (vx, vy, ω) → 麦轮逆解 → 四轮占空比（含死区补偿/单轮补偿）            │
│  回答"四个轮子各给多少电"                                              │
└──────────────────────────────────────────────────────────────────────┘
```

三层的分工必须严格：**上位层只输出物理量（米、米/秒、弧度/秒），下位层只管怎么变成电**。
现有代码把"方向"和"电"混在一起（`forward()` 直接 `setSpeed(150)`），所以没法闭环。

### 3.2 为什么底盘不用 PID 积分

云台用的是"绝对角度伺服"（只用 Kp，每帧直接对准），这个思路可以沿用到横移/居中，
但底盘有两个云台没有的坑：

| 问题 | 表现 | 本设计的对策 |
|---|---|---|
| 静摩擦死区 | 占空比低于约 30/255 电机不转，积分会把误差攒成"暴冲" | 输出前做死区补偿（最小启动占空比），控制器不积分 |
| 打滑 / 横移效率低 | 麦轮横移实际速度只有理论的 60~80%，且随地面变化 | 横移通道单独限速，增益比前后通道小 |
| 帧延迟 | 摄像头 + 检测 + 传输约 100~200ms | 增益保守、限幅、必要时做 2 帧线性外推 |
| 电池电压下降 | 同一占空比速度变慢，开环轨迹越来越小 | **这正是闭环的价值**，作为教学案例（E5） |

结论：**位姿环用 P + 少量 D，不引入 I**。需要消除稳态误差时，用"视觉重新观测"而不是"积分累积"。

### 3.3 闭环到底闭了什么

很多同学会把"闭环"理解成"加个 PID"。本设计用三个具体实验把"闭的是什么"讲清楚：

| 闭环 | 被控量 | 反馈来源 | 对应实验 |
|---|---|---|---|
| 速度环 | 轮速 / 车体线速度 | 视觉测位移变化率 | E0 视觉测速仪 |
| 位姿环 | 横向偏差 / 距离 / 航向 | 画面中的目标框位置与宽度 | E1 / E2 / E4 |
| 任务环 | 任务状态 | 检测结果 + 超时 | E8 回家 |

## 四、关键量化模型

### 4.1 麦轮逆运动学（归一化版）

沿用 lab08 的 X 型布置公式，但改成**归一化 + 可标定**版本：

```
d1 = vy - vx + ω · k
d2 = vy + vx - ω · k
d3 = vy - vx - ω · k
d4 = vy + vx + ω · k
```

- `vx ∈ [-1, 1]`：前后（+ 前进）
- `vy ∈ [-1, 1]`：左右（+ 左移）
- `ω ∈ [-1, 1]`：自转（+ 逆时针，需实测确认）
- `k`：自转权重，理论值 `(a + b) / R`，由 6.2 的转向标定反推

归一化：先按四轮最大绝对值缩放，保证不超限；再逐轮乘增益补偿 `trim[i]`（±5%），
最后做死区补偿：

```python
def _deadband_comp(self, v: float) -> float:
    """把 [-1,1] 的归一化速度映射成占空比系数，抬过静摩擦死区"""
    if abs(v) < 1e-3:
        return 0.0
    duty = self.MIN_DUTY + (1.0 - self.MIN_DUTY) * abs(v)   # MIN_DUTY 由标定得到
    return math.copysign(duty, v)
```

> 注意：`trim[i]` 与符号在 Phase 0 标定，**不允许拍脑袋写死在代码里**。
> 四个轮子的符号用实测表格生成，不靠推理。

### 4.2 单目测距（小孔模型）

```
距离 Z ≈ (f_px · W_real) / w_px  =  K / w_px
```

- `W_real`：目标真实宽度（网球直径 6.7cm，色块边长 8cm）
- `w_px`：目标在画面里的像素宽度
- `K`：标定常数，用"放在 0.5m / 1.0m / 1.5m 处各测一次"拟合

按 `HFOV ≈ 64°`、`640px` 估算 `f_px ≈ 512`，网球 `K ≈ 34.3`（单位 m·px）：

| 距离 | 网球像素宽度 | 色块(8cm)像素宽度 |
|---|---|---|
| 0.5 m | ≈ 69 px | ≈ 82 px |
| 1.0 m | ≈ 34 px | ≈ 41 px |
| 2.0 m | ≈ 17 px | ≈ 20 px |

**精度边界**：`Z ∝ 1/w`，距离越远、目标越小，误差放大越快。所以 0.4~1.5m 是可用的
工作区，超过 2m 只能做"看见/没看见"的二值判断，不做测距。

### 4.3 像素 → 角度

沿用 [pid_tracker.py](../core/pid_tracker.py) 的实测值：

```
水平: 10 px/°（640px ≈ 64° FOV）
垂直: 约 10 px/°（480px ≈ 48°，可用范围略小）
```

摄像头装在云台上，所以**云台角度变化会直接改变像素基准**。设计约束：
**底盘闭环实验运行期间锁定云台**（`h_cur = v_cur = 90`），图像坐标系 ≈ 车体坐标系。
唯一例外是 E3"云台罗盘"，它反过来把云台角度当反馈量用。

### 4.4 时间预算

| 环节 | 耗时 | 备注 |
|---|---|---|
| 摄像头取帧 | ~30ms | 640×480，后台线程常驻 |
| 颜色/网球检测 | ~15ms | HSV，可 20Hz |
| 人脸检测 (YuNet) | ~40ms | 可 10Hz |
| TFLite SSD | ~150ms | 只能 5Hz，仅用于避障类实验 |
| 串口/PCA9685 写 | ~5ms | 阻塞极短 |
| **合计（颜色类）** | **~50ms** | 控制周期 80~100ms 可达 |

因此：**以颜色/网球为主的实验走 15~20Hz；涉及通用物体的实验降到 5Hz，且必须大死区、低增益。**

## 五、基建改造

### 5.1 `drivers/mecanum.py`：新增连续速度接口

只加一个方法，不动现有 9 个方向函数（积木引擎和技能系统还在用）：

```python
# petcar/drivers/mecanum.py（新增，不替换现有接口）
def drive(self, vx: float = 0.0, vy: float = 0.0, w: float = 0.0,
          speed: int | None = None):
    """连续速度控制。vx 前+ / vy 左+ / w 逆时针+，范围 [-1, 1]。"""
    speed = self.normal_speed if speed is None else max(0, min(255, int(speed)))
    d = self.kinematics.inverse(vx, vy, w)        # 四轮归一化量，含 trim
    with self._lock:
        for i, val in enumerate(d):
            val = self._deadband_comp(val)
            motor = self._motors[i]
            motor.run(self._dir_map["F" if val >= 0 else "B"])
            motor.setSpeed(int(abs(val) * speed))
    self._current_name = "drive"
```

要点：

- `speed` 作为"上限"传入，归一化量再乘它；这样一次实验内可以动态降速。
- 保留 `_apply()` 与 9 个方向函数，**不改调用方**，避免动到积木引擎。
- `shutdown()/stop()` 语义不变。

### 5.2 新文件 `core/kinematics.py`：运动学与标定

```python
@dataclass
class Calib:
    v_per_duty: float = 0.0        # (m/s) / duty，speed=150 时实测
    w_per_duty: float = 0.0        # (rad/s) / duty
    k_rot: float = 0.0             # 自转权重 (a+b)/R
    min_duty: float = 0.12         # 静摩擦死区（归一化占空比）
    trim: tuple = (1.0, 1.0, 1.0, 1.0)   # 四轮增益补偿
    sign: tuple = (1, 1, 1, 1)           # 四轮方向符号（实测）
    k_distance: float = 34.3       # 目标宽度→距离常数 (m·px)
    px_per_deg: float = 10.0

    @classmethod
    def load(cls, path) -> "Calib": ...

class MecanumKinematics:
    def inverse(self, vx, vy, w) -> tuple[float, float, float, float]:
        """(vx, vy, w) → 四轮归一化量 [-1, 1]"""
    def forward(self, d) -> tuple[float, float, float]:
        """四轮归一化量 → (vx, vy, w)，用于指令积分成轨迹"""
    def rpm_to_speed(self, rpm) -> float:
        """轮速 → 车体线速度，用于标定换算"""
```

标定结果落盘到 `petcar/config/kinematics_calib.json`，随仓库一起提交。
未标定时所有值为 0，`KinematicsService` 拒绝启动并提示"请先跑 E0 标定"——
**不提供"差不多"的默认值**，避免学生拿到一个跑不准的车还以为是算法问题。

## 六、标定流程

标定不是"额外工作"，它是**第一个实验**。学生跑标定的过程，就是理解开环误差的过程。

### 6.1 E0-a 方向与接线校验（Phase 0，必做）

**目的**：确认 `sign`、`trim`、`ω` 符号，消除 2.3 的方向表隐患。

流程：

1. 用 `drive(vx=+0.4)` 单轴输出，目测车是否前进；不是则翻转 `vx` 通道符号。
2. 用 `drive(vy=+0.4)` 单轴输出，确认是左移还是右移，记录符号。
3. 用 `drive(w=+0.4)`，确认是逆时针还是顺时针。
4. 若某个动作导致车"卡死抖动"（四个轮子互相抵消），说明 `sign` 组合错误，
   逐轮单独测试（`drive` 只给单个轮子非零），重建符号表。
5. 结果写入 `sign` 与 `trim`，并在面板留存一张"实测四轮方向表"截图。

**验收**：三个基础动作方向全部正确，且横移与自转的电机组合不同。

### 6.2 E0-b 直线速度标定

- 场地：2m 直道，地面贴起止标线。
- 方法：`speed=150`，`drive(vx=0.5)` 跑 1.0s，用视觉测标线位移，重复 5 次取中位数。
- 产出：`v_per_duty`（m/s per duty）。
- 建议同时测 `speed=100 / 150 / 200` 三档，拟合"占空比 → 速度"曲线；
  若线性度差（> 15%），在 `Calib` 里存成分段表。

### 6.3 E0-c 转向标定

- 场地：地面贴一条直线，车头对准。
- 方法：`drive(w=0.5)` 跑 1.0s，视觉/人眼测转过的角度（或用手机水平仪），取中位数。
- 产出：`w_per_duty`，并由公式 `k = ω_theory 反解` 得到 `k_rot`。

### 6.4 E0-d 距离标定

- 目标：网球（直径 6.7cm）或 8cm 色块。
- 方法：目标放在 0.5 / 1.0 / 1.5 / 2.0m，读 `w_px`，拟合 `K = Z · w_px`。
- 产出：`k_distance`，并把 4 个点的残差写进实验报告；残差 > 20% 说明
  目标尺寸估计错了或镜头畸变明显。

### 6.5 标定的有效期

电池电压、地面材质、轮胎磨损都会让标定漂移。设计上：

- 面板显示上次标定时间；超过 7 天提示重标。
- 每次实验结束记录"闭环稳态误差"，若连续 3 次超阈值，提示重标。
- **不做自动在线辨识**（过于复杂，超出教学范围），保持"人标、车跑"的朴素流程。

### 7.2 E0 视觉测速仪（L0，也是标定入口）

**玩法**：把车放在两条标线之间，点"测速"，车按指定占空比跑 1 秒，视觉测出位移，
自动算出 `v_per_duty` 并写进标定文件。连测 5 次给出均值与离散度。

- 参数：`speed=150`、`duty=0.5`、`duration=1.0s`、`repeat=5`
- 控制律：无（纯开环），只有测量
- 教学点：开环速度的重复性有多差（离散度常达 10~20%）
- 失败模式：地面打滑、起止标线被车轮压住、摄像头俯仰角变化

### 7.3 E1 循线小火车（L1）

**场地**：3~5cm 黄色美纹纸贴成 S 形或圆圈，深色地面。

- ROI：画面下方 `y ∈ [0.55H, 0.95H]`，只在这个区域找色带质心
- 横向误差：`ex = (cx - W/2) / (W/2) ∈ [-1, 1]`
- 控制律：

```
vy = -Kp · ex                       # 横移纠偏（符号由 Phase 0 确定）
vx = V0 · (1 - 0.4 · |ex|)          # 越偏越慢，弯道自动降速
ω  = 0                              # 关键：不转向，只横移
```

- 参数：`V0=0.35`、`Kp=0.9`、`Kd=0.15`、`deadzone=0.03`、`ROI=0.55~0.95`
- 为什么不用转向：摄像头随云台固定在车头，转向会让 ROI 里的线整体旋转，误差符号
  与图像一起转，控制器容易自激。横移保持图像基准稳定，而且**这是麦轮独有的自由度**，
  四轮差速车做不出来。
- 教学点：纯 P 会蛇形 → 加 D 抑制；死区太小会抖；横移打滑导致 `Kp` 不能大
- 指标：横向误差 RMS、单圈时间、脱线次数

### 7.4 E2 跟着我走（L1）

**目标**：人脸 / 网球 / 颜色块（复用 P1 的 HSV 配置）。

- 距离：`Z = k_distance / w_px`，误差 `ez = Z - Z_target`
- 横向：`ex` 同上
- 控制律：

```
vx = clamp(Kp_z · ez, -0.3, v_max(Z))     # 远了前进，近了后退
vy = -Kp_x · ex                           # 横向跟随
v_max(Z) = 0.15 + 0.5 · min(1, Z)         # 越近越慢
```

- 参数：`Z_target=0.8m`、`Kp_z=0.9`、`Kp_x=1.2`、`deadzone=0.05`
- 教学点：单目测距误差随距离放大；目标转身时 `w_px` 突变 → 需要 EMA 平滑；
  丢目标必须停车而不是继续走
- 指标：稳态距离误差、丢失次数

### 7.5 E3 云台罗盘（L1，最有巧思的一个）

**思路**：云台已经能靠现有 PID 把目标锁在画面中心。那么**云台的水平角**
`ptz.h_cur` 就等价于"目标相对车头的方位角"。底盘只需要转，让云台回到 90°：

```
err = (90 - ptz.h_cur) / 90        # 归一化方位误差
ω   = clamp(Kp · err, -0.4, 0.4)
```

- 参数：`Kp=0.5`、`deadzone=3°`
- 优点：底盘闭环**不需要再跑一次检测**，只读一个浮点数，CPU 开销几乎为零；
  云台 20Hz 快环 + 底盘 5Hz 慢环，是典型的**串级控制**
- 教学点：传感器复用、快慢环分工、串级系统里"内环必须先稳"
- 约束：实验期间只读云台角度，不写云台；`PIDTracker` 正在运行
- 失败模式：云台打角（0/180°）时目标在正后方，底盘会原地追着转圈；
  需要加"云台接近限位则视为丢失"的保护

### 7.6 E4 定点停车（L1）

三阶段状态机：

```
APPROACH : Z > 0.45m，定速 vx=0.25 接近，同时 vy 居中
FINE     : 0.25 < Z < 0.45m，按 Kp·ez 减速接近
HOLD     : |Z - Zt| < 0.04m 且 |ex| < 0.05 持续 1.0s → 停车，DONE
RETRY    : 进入 FINE 后仍持续接近或超调 → 后退 0.2m 重来（最多 2 次）
```

- 参数：`Zt=0.30m`、`vx_fast=0.25`、`Kp_z=1.2`、`hold_time=1.0s`
- 教学点：状态机、滞回（进入/退出阈值不同）、超调与重试
- 指标：停车距离误差、成功率（10 次）
- 好玩：把一个小球放在地上，车每次都停在球前 30cm，误差 3cm 以内

### 7.7 E5 画正方形（L2）

同一套动作跑两遍，直接对比：

**模式 A 纯开环**

```
repeat 4:
    drive(vx=0.4) for T_forward
    drive(w=+0.4) for T_turn        # 目标 90°
```

**模式 B 视觉纠偏**

```
每段结束后：
    视觉测出"位于地面角点的实际位置"
    → 修正下一段的时长 T_forward 与转角 T_turn
    → 累计误差不再增长，被限制在一段之内
```

- 参数：`T_forward=0.8s`、`T_turn=0.6s`、`rounds=3`
- 教学点：**误差累积**。开环跑 3 圈后闭合误差常常 > 30cm；闭环能稳定在 5cm 内
- 指标：闭合误差（终点回到起点的距离）、随圈数的误差增长曲线
- 加分玩法：中途换一块不同摩擦的地面，开环立刻"变形"，闭环基本不变

### 7.8 E6 画圆（L2）

**模式 A（开环参数）**：`vx = v`、`ω = v / R`，跑 `T = 2πR / v`。

**模式 B（视觉循线）**：地面贴一个圆环胶带，直接用 E1 的控制器沿环走。

- 参数：`R=0.4m`、`v=0.25m/s` → `ω≈0.625 rad/s`、`T≈10s`
- 教学点：曲率 `κ = ω / v`；开环时"半径由占空比决定"，闭环时"半径由地面决定"
- 指标：轨迹与理想圆的平均径向偏差
- 演示：两条轨迹画在同一张俯视图上，开环是"螺旋"，闭环是"圆"

### 7.9 E7 画 8 字（L2，本设计的"旗舰实验"）

**路径**：Gerono 双纽线，参数方程

```
x(t) = A · sin(t)
y(t) = A · sin(t) · cos(t)
```

对时间求导得到 `(vx_path, vy_path)`，航向对齐切线得到 `ω = dθ/dt`，
于是每帧都能算出 `(vx, vy, ω)`——**这正是麦轮"全向运动"才能完成的路径**。

- 参数：`A=0.5m`、周期 `T=16s`、`v_max=0.35`
- **地标校正**：在 8 字的两个"腰部"各贴一个色块。车每次经过时，视觉测出
  相对色块的位置，用它去修正"航迹推算"累积的漂移。
- 教学点：航迹推算（Dead Reckoning）+ 地标校正（Landmark Correction）=
  SLAM 的最小雏形。没有地标时轨迹会漂成"歪 8 字"，有地标时能持续闭合。
- 指标：轨迹与理论曲线的平均偏差；有无地标校正的对比
- 风险：麦轮横移打滑会让 8 字"下半部分"明显变形，这本身就是一个很好的讨论点

### 7.10 E8 回家（L3）

```
SEARCH   : 原地缓慢旋转（ω=0.25），扫视门牌色块
FOUND    : 锁定目标，计算方位
APPROACH : 按 E2/E3 的方式接近
ALIGN    : 横移/微调，使目标框落入预设"停车框"
DONE     : 停车 + OLED 显示 love + 播报"我回来啦"
```

- 参数：`search_timeout=30s`、`Z_stop=0.35m`
- 教学点：状态机、超时、失败恢复（搜索失败回 `SEARCH` 并换方向）
- 指标：平均寻回时间、成功率

### 7.11 E9 追球推球（L3）

云台追球、底盘堵位：

| 层 | 频率 | 目标 |
|---|---|---|
| 云台（快环） | 15Hz | 球保持在画面中心（复用 PIDTracker） |
| 底盘（慢环） | 5Hz | 用云台角度（E3）对准球，`vx` 接近 |
| 推球 | 触发式 | 球进入画面下方中央区域 → 短促加速 0.4s |

- 教学点：分层控制、快慢环、触发式动作
- 好玩：把球推进 1m 外的"球门"（两个色块之间）

### 7.12 E10 避障巡逻（L3）

- 固定路线：前进 → 横移 → 前进（用 E5 的开环段 + E1 的循线）
- TFLite 每 200ms 检测一次 `person / chair / bottle`，框面积超过阈值 → 判定障碍
- 策略：横移 0.6m 绕开，再横移回来
- 教学点：感知-决策-执行闭环、低频感知如何配合高频控制
- 风险：TFLite 150ms/帧，只能"看见静态障碍"，不要指望躲开跑动的人

### 7.13 E11 循线竞速（L3）

E1 的竞技版：400ms 内不撞墙跑完一圈，计时 + 误差 RMS 排行榜，
允许现场调 `Kp / Kd / V0`。这是最省事的课堂活动。

### 7.14 E12 手势指挥（L3）

手势识别（MediaPipe 优先，OpenCV 凸包回退）→ 映射成运动指令：

| 手势 | 指令 |
|---|---|
| 手掌张开（掌心） | 停 |
| 食指指向左 | 左移 |
| 食指指向右 | 右移 |
| 握拳 | 前进（短促 0.5s） |

- 教学点：人机闭环里的延迟（检测 ~80ms + 人手反应），以及"指令去抖"
  （连续 3 帧同一手势才生效）

### 7.15 评分指标（所有实验通用）

| 指标 | 定义 | 用途 |
|---|---|---|
| 收敛时间 `t_s` | 误差首次进入 ±5% 带并保持 0.5s | 比"快不快" |
| 稳态误差 `e_ss` | 最后 2s 的平均绝对误差 | 比"准不准" |
| 超调 `M_p` | 最大反向误差 / 目标阶跃 | 比"稳不稳" |
| 抖动 RMS | 帧间控制量差值的 RMS | 比"顺不顺" |
| 成功率 | 10 次任务成功次数 | 比"靠不靠谱" |

面板把前三个画成曲线，后两个做成数字。**不要只报"跑通了"，要让学生看到曲线形状。**

## 八、状态机与异常处理

### 8.1 顶层状态

```
        ┌────────┐  start   ┌─────────┐  目标可见   ┌──────────┐
        │  IDLE  │ ───────▶ │ ARMED   │ ─────────▶ │ RUNNING  │
        └────────┘          └─────────┘            └──────────┘
            ▲                     │                     │
            │                     │ 标定缺失/设备异常     │ 丢目标>1s
            │                     ▼                     ▼
            │                ┌────────┐            ┌────────┐
            └────────────────│ ERROR  │◀───────────│  LOST  │
                             └────────┘   恢复失败   └────────┘
                                  ▲                     │ 目标重见
                                  │ 超时/急停            ▼
                             ┌─────────┐           （回 RUNNING）
                             │ STOPPED │
                             └─────────┘
```

### 8.2 异常处理矩阵

| 异常 | 检测方式 | 处理 |
|---|---|---|
| 摄像头掉线 | `camera.is_open == False` 或连续 10 帧取不到 | 立即停车，`ERROR` |
| 目标丢失 | `observe()` 返回 None | 0.4s 内保持上一次指令；之后停车；1s 进 `LOST` |
| 检测框跳变 | 相邻帧中心位移 > 30% 画面宽 | 丢弃该帧（误检） |
| 电机不转（堵转） | 指令非零但视觉位移 0 持续 2s | 停车并提示"检查地面/接线" |
| 标定缺失 | `Calib.min_duty == 0` | 拒绝启动，提示跑 E0 |
| 与积木冲突 | `_blocks_busy()` | 409 |
| 面板关闭页面 | 前端 3s 无轮询 | 服务端 10s 后自动停车（防"人走了车还在跑"） |

### 8.3 急停链路

```
前端急停按钮 → POST /api/estop（复用现有）
    ├─ block_service.stop(estop=True)
    ├─ _cancel_action()
    ├─ kin_service.stop()        ← 新增：先停实验线程，防止它再发指令
    ├─ mecanum.stop()
    └─ camera.stop_face_tracking()
```

**顺序很重要**：必须先停实验线程再停电机，否则线程下一帧又把电机打开。

## 十一、风险与开放问题

### 11.1 已知风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 方向表符号错误（2.3） | 闭环反向，越调越偏 | Phase 0 强制标定，未标定拒绝启动 |
| 麦轮横移效率 60~80% 且打滑 | 横移闭环精度差、易振荡 | 横移通道限速 0.45、增益小于前后通道 |
| 摄像头装在云台上 | 云台一动，图像基准就变 | 底盘实验期间锁云台；E3 反过来利用这一点 |
| USB 摄像头自动曝光/白平衡 | HSV 阈值漂移，循线忽断忽连 | 建议 `v4l2-ctl` 固定曝光；或按画面亮度自适应 |
| 画面延迟 100~200ms | 高增益必振荡 | 低增益 + 限幅 + 近目标降速 |
| 无编码器 | 长距离必然漂移 | 只用短距离 + 地标校正，不承诺建图 |
| Pi 4B 2G 资源紧张 | 检测掉帧、控制周期抖动 | 控制用 320×240 降采样；TFLite 类实验降到 5Hz |
| 地面反光/深色 | 色带检测失败 | 指定高饱和胶带；面板提供 HSV 预设 |

### 11.2 待确认问题

1. **是否给底盘加编码器**？加 4 路霍尔编码器（约 60 元）能做真正的轮速闭环，
   精度提升一个量级，但会改变现有"纯开环教学"的立意。建议保持现状，
   把编码器作为"进阶硬件选项"写进文档。
2. **是否加 IMU**？MPU6050（约 10 元）能直接测航向，E5/E6/E7 的精度会显著提升。
   建议作为 v2 选项，不影响本设计落地。
3. **入口形态**：独立页面 `/kinematics` 还是面板卡片？本设计倾向前者（见 5.6）。
4. **PIDTracker 是否改造**？目前它只管云台。E3/E9 需要"云台 + 底盘"双输出，
   建议**不改** PIDTracker，由实验层组合两个控制器，保持现有代码稳定。
5. **实验是否需要"一键演示"**？建议 Phase 4 加一个 30 秒演示脚本：
   循线一圈 → 追球 → 画 8 字，用于课堂暖场。

## 十二、开环专属玩法（E13~E20）

这一章的场景全部满足三个硬约束，可以在**现有硬件上直接开跑**：

- 不装编码器、不装 IMU，底盘保持开环；
- 不训练任何模型，只用现有 HSV / 网球 / 人脸检测；
- 不新增基建，全部走第五章的 `ServoLoop` + `KinematicsService` + `mecanum.drive()`。

通用约束（本章所有实验默认遵守）：

| 约束 | 值 | 原因 |
|---|---|---|
| 云台锁定 | `h=90, v=90`（E14 除外） | 云台一动图像基准就变 |
| 速度上限 | 0.40（归一化） | 这些场景多在桌边、人附近 |
| 丢目标 | 0.4s 保持，1.0s 停车 | 不允许"盲走" |
| 控制频率 | 15Hz | 颜色/网球检测可支撑 |
| 完成判定 | 位置/距离，不用角度积分 | 开环没有角度传感器 |

### 12.1 E13 卫星绕行（绕可乐瓶 360°）

**目标**：车头始终朝向瓶子，沿半径 R 横移绕一圈，回到起点。

**场地**：瓶子放地面中央，半径 0.5m 处贴一圈淡色参考线（可选）。

**控制律**（极坐标解耦）：

```
ez = R - Z                              # 距离误差（单目测距）
ex = 目标横向归一化偏差
vx = clamp(0.8 * ez, -0.15, 0.15)       # 保距，宁可慢
ω  = clamp(0.25 * ex, -0.25, 0.25)      # 方位微调，车头始终朝瓶
vy = v_tangent * dir                    # 切向绕行，dir 由 Phase 0 标定
```

**360° 判定**（开环没有角度传感器，三选一）：

| 方案 | 做法 | 精度 |
|---|---|---|
| A 计时 | `T = 2πR / v_t`（v_t 用标定后的 m/s） | 闭合误差 10~20cm |
| B 地标 | 起点放一个色块，回到起点附近且方位回正即停 | 最好，推荐 |
| C 方位累加 | 累加视觉方位角变化，过 360° 停 | 中等，需防抖 |

**参数**：`R=0.5m`、`v_t=0.22m/s`、`Kp_z=0.8`、`Kp_θ=0.25`

**好玩**：像卫星绕行星。若同时开 E14，瓶子会在画面里"钉死不动"，背景在转。

**教学点**：径向/切向解耦；横移打滑导致半径缩小，距离环会自动补回来——这正是闭环的价值。

**失败模式**：瓶子检测抖动会让 `ω` 抖；R 越小需要的角速度越大，别把 R 设到 0.3m 以下。

**验收**：绕一圈回到起点偏差 < 15cm，全程不丢瓶。

### 12.2 E14 云台稳定器（车转，画面不转）

**目标**：底盘原地旋转，云台按相同角速度反向补偿，让画面里的目标保持不动。

**原理**（纯前馈，不做视觉闭环）：

```
底盘转角 θ_c = ω · t
云台角   θ_p = 90 - k · θ_c
k = 云台角变化 / 底盘转角，由标定得到（先按 0.5 试，实测修正）
```

实现：同一个控制循环里，先发 `drive(w=ω)`，再按 `dt` 调 `ptz.h_rotate(θ_p)`。

**参数**：`ω=0.3`、`k=0.5`（待标定）、`CONTROL_HZ=20`

**好玩**：像鸡头稳定器。录两段视频（补偿开 / 补偿关）对比，效果非常直观。

**教学点**：开环前馈控制；`k` 标不准不会"爆炸"，只会让画面缓慢漂移——这是前馈误差的典型表现；云台打到限位必须停底盘。

**失败模式**：`k` 偏大 → 画面反向漂移；`k` 偏小 → 追不上；云台限位 0/180° 附近要先停再回中。

**验收**：底盘转满 360° 后，目标框位移 < 画面宽度的 15%。

### 12.3 E15 视觉围栏（怎么开都不出圈）

**目标**：地面贴 1.5m×1.5m 方框，车在框内执行用户指令，接近边界前被"推回"，绝不越界。

**原理**：人工势场。在 ROI 中检测四条边线，换算成"距边界的归一化距离" `d_i`：

```
F_i = k_r · max(0, 1/d_i - 1/d0) · n_i     # n_i 指向框内
(vx, vy) = clamp(ΣF_i + 用户指令, ±0.4)
```

**参数**：`d0=0.35`（进入 35cm 开始排斥）、`k_r=2.0`、框 1.5m×1.5m

**好玩**：像遛狗不出圈；也可以设"越界即失败"的挑战，让人故意把车往外开。

**教学点**：虚拟势场法、多约束合成、斥力与用户指令的优先级。

**失败模式**：摄像头俯角不够，看不到近处边线 → 云台压低到 45°；边线反光 → 换高对比胶带。

**验收**：连续随机指令 60s，0 次出界。

### 12.4 E16 绕桩 S 弯

**目标**：3 个锥桶/色块交错摆放（间距 0.6m），车 S 形绕过，不碰桩。

**原理**：期望横向偏移随时间变化 + 局部修正：

```
ex_obs = 最近桩的横向归一化位置
ex_des = A · sin(2π·s / L)          # s ≈ v·t，开环估算行进距离
vy     = clamp(-Kp · (ex_obs - ex_des), ±0.4)
vx     = V0 · (1 - 0.3·|vy|)        # 打方向时略减速
```

**参数**：`A=0.15`、`L=1.2m`、`Kp=1.2`、`V0=0.3`

**好玩**：像滑雪绕旗门，可计时排名。

**教学点**：期望轨迹生成 + 局部修正；检测延迟会表现为"切内线"，`Kp` 不能太大。

**失败模式**：桩太矮太细看不见 → 换 20cm 高锥桶或贴大色块；两桩重叠时取最近的一个。

**验收**：3 桩全过，5 次里 ≥ 4 次零碰撞。

### 12.5 E17 推球进门

**目标**：把网球推进两个色块之间的球门（宽 40cm）。

**状态机**：

```
AIM   : 球居中（ex→vy），距离 0.35~0.50m
PUSH  : 开环冲击，vx=0.5 持续 0.5s，然后立刻停
RESET : 后退 0.2m，重新找球
```

**参数**：`push_duty=0.5`、`push_ms=500`、`Z_push=0.40m`

**好玩**：台球/足球。进球判定用"球经过两色块之间的连线"，不需要复杂视觉。

**教学点**：闭环对准 + 开环冲击的组合；冲击量（推多远）需要标定，且随电量变化——可以现场演示"满电推过头"。

**失败模式**：推偏、球贴墙、球滚进阴影导致颜色丢失。

**验收**：10 次推进 ≥ 6 次进门。

### 12.6 E18 快递员巡回

**目标**：依次访问 3 个不同颜色的色块，每点停 1s 播报，循环。

**状态机**：

```
SELECT   : 取下一个目标颜色（红 → 绿 → 蓝）
SCAN     : 原地慢转（ω=0.2），扫到目标颜色即锁定
APPROACH : 方位 + 保距（复用 E2）
ARRIVE   : 距离 < 0.35m 且居中 → 停 1s → NEXT
```

**参数**：`visit_order=[红,绿,蓝]`、`Z_stop=0.35m`、`scan_ω=0.2`

**好玩**：送快递/巡逻。可以让孩子摆积木当"快递点"，顺序自己定。

**教学点**：任务调度、颜色分类、目标切换、失败重搜。

**失败模式**：红/橙混淆 → 选色相差 > 25 的三个颜色；目标在车后方永远扫不到 → 扫描必须转满 360°。

**验收**：一轮 3 点全达，连续 3 轮不出错。

### 12.7 E19 弹力绳跟随

**目标**：人拿色块在车周围慢慢走，车保持 0.8m，全程**不转头**，只用横移 + 前后。

**控制律**：

```
vx = Kp_z · ez
vy = -Kp_x · ex
ω  = 0
|ex| > 0.85（目标跑到侧后方）→ 进入 TURN 子状态，原地转到目标回到画面中部
```

**参数**：`Z_target=0.8m`、`Kp_z=0.9`、`Kp_x=1.2`、`TURN 触发=0.85`

**好玩**：像宠物侧着身子跟着你走，视觉上很怪很有趣，而且四轮差速车根本做不到。

**教学点**：全向底盘的优势——不转向就能跟随，图像基准始终稳定；代价是侧向单目测距会因视角变形而不准，所以限制在 ±60° 内。

**失败模式**：目标在正侧方时测距误差大 → 超 60° 就转向；横移打滑 → `Kp_x` 调小。

**验收**：跟随 30s，距离误差 < 25cm，丢失 ≤ 1 次。

### 12.8 E20 描红（沿任意图案走）

**目标**：地面用胶带贴任意图案（字母、心形、箭头），车沿线走完。

**与 E1 的区别**：曲率自适应。

```
ex 同 E1（ROI 内色带质心）
ėx = 横向误差变化率（帧间差分，EMA 平滑）
vx = V0 · (1 - 0.6·min(1, |ėx|/0.3))     # 弯道降速
vy = -Kp(ex) · ex                        # Kp 随 |ėx| 从 0.8 增到 2.0
丢线：原地小角度搜索 0.3s（左右各一次），仍未找到则停车
```

**参数**：`V0=0.3`、`Kp` 基线 0.8 上限 2.0、`ROI=0.55~0.95`

**好玩**：车"写字"；可以办"谁的图案最难"的比赛。

**教学点**：从固定路径（直线/S 弯）到任意路径；用误差变化率估计曲率；丢线恢复。

**失败模式**：直角弯必丢线 → 用圆弧弯或接受 2 次脱线；图案交叉处质心跳变 → 加形状连续性判断。

**验收**：一个闭合图案跑完，脱线 ≤ 2 次。

### 12.9 本章场景与已有基建的对应关系

| 场景 | 直接复用的现有能力 | 需要新增的只有 |
|---|---|---|
| E13 卫星绕行 | 颜色/网球检测、单目测距、`drive()` | 极坐标解耦 + 360° 判定 |
| E14 云台稳定器 | `PTZDriver`、`drive()` | 一个前馈标定常数 `k` |
| E15 视觉围栏 | 颜色检测（边线） | 势场合成逻辑 |
| E16 绕桩 S 弯 | 颜色检测、`drive()` | 期望偏移曲线 |
| E17 推球进门 | 网球检测、`drive()` | 三状态机 + 冲击标定 |
| E18 快递员巡回 | 颜色检测、E2 控制器、TTS | 任务调度表 |
| E19 弹力绳跟随 | 颜色/人脸检测、单目测距 | 侧向限幅 + TURN 子状态 |
| E20 描红 | E1 循线控制器 | 曲率自适应增益 |

**结论**：这 8 个玩法里，只有 E14 需要一个新的标定常数，其余全是"现有检测 + 现有逆解 + 不同控制律"的组合。
没有一个需要训练模型，也没有一个需要编码器。

### 13.2 术语

| 术语 | 含义 |
|---|---|
| 开环 | 只发指令，不检测结果 |
| 视觉伺服 | 用图像特征误差直接驱动执行器（IBVS） |
| 航迹推算 | 用速度积分估计位置，误差随时间累积 |
| 地标校正 | 用已知位置的标记重置/修正推算误差 |
| 串级控制 | 内环快、外环慢，外环输出作为内环目标 |
| 死区 | 误差小于阈值不动作，防抖 |
