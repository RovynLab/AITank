# 进程、运行状态与启动控制

> 适用对象：需要在树莓派上启动/排查 petcar 的老师和维护者。
> 相关文档：[小车使用手册](./小车使用手册.md) · [系统架构文档](./系统架构文档.md)

---

## 一、一句话结论

- **petcar 只有一个 Python 进程**，摄像头、Flask、表情、语音、积木都在这一个进程的线程里；
- **Ollama 不是 start.sh 启动的**，它是系统 systemd 服务，开机自启，模型首次对话才加载；
- **whisper 不独立成进程**，它由 petcar 启动时加载进内存；
- **piper 是 petcar 的子进程**，第一次说话时拉起，之后常驻待命，空闲 0% CPU；
- **start.sh 通过环境变量控制加载方式，但面板保存的 `data/config_local.json` 优先级更高**，会覆盖 start.sh 的设置。

---

## 二、进程全景

板子运行 `./petcar/start.sh --voice` 时的典型进程树：

```
systemd(1)
├── ollama serve                     ← 开机自启，常驻
│    └── ollama runner                ← 首次对话时创建，闲置 5 分钟后退出
├── sshd / 桌面 / 其他系统进程
└── python3 -m petcar.main            ← petcar 主进程（单进程）
     ├── [线程] Flask HTTP
     ├── [线程] 摄像头采集
     ├── [线程] 表情渲染 8 FPS
     ├── [线程] 语音监听（whisper 在该进程内推理）
     ├── [线程] 每个 MJPEG 客户端一个视频流线程
     ├── [线程] 心情衰减 / 积木看门狗 / PID 追踪 ...
     └── piper                       ← 第一次 TTS 时创建，之后常驻
```

| 进程 / 执行体 | 父进程 | 谁启动 | 何时创建 | 何时退出 | 实测资源（Pi 4B 2G） |
|---|---|---|---|---|---|
| `ollama serve` | systemd | 开机自启 | 开机 | 手动 stop | 约 125 MB，空闲 0% |
| `ollama runner` | `ollama serve` | 首次 LLM 请求 | 第一次对话 | 闲置 5 分钟（默认 keep_alive） | 0.5B 约 597 MB，生成时约 200% CPU |
| `python3 -m petcar.main` | setsid | `start.sh` | 执行 start | stop / 崩溃 | 约 341 MB，35 线程 |
| whisper | —— | petcar 进程内 | `ASRDriver` 初始化时 | petcar 退出 | 模型内存计入 petcar，识别时占 1 核数秒 |
| `piper` | petcar | 第一次 `speak()` | 启动欢迎语 | petcar 退出 | 约 130 MB，空闲 0% |
| `ffmpeg` / `aplay` | petcar | 每次播放 | 按需 | 播完即退 | 短时占用 |
| 视频流线程 | petcar | 每个浏览器连接 | 打开面板视频 | 关闭页面/断开 | 每路约 5~7% CPU |

> `ollama runner` 的 `ps` 里 `%CPU` 是**从加载至今的平均值**，不代表当前状态。要看实时值用 `top -p <pid>`。

## 三、配置优先级（最容易踩的坑）

```
data/config_local.json（面板“保存并生效”写入）
        ↑ 覆盖
PETCAR_* 环境变量（start.sh 设置）
        ↑ 覆盖
petcar/config.py 默认值
```

`main()` 的顺序是：先 `load_runtime_config()`，再 `_connect_all()` 创建 ASR/TTS/LLM。因此**只要 `data/config_local.json` 里存了某一项，start.sh 传的同名环境变量就不生效**。

当前板上保存的键：

```
whisper_model, llm_backend, tts_mode
```

例如：

- 保存了 `whisper_model=tiny`，那么 `./petcar/start.sh --voice` 里的 `base` 不会生效；
- 保存了 `tts_mode=edge`，那么 `./petcar/start.sh --offline` 里的 `piper` 不会生效。
- 保存了 `llm_backend=doubao`，那么 `./petcar/start.sh` 不会再连 Ollama。

### 让 start.sh 真正生效的三种办法

```bash
# 1) 面板「设置」里改回想要的值，保存并生效
# 2) 直接删除运行时配置，回到 config.py / 环境变量默认值
rm ~/AITank/data/config_local.json
# 3) 在面板点「恢复默认」
```

删除/修改后都需要重启进程：

```bash
cd ~/AITank && ./petcar/start.sh restart --voice
```

### 确认当前到底生效了什么

```bash
curl -s http://127.0.0.1:5000/api/status | python3 -m json.tool | grep -A 8 '"config"'
```

返回中的 `asr_mode`（固定为 `whisper`）、`llm_backend`、`llm_model`、`tts_mode` 才是真实生效值。

## 四、各模型的加载时机

### 4.1 Ollama（LLM）

| 问题 | 答案 |
|---|---|
| 谁启动 | 系统 systemd：`systemctl is-enabled ollama` → `enabled`，开机自启 |
| start.sh 管吗 | 不管启动，只设置 `PETCAR_LLM_BACKEND=ollama` 让 petcar 去连 |
| 模型何时进内存 | 第一次 `POST /api/chat` 时才加载 |
| 何时释放 | 闲置约 5 分钟自动卸载；`ollama ps` 的 `UNTIL` 列可看剩余时间 |
| Ollama 没起来会怎样 | 不再自动回退 mock：启动时不做探测，对话请求失败会直接报错；面板与本地固定指令仍可用 |
| 怎么手动卸载 | `ollama stop qwen2.5:0.5b` |
| 怎么彻底停 | `sudo systemctl stop ollama` / `sudo systemctl disable ollama` |

### 4.2 whisper（ASR，语音识别）

- **不是独立进程**，是 petcar 进程里的 CTranslate2/faster-whisper；
- 在 `ASRDriver()` 构造时**立即加载**，位置在 `main.py:64`；
- 即使只开面板（`--flask`），只要构造了 `ASRDriver` 就会加载；
- 当前 ASR 只有 whisper 一种方式，没有“跳过加载/终端文字输入”的开关；whisper 加载失败会直接报错；
- 模型大小看 `config.WHISPER_MODEL`：默认 `small`，可用 `PETCAR_WHISPER_MODEL` 或面板配置改；
- 当前板上保存的是 `tiny`，所以启动日志显示 `加载 faster-whisper tiny`。

### 4.3 piper / edge（TTS，语音合成）

| 模式 | 何时启动 | 说明 |
|---|---|---|
| `piper` | 第一次 `speak()`（启动欢迎语） | 拉起常驻子进程，模型只加载一次，之后每句话只写一行文本；空闲 0% CPU |
| `edge` | 每句话调用 edge-tts | 需要联网；结果有缓存；失败回退 piper/espeak |
| `espeak` | 每次调用 | 机械音，兜底 |
| `pyttsx3` | 每次调用 | 系统自带语音引擎 |

TTS 模式由 `TTS_MODE` 决定，当前面板保存为 `piper`，所以板上会一直看到一个 piper 进程，属正常现象。

## 五、start.sh 启动控制

### 5.1 模式矩阵

| 命令 | 设置的环境变量 | 期望效果（**无面板配置覆盖时**） |
|---|---|---|
| `./petcar/start.sh` | `LLM_BACKEND=ollama` | 完整链路：面板 + 语音，whisper 用 `config.py` 默认模型 |
| `./petcar/start.sh --voice` | `WHISPER_MODEL=base`、`HF_ENDPOINT=镜像` | 加载 whisper base，开启语音对话 |
| `./petcar/start.sh --full` | 不额外设置 | 与默认相同，用 `config.py` 的默认模型（small） |
| `./petcar/start.sh --offline` | `TTS_MODE=piper` | 语音合成走本地 Piper |
| `./petcar/start.sh --port 5001` | —— | 命令行参数，**始终生效** |

### 5.2 推荐用法

| 场景 | 命令 |
|---|---|
| 课堂演示 / 只想点面板 | `python3 -m petcar.main --flask`（start.sh 没有仅面板模式；`--flask` 仍会加载 whisper） |
| 语音对话 | `./petcar/start.sh --voice` |
| 断网环境 | `./petcar/start.sh --voice --offline` |
| 启动异常 / 看实时日志 | `./petcar/start.sh foreground` |

### 5.3 启动脚本做了什么

1. 定位仓库根目录，`cd ~/AITank`；
2. 组装环境变量（见上表）；
3. `setsid python3 -m petcar.main --port 5000`，脱离 SSH 会话；
4. 写 `petcar/logs/petcar.pid`，日志追加到 `petcar/logs/petcar.log`；
5. 最多等 90 秒 HTTP 200，然后打印面板地址。

## 六、状态查看与诊断

### 6.1 脚本自带

```bash
cd ~/AITank
./petcar/start.sh status      # PID、端口、HTTP、内存、运行时长
./petcar/start.sh logs        # 最近 80 行
./petcar/start.sh logs -f     # 实时跟踪
```

### 6.2 系统命令

```bash
# petcar 进程
pgrep -af 'petcar.main'

# Ollama 服务与模型
systemctl is-enabled ollama
systemctl is-active ollama
ollama ps                     # 已加载模型、大小、剩余驻留时间
ollama list                   # 本地已有模型

# piper 常驻进程
pgrep -af piper

# 面板连接（MJPEG 视频流会占 CPU）
ss -tnp | grep :5000

# 进程内容
ps -eo pid,ppid,pcpu,pmem,rss,etime,args --sort=-pcpu | head -n 12
```

### 6.3 面板 API

```bash
curl -s http://127.0.0.1:5000/api/status | python3 -m json.tool
```

| 字段 | 含义 |
|---|---|
| `config.asr_mode` | 实际生效的 ASR 模式（当前固定 `whisper`） |
| `config.whisper_model` | 实际加载的 whisper 模型（若返回） |
| `config.llm_backend` / `llm_model` | 实际 LLM 后端与模型 |
| `config.tts_mode` | 实际 TTS 模式 |
| `system.cpu_percent` / `mem_percent` / `temp_c` | 系统 CPU、内存、温度 |
| `voice.asr` / `voice.tts` | 语音驱动当前模式 |

### 6.4 线程级 CPU

```bash
PID=$(pgrep -f 'python3 -m petcar.main' | head -n1)
top -H -b -n 2 -d 1 -o %CPU -p $PID | grep -A 10 '^ *PID USER' | tail -n 11
```

更精确的 5 秒采样（按线程算百分比）：

```bash
python3 - <<'PY'
import os, time
pid = int(os.popen("pgrep -f 'python3 -m petcar.main' | head -n1").read())
hz = os.sysconf("SC_CLK_TCK")
def snap():
    return {t: sum(map(int, open(f"/proc/{pid}/task/{t}/stat").read().split()[13:15]))
            for t in os.listdir(f"/proc/{pid}/task")}
a = snap()
time.sleep(5)
b = snap()
for t in sorted(b, key=lambda k: b[k] - a.get(k, 0), reverse=True)[:8]:
    print(t, round((b[t] - a.get(t, b[t])) / hz / 5 * 100, 1))
PY
```

线程名在 `top -H` 里都显示 `python3`，可按“创建时间 + CPU 占比”对应：

| 线程来源 | 典型占比 | 说明 |
|---|---|---|
| 每个 MJPEG 视频流 | 5~7% | 每个浏览器标签页一路，开多个页面会叠加 |
| 摄像头采集 | 5~6% | 640×480 持续读帧 |
| 表情渲染 | 5~6% | 8 FPS 画图 + 推送 I2C（无变化时跳过） |
| 语音监听 | 约 5% | 录音 + VAD；识别时短时吃满 1 核 |
| 心情 / 看门狗 / PID | 0.2~1% | 低频任务 |

## 七、正常资源基线（Pi 4B 2G 实测）

| 项目 | 空闲 | 对话/识别时 |
|---|---|---|
| 系统内存 | 约 74%（1365/1844 MB） | 可能到 85% |
| Swap | 数十 MB | 视模型大小 |
| 温度 | 65~70°C | 70~75°C |
| petcar CPU | 30~40%（有 1 路视频） | +1 核跑 whisper |
| Ollama CPU | 0% | 约 200%（2 核）数秒 |
| piper CPU | 0% | 播报时短时上升 |

> 内存构成：Ollama runner 597 MB + petcar 341 MB + piper 130 MB。
> 若换 1.5B 模型，Ollama 部分会明显增大，2 GB 板容易触发 swap。

## 八、常见问题

**Q1：我只想开面板，为什么还是加载了 whisper？**
A：`main()` 初始化时就会构造 `ASRDriver()` 并加载 whisper；`--flask` 只是不跑语音循环，不会跳过驱动初始化。当前 ASR 只有 whisper 一种方式，没有 mock 或“跳过加载”的开关。内存紧张时把 whisper 模型降到 `tiny`。

**Q2：为什么有一个 piper 进程一直在？**
A：TTS 模式为 piper 时，启动欢迎语会拉起常驻进程，模型只加载一次。空闲 0% CPU，属正常。不想常驻就把 TTS 模式改成 `edge` 或 `espeak`。

**Q3：`ps` 里没看到 Ollama 模型进程？**
A：`ollama runner` 只在模型加载期间存在，闲置 5 分钟后自动退出；`ollama serve` 会一直在。

**Q4：Ollama 的 `%CPU` 显示 167%/208%，是不是一直在满负荷？**
A：那是从进程创建到现在的平均值。用 `top -p <pid>` 看实时值，空闲时应为 0%。

**Q5：CPU 一直在 50% 左右，谁在用？**
A：优先看视频流：每个浏览器标签页一路 MJPEG，每路 5~7%；多开页面会叠加。关闭多余页面或在面板「关闭摄像头」可立即下降。

**Q6：怎么彻底不启用语音，只留面板？**
A：用 `python3 -m petcar.main --flask` 手动启动（不会跑语音循环），但 `ASRDriver` 仍会加载 whisper、启动欢迎语也会播报。当前没有“只打印文本”的 TTS；想安静可把 TTS 模式设为 `espeak` 并把音量调低。

**Q7：Ollama 连不上会怎样？**
A：当前版本不会回退 mock，对话接口会直接报错（面板与本地固定指令仍可用）。先 `systemctl status ollama`、`ollama list` 确认服务和模型，或把面板 LLM 后端切到 `doubao` 并填好 Key。

**Q8：怎么确认 whisper 用的是哪个模型？**
A：启动日志有 `[ASR] 加载 faster-whisper <模型>`；`/api/status` 的 `config` 里也能看到；日志位置 `petcar/logs/petcar.log`。
