## 1. 背景与问题

### 1.1 现状

PetCar 当前是**单车自治**的架构：每台树莓派上跑一个 `python3 -m petcar.main`，Flask 监听 `0.0.0.0:5000`，同一个进程里同时提供：

- 中控面板 `/`：视频流、方向控制、云台、颜色识别、PID 追踪、技能、聊天、语音、配置
- 积木编程 `/blocks`：选积木、运行、停止、急停、文件保存/导入导出
- 全部管理接口：`/api/config`、`/api/logs`、`/api/camera/open`、`/api/skill/run` 等

这套设计在"一个学生 + 一台车"的课外场景很好用，但**没有任何身份、会话、权限和并发控制**。任何能访问 `http://<车IP>:5000` 的人，都拥有和老师完全相同的权限。

### 1.2 课堂真实痛点

| 现象 | 技术根因 | 课堂后果 |
| --- | --- | --- |
| 学生提前打开页面，随意开车 | 服务端无鉴权，`/api/base/move` 无条件执行 | 车撞桌角、掉下桌、撞人 |
| 多个学生同时控制同一台车 | 无控制权归属 | 指令互相打架、PID 追踪抢占底盘 |
| 学生点开"配置"改速度/模型 | `/api/config` 对所有人开放 | 整台车行为被改乱，下节课无法复现 |
| 学生运行与课程无关的积木 | 积木目录全量开放、无时长限制 | 偏离教学进度，电机长时间空转 |
| 车在讲台/充电时也被控制 | 只能靠"关机"或拔电 | 老师没法在后台准备 |
| 老师不知道哪台车在线、哪台坏了 | 无集中视图 | 逐个 IP 试，课堂前 10 分钟全在排障 |
| 下课后没人"收车" | 无统一收口 | 学生回教室后仍在操控 |

### 1.3 设计目标

必须做到的四件事（用户核心诉求）：

1. **发现**：老师打开一个页面，就能看到教室里所有在线的小车。
2. **确认状态**：每台车是否在线、是否被占用、当前在跑什么、有没有异常。
3. **锁定/放开**：上课期间默认锁死；老师按需开放，一键全锁、一键放学。
4. **只开本课内容**：按课程包只开放当日这节课需要的页面、积木、速度上限和运行时长。

同时必须满足的工程目标：

- **锁在车端**，不是前端灰按钮。学生直接 `curl` 也绕不过去。
- **默认拒绝**：新接口忘了登记就默认不可用，而不是默认全开。
- **断网/中心宕机不会让车跑飞**：失联即停车、限时进入安全锁。
- **不推翻现有架构**：保留单车 Flask、积木引擎、语音链路，只加一层管控。
- **老师零安装、学生零安装**：都是浏览器。

### 1.4 非目标（本期不做）

- 不做学生账号体系与成绩系统（用"座位/小组"临时身份即可）。
- 不做云端多校区管理（预留中心间同步接口，不实现）。
- 不做视觉 SLAM、地理围栏（后续可与摄像头/UWB 结合）。
- 不改造成"云端代理全部流量"的架构（视频流仍直连车端）。

## 2. 角色与场景

| 角色 | 使用方式 | 权限 |
| --- | --- | --- |
| 授课老师 | 教师机浏览器打开中心（默认 `http://127.0.0.1:8095` 或教师机 IP） | 发现、锁定、开课、发码、收回、审计 |
| 学生 | 平板/电脑浏览器，扫车身二维码 | 仅本课课程包内的能力 |
| 巡课/管理员 | 同一中心页面的"管理模式"（PIN 进入） | 多教室、设备改名、密钥、批量升级 |
| 车端 | 后台线程，无界面 | 只执行中心下发的策略 |

典型一节课：

```
课前 5 分钟  老师开中心 → 自动发现 N 台车 → 检查在线/温度/占用 → 一键全锁
上课         选课程包「第 3 课 红绿灯」→ 设置时长 40 分钟 → 开课 → 投屏课堂码
学生         扫车上二维码 → 输入 4 位课堂码 → 进入"只含本课积木"的界面
课中 35 分钟 系统提示"还剩 5 分钟"→ 到时自动停止程序并锁车
下课         老师点「放学」→ 全部锁车、程序停止、审计落库
```

## 3. 设计原则

1. **服务端强制（Server-side Enforcement）**
   所有限制在车端 Flask 的请求入口和驱动层执行。前端隐藏按钮只是体验优化，不构成安全边界。

2. **失败关闭（Fail-Closed）**
   未登记的路由默认拒绝；与中心失联超过宽限期，车自动进入安全锁（只允许急停和只读状态）；断电重启后默认回到锁定态，而不是"上次是开的"。

3. **锁与授权分离**
   "锁"决定**能不能动**；"课程包"决定**能做什么**。两者独立配置：可以先解锁再按课限权，也可以锁着只给学生看摄像头。

4. **控制权唯一**
   一台车同一时刻只能有一个有效控制会话（一个座位/小组）；老师拥有随时收回的最高权限。

5. **最小心跳、可离线降级**
   中心只做"授权 + 观测"，不代理视频和运动指令；车端保存最近一次策略，短时断网不影响已开始的课程。

6. **安全动作永远可用**
   急停（`/api/estop`、`/api/blocks/estop`）在任何状态、任何身份下都放行，且只允许"停"。

## 4. 总体架构

### 4.1 拓扑

```
┌──────────────────────── 教室 Wi-Fi（同一网段 /24）────────────────────────┐
│                                                                          │
│   ┌──────────────────────────┐        ┌──────────────────────────────┐   │
│   │ 教师笔记本 / 教室服务器     │        │ 机房台式机（有线）            │   │
│   │ Classroom Console :8095  │◄──────►│ 浏览器（扫码进入）            │   │
│   │  - 设备发现与车况墙       │  HTTP  │                              │   │
│   │  - 锁 / 课程包 / 令牌     │        └──────────────┬───────────────┘   │
│   │  - 审计（SQLite）         │                       │ 直接访问车端       │
│   └───────┬──────────────────┘                       │ 5000（带令牌）     │
│           │ 心跳 3s（HTTP + HMAC）                    │                    │
│           │ UDP 广播 5002（发现）                      │                    │
│   ┌───────▼──────────────────────────────────────────▼───────────────┐   │
│   │ 01 号车 树莓派  petcar.main :5000                                 │   │
│   │  ├─ ClassroomAgent 线程：心跳 / 拉策略                            │   │
│   │  ├─ ClassroomGuard：锁状态、令牌表、课程包、限速限时（线程安全）   │   │
│   │  ├─ Flask before_request：路由 → 能力校验（默认拒绝）              │   │
│   │  ├─ BlockService：积木类别白名单 + 运行时长上限                    │   │
│   │  └─ mecanum / ptz / camera / skills …（原有硬件层）                │   │
│   └───────────────────────────────────────────────────────────────────┘   │
│   … 02、03 … N 号车（同构）                                                │
└──────────────────────────────────────────────────────────────────────────┘
```

### 4.2 为什么控制信令不经过中心代理

- 视频流（MJPEG）带宽大，经中心转发会拖垮教师笔记本；
- 现有架构是浏览器直连车，改代理等于重写前端与所有 API；
- 中心只负责**发授权、收状态**，天然是"轻控制面"。

代价是学生浏览器必须能直连车 IP。教室同一 Wi-Fi 下成立；若学校网络有 AP 隔离，需按第 12 节处理（换 SSID 或走教师机热点）。

### 4.3 部署形态

| 形态 | 说明 | 适用 |
| --- | --- | --- |
| A. 教师机工具（推荐首版） | 老师电脑运行 `python -m classroom_console`，监听 `0.0.0.0:8095`，页面本机打开 | 单教室、走班 |
| B. 教室常开服务器 | 同一程序装在教室迷你主机/树莓派，教师用平板访问 | 多班共用、固定教室 |
| C. 多教室（预留） | 每教室一个实例，管理端汇总 | 后续 |

首版只交付 A，B 只是换部署位置，代码一致。

### 4.4 机房教室的网络接法（AP 模式）

适用场景：学校机房，学生用有线台式机，教室新增一台无线路由器，同一教室 10 台以内小车。

#### 4.4.1 接法

```
学校墙面网口（机房交换机，已有 DHCP）
        │
   路由器 LAN1          ← 必须 LAN 口，不能 WAN
   ├─ LAN2 ── 教室机（原网线改接这里，不断网）
   └─ Wi-Fi ── 小车 ×N、教师笔记本
```

路由器在这里只当"无线 AP + 多口交换机"：不路由、不 NAT、不发 DHCP。机房电脑、小车、教师笔记本全部从学校 DHCP 拿到同一网段地址，二层直接互通。

#### 4.4.2 这算不算 AP 模式

算。判断依据是结果，不是路由器上的模式开关名字：

- 网线接 **LAN 口**，**WAN 口空置**；
- 路由器 **DHCP 关闭**；
- 无线与 LAN 二层桥接、互通；
- 所有终端同网段、能互 ping；
- 路由器不做 NAT。

五条全部满足就是 AP 模式。用**有线回程**的 AP 模式比 WDS/无线中继稳定，本方案推荐这种。

#### 4.4.3 配置顺序（先配置，后接线）

1. **登录路由器**，把 LAN IP 改成学校网段内的空闲地址（如 `10.1.1.250`，避开网关和 DHCP 池），否则以后找不到管理页。
2. **关闭 DHCP 服务器**——最要紧的一步，忘了关等于在机房网段里多放一个 DHCP，会干扰整个教室甚至整层。
3. **WAN 口不接任何线**（部分固件的 AP 模式会把 WAN 并到 LAN，按说明书确认）。
4. **关闭 AP 隔离 / 客户端隔离**，关闭访客网络（访客网络默认隔离）。
5. **单独 SSID**，不要与学校 AP 同名；2.4G 给小车，5G 给教师笔记本。
6. **最后再接线**，接完按下表验证。

#### 4.4.4 五分钟验证

| 检查项 | 不通时优先排查 |
| --- | --- |
| 笔记本拿到的 IP 前三段与机房电脑一致 | DHCP 上行没桥接成功 |
| 笔记本 ping 通网关 | 路由器还在做 NAT |
| 笔记本 ping 通一台机房电脑 | AP 隔离没关 |
| 机房电脑 ping 通笔记本 | AP 隔离，或 Windows 防火墙挡 ICMP |
| 机房电脑浏览器能开 `http://小车IP:5000` | 车端进程/防火墙 |

五项全通，说明"同一网段"成立，中心与学生入口都能正常工作。

#### 4.4.5 必须提前确认的五件事

1. **学校交换机端口安全**：拔电脑插路由器可能触发"一个端口只允许一个 MAC"，也会涉及私接网络的管理规定——先报备网管，这是最大不确定性。
2. **DHCP 池与分配策略**：10 台车 + 教师笔记本 + 原有电脑，地址要够；若学校按 MAC 白名单分配，需要登记小车网卡。建议给 10 台车和教师笔记本做 **DHCP 保留**（固定 IP）。
3. **环路**：只允许"LAN 口接墙口 / LAN 口接教室机"。**不要把第二个 LAN 口再接回墙上或同一台交换机**，否则形成环路、广播风暴，整层断网。
4. **无线带宽**：10 台车同时推 MJPEG 视频会吃满 2.4G。建议 640×480@10fps、按需开流，不要 10 路同时看；教师笔记本走 5G。
5. **教师笔记本地址固定**：学生扫码入口指向中心，笔记本用 Wi-Fi 时 IP 可能变，必须静态 IP 或 DHCP 保留；更稳的是中心跑在有线教室机上，笔记本只作操作端。

#### 4.4.6 规模评估

- **10 台以内**：单台 AP 路由器 + 2.4G 足够，本方案直接可用。
- **30～40 台**：需要独立 AP、小车走 5G、视频分流，并重新评估心跳与中心负载。
- 同网段意味着学生可以绕过中心直连车 IP，**网络方案本身不提供权限控制**，必须依赖车端 `ClassroomGuard`。

## 5. 关键机制

### 5.1 设备发现与注册

**双通道发现**，互为兜底：

1. **UDP 广播（主）**
   车端 `ClassroomAgent` 启动后每 3 秒向 `255.255.255.255:5002` 发一条发现包；中心监听 5002。15 秒无包判离线。
   ```json
   {"v":1,"device_id":"pc-01-a1b2c3","name":"01号车","ip":"10.1.1.121","port":5000,"state":"LOCKED","fw":"2026.11"}
   ```
2. **网段扫描（兜底）**
   中心支持"扫描 10.1.1.0/24"，并发 HTTP `GET /classroom/info`（超时 300 ms、并发 64），把未广播到的车补进列表。用于 AP 隔离广播、跨网段或刚换 IP 的情况。

**稳定身份**：`device_id` 持久化在 `/etc/petcar/classroom.json`，首次启动由 CPU 序列号 + MAC 派生 UUID，不随 DHCP 变 IP 而变。车身上贴的编号（`name`）在中心改名后随心跳回写，掉落重装也能认回。

**手工添加**：支持填 IP + 端口，适合固定 IP 的老旧交换机环境。

### 5.2 状态模型（车况墙字段）

车端每 3 秒心跳上报，中心只展示、不轮询车端 HTTP（减少负载）：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `device_id` / `name` / `ip` | 本地配置 | 身份与地址 |
| `lock_state` | Guard | `UNLOCKED` / `ROSTER` / `LESSON` / `LOCKED` |
| `lesson` | Guard | 当前课程 `id`、名称、剩余秒数 |
| `session` | Guard | 当前占用座位/小组、进入时间 |
| `base` | `/api/status` 同源 | 速度、当前指令、是否运动中 |
| `camera` | 驱动 | 是否开启、是否在追踪 |
| `program` | BlockService | 是否运行、程序名、已运行秒数 |
| `sys` | 本地采集 | CPU 温度、负载、内存、运行时长 |
| `hw` | 驱动初始化结果 | 电机 HAT / 摄像头 / 音频 是否可用 |
| `version` | 本地 | petcar 版本、策略版本 |
| `last_seen` | 中心 | 最后心跳时间 |

> 电量：PetCar 目前没有电池采样硬件。若后续加 INA219，心跳增加 `battery: {v, pct}`，页面直接显示；没有则显示"—"，不臆造数据。

异常判定（中心侧规则，便于老师一眼看到）：

- 离线：> 15 s 无心跳
- 驱动异常：`hw` 任一项 false 且持续 > 10 s
- 高温：CPU > 75 ℃
- 失控风险：`program.running` 且 `base.moving` 但程序已超课程时长
- 被抢占：同一 `device_id` 出现两个不同座位会话

### 5.3 锁模型

#### 四态

| 状态 | 含义 | 允许的操作 |
| --- | --- | --- |
| `UNLOCKED` | 自由模式（备课、调试、开放日） | 全部（仍需令牌，见 5.5） |
| `ROSTER` | 课前待机，默认态 | 锁屏页、状态查询、急停 |
| `LESSON` | 上课中 | 持有本课令牌的学生，按课程包能力 |
| `LOCKED` | 强制锁定（讲台、充电、放学） | 锁屏页、状态查询、急停 |

优先级：`LOCKED` > `ROSTER` > `LESSON` > `UNLOCKED`。老师一键锁车时无论当前是什么课，直接进 `LOCKED` 并立即停车。

#### 租约与断连

- 中心随每次心跳响应下发 `lease_ttl`（默认 180 s，可在 30 s–30 min 调整）。
- 车端记录 `last_sync`（`time.monotonic()`，不受系统时间未同步影响）。
- 超过 `last_sync + lease_ttl`：
  1. 立即 `mecanum.stop()`、`block_service.stop()`、停止人脸追踪；
  2. 进入 `SAFE_LOCK`（按 `LOCKED` 处理）；
  3. OLED 显示"等待老师连接…"，网页显示"已与课堂中心断开"。
- 心跳恢复后按中心策略恢复，不会自动回到 `UNLOCKED`。

#### 断电重启

车端策略落盘 `/var/lib/petcar/classroom_policy.json`（含 `boot_state`）。默认 `boot_state = ROSTER`，即重启后必须由老师解锁。老师可把某台车设为 `boot_state = UNLOCKED` 用于开发调试。

### 5.4 能力、令牌与课程包

#### 能力（capability）

把现有 API 收敛成 9 个能力位：

| 能力 | 覆盖 |
| --- | --- |
| `page.panel` | 中控面板页面 |
| `page.blocks` | 积木编程页面 |
| `drive` | `/api/base/move`、`/api/base/speed` |
| `ptz` | `/api/ptz` |
| `camera` | `/api/video_feed`、`/api/camera/*`、`/api/photo*`、`/api/faces` |
| `vision` | `/api/color_cfg`、`/api/track`、`/api/detect` |
| `blocks` | `/api/blocks/run|stop|status|files/*` |
| `interact` | `/api/action`、`/api/emotion(s)`、`/api/chat`、`/api/tts`、`/api/skill/run`、`/api/asr/*` |
| `admin` | `/api/config*`、`/api/logs`、`/api/voice_test` |

`/api/estop`、`/api/blocks/estop` 不属于任何能力，**永久放行**。

#### 令牌

中心签发，形如：

```
pc1.<base64url(payload)>.<base64url(hmac_sha256(center_secret, payload))>

payload = {
  "jti": "9f2c…",            // 唯一 ID，可单独吊销
  "vid": "pc-01-a1b2c3",     // 绑定车辆
  "seat": "3组-B",            // 座位/小组
  "sid": "s-20261117-03",     // 课时会话
  "caps": ["page.blocks","camera","vision","blocks","drive"],
  "blocks_allow": ["event","control","logic","motion","sense.color"],
  "limits": {"max_speed": 140,"max_program_s": 300,"max_move_s": 3},
  "exp": 1795000000
}
```

- **一次使用**：`?t=<token>` 进入后换成 `HttpOnly` Cookie，随后从 URL 清掉，避免出现在浏览器历史和日志里。
- **车端本地验签**：车端与中心共享 `center_secret`，本地校验签名 + `vid` + `exp`，不依赖中心在线。
- **即时吊销**：心跳响应携带 `grants_epoch` 和已吊销 `jti` 列表；车端比对外，中心删授权 ≤ 3 s 生效。
- **短有效期**：默认到本节课结束时间 + 5 分钟；下课后所有令牌自动失效。

> 为什么还要 HMAC：没有签名，学生只需改 payload 里的 `caps` 就能越权。共享密钥在首次绑定时写入车端 `/etc/petcar/classroom.json`，不进 Git。

#### 课程包（Lesson Profile）

课程包是"当日这节课只能做什么"的配置，中心预置、老师可编辑：

```json
{
  "id": "lesson-03-traffic-light",
  "title": "第 3 课：红绿灯——看到红色就停",
  "caps": ["page.blocks", "camera", "vision", "blocks", "drive", "interact"],
  "blocks_allow": ["event", "control", "logic", "variable", "motion", "sense.color"],
  "limits": { "max_speed": 120, "max_program_s": 300, "max_move_s": 2.0 },
  "ui": { "mode": "blocks_only", "banner": "本节课只开放积木、颜色识别和低速行驶" },
  "auto_lock_after_s": 2400
}
```

预置示例：

| 课程包 | caps | 积木 | 限制 |
| --- | --- | --- | --- |
| L1 认识小坦（观察） | `camera, interact` | 无 | 不能动 |
| L2 让它动起来 | `camera, blocks, drive` | motion、control、event | 速度 ≤ 100/255，程序 ≤ 3 min |
| L3 红绿灯 | `camera, vision, blocks, drive, interact` | + sense.color | 速度 ≤ 150，程序 ≤ 5 min |
| 自由活动 | 全能力 | 全部 | 速度 ≤ 180，程序 ≤ 10 min |
| 备课/调试 | `admin` + 全能力 | 全部 | 不限（仅教师 PIN） |

课程包的强制点在**车端**，不是下发 JSON 给前端过滤：

- **路由级**：`before_request` 按能力表拦截。
- **积木级**：`BlockService.run()` 编译后遍历块类型所属 `category`，不在 `blocks_allow` 内直接返回 400，并指出第几块。
- **执行级**：`mecanum` 增加 `speed_cap`，`set_speed` / `move_for_duration` / 积木 runtime 的运动调用统一 clamp；`BlockService.max_runtime` 按课程包设置。
- **时长级**：开课倒计时到点 → 停程序 → 进 `LOCKED`。

### 5.5 请求拦截流程

车端新增 `ClassroomGuard.before_request()`，注册在 `create_app()` 最前面：

```
请求进入
  ├─ 静态资源（/static/*、Blockly 资源）        → 放行
  ├─ /api/estop、/api/blocks/estop              → 放行（只停）
  ├─ /classroom/*（心跳/上报）                   → 仅允许中心签名或 127.0.0.1
  ├─ 锁屏页 /lock、/api/init、/api/health        → 放行
  ├─ 其余请求：
  │    ├─ 取 Cookie/Authorization 中的令牌
  │    ├─ 无令牌 → API 返回 401，页面 302 到 /lock
  │    ├─ 令牌无效/过期/被吊销 → 401
  │    ├─ 路由未登记能力表 → 403（默认拒绝，并记审计）
  │    ├─ 能力不在令牌 caps → 403 + 友好提示
  │    └─ 写操作且 lock_state ∈ {LOCKED, ROSTER} → 423 Locked
  └─ 进入原路由
```

错误码约定，便于前端做统一提示：

| 状态码 | 语义 | 学生端提示 |
| --- | --- | --- |
| 401 | 未授权/令牌失效 | "请扫码重新进入课堂" |
| 403 | 本课不开放该功能 | "这节课还没有开放这个功能哦" |
| 423 | 车辆已锁定 | "小车被老师锁住啦" |
| 429 | 操作太频繁 | "慢一点，小车反应不过来" |

### 5.6 控制权与会话

- **一个会话 = 一个座位/小组 × 一台车 × 一节课**。
- 座位领车两种方式：
  1. **固定车身码（推荐）**：每台车贴二维码，指向中心 `/s/<device_id>`；学生扫码后输入老师投屏的 **4 位课堂码**，中心为其签发绑定该车的令牌。老师不用每节课打印新码。
  2. **按座位发码**：中心为每个座位生成一次性链接/二维码，适合严格对号入座。
- 同一台车第二个座位尝试进入：返回 409，并提示"该车已被 3 组使用"；老师端可"踢下线"。
- 老师可在车况墙看到"谁在用哪台车"，一键"收回"。
- 会话空闲 10 分钟无操作自动释放（令牌作废），避免占着车不玩。

### 5.7 安全兜底

| 场景 | 机制 |
| --- | --- |
| 学生用 curl 直接调运动 API | 车端 401/423，电机不动 |
| 页面卡死/断网 | 已有 0.6 s 运动租约看门狗，自动停车（沿用） |
| 中心宕机/教师机睡眠 | 宽限期后安全锁 + 停车，OLED 提示 |
| 学生抢方向盘 | 单会话绑定，非持有者 409 |
| 改课程包绕过限制 | 课程包只存中心，车端只接收已签名策略；本地文件校验签名 |
| 令牌被转发给其他班 | 绑 `vid` + `sid` + `exp`，下课即失效 |
| 老师忘了锁车 | 课程结束时间自动锁；放学按钮；可配置"静默 N 分钟自动锁" |
| 老师手机没电 | 车端本地教师 PIN（6 位，贴车底）在锁屏页输入，获 10 分钟教师权限；使用记审计 |
| 急停 | 永久放行、幂等，任何状态都可停 |

### 5.8 审计

车端本地环形日志（最多 5000 条）+ 中心 SQLite 汇总，记录：

`device_online/offline`、`lock/unlock`、`lesson_start/end`、`token_issue/revoke`、`session_start/end`、`blocked_request`（按路由+座位聚合，1 分钟一条，防刷爆）、`program_run/stop`、`estop`、`speed_clamped`、`policy_change`、`pin_unlock`。

中心支持按班级/日期/车辆筛选，导出 CSV。目的不是追责，而是**下节课能复盘"哪台车为什么跑飞"**。

## 6. 接口设计

### 6.1 车端新增（`petcar/classroom/`）

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/classroom/info` | 公开（脱敏） | 身份、版本、当前锁态，供扫描发现 |
| POST | `/classroom/heartbeat` | 中心 HMAC | 上报状态，返回策略与授权增量 |
| GET | `/classroom/policy` | 中心 HMAC | 主动拉取（心跳失败时重试） |
| POST | `/classroom/grant` | 中心 HMAC | 下发/吊销令牌（也可合并进心跳响应） |
| POST | `/classroom/lock` | 中心 HMAC 或教师 PIN | 立即锁定/解锁 |
| GET | `/lock` | 公开 | 锁屏页（显示车号、班级、状态、扫码说明） |
| POST | `/classroom/pin` | 公开 + 限速 | 教师 PIN 应急解锁 |

心跳请求（车 → 中心）：

```http
POST /api/vehicles/pc-01-a1b2c3/heartbeat
X-PetCar-Ts: 1794922834
X-PetCar-Sig: hmac_sha256(secret, ts + "\n" + body)

{"state":"LESSON","policy_ver":17,"program":{"running":true,"name":"红绿灯","elapsed":42},
 "base":{"speed":120,"moving":true},"sys":{"cpu":46.1,"temp":58.2,"mem":63},
 "hw":{"motor":true,"camera":true,"audio":true},"session":{"seat":"3组-B"}}
```

心跳响应（中心 → 车）：

```json
{
  "policy_ver": 18,
  "lock_state": "LESSON",
  "lease_ttl": 180,
  "lesson": {"id":"lesson-03-traffic-light","ends_at":1795000000},
  "caps": ["page.blocks","camera","vision","blocks","drive","interact"],
  "blocks_allow": ["event","control","logic","motion","sense.color"],
  "limits": {"max_speed":120,"max_program_s":300,"max_move_s":2.0},
  "grants": [{"jti":"9f2c","seat":"3组-B","exp":1795000300}],
  "revoked": ["1a7d"]
}
```

原则：**策略全量下发、幂等应用**；车端只认 `policy_ver` 更大的包，避免乱序覆盖。

### 6.2 中心端（`classroom_console`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 车况墙页面 |
| GET | `/api/vehicles` | 车辆列表 + 状态 + 异常标记 |
| POST | `/api/vehicles/{id}/lock` | 单台锁/解锁（`{"lock":true,"reason":"充电"}`） |
| POST | `/api/vehicles/lock-all` | 全部锁定 |
| POST | `/api/vehicles/scan` | 触发网段扫描 |
| GET/POST | `/api/lessons` | 课程包列表/保存 |
| POST | `/api/sessions` | 开课（课程包、车辆分组、时长） |
| POST | `/api/sessions/{id}/end` | 放学（全锁 + 吊销令牌 + 停程序） |
| POST | `/api/sessions/{id}/seat` | 为座位签发令牌，返回二维码内容 |
| POST | `/api/sessions/{id}/revoke` | 收回某座位 |
| GET | `/s/{device_id}` | 学生入口，校验课堂码后 302 到车端并带令牌 |
| GET | `/api/audit` | 审计查询/导出 |
| GET | `/api/health` | 中心自检 |

课堂码：4 位数字，每节课随机，5 分钟自动轮换一次（旧码宽限 60 s），投屏显示。防的是"隔壁班学生拿旧链接进来"。

### 6.3 OLED / 灯效反馈

PetCar 有 OLED 和表情引擎，锁态要"看得见"：

| 状态 | OLED |
| --- | --- |
| `ROSTER` | 睡眼表情 + "等你上课" |
| `LESSON` 未授权 | 好奇表情 + "扫码带我玩" |
| `LESSON` 已授权 | 开心 + 当前课程名 |
| `LOCKED` | 委屈/睡着 + "老师锁住我了" |
| 失联 | 疑惑 + "找不到老师" |

## 7. 数据模型（中心 SQLite）

```sql
vehicles(id TEXT PK, name TEXT, ip TEXT, port INT, secret_hash TEXT,
         boot_state TEXT, last_ip TEXT, last_seen REAL, fw TEXT, tags TEXT);

lessons(id TEXT PK, title TEXT, caps TEXT, blocks_allow TEXT, limits TEXT,
        ui TEXT, auto_lock_after_s INT, updated_at REAL);

sessions(id TEXT PK, lesson_id TEXT, class_name TEXT, started_at REAL,
         ends_at REAL, status TEXT);            -- planned/active/ended

grants(jti TEXT PK, session_id TEXT, vehicle_id TEXT, seat TEXT,
       token_hash TEXT, exp REAL, revoked INT DEFAULT 0);

vehicles_state(vehicle_id TEXT PK, state TEXT, payload TEXT, updated_at REAL);

audit(id INTEGER PK AUTOINCREMENT, ts REAL, actor TEXT, action TEXT,
      vehicle_id TEXT, detail TEXT);
```

车端本地只存三个文件：

- `/etc/petcar/classroom.json`：`device_id`、`center_url`、`center_secret`、`name`
- `/var/lib/petcar/classroom_policy.json`：最近一次策略（含签名）
- `/var/lib/petcar/audit.jsonl`：环形审计

## 8. 关键时序

### 8.1 自动发现

```
车 ClassroomAgent                 中心
   │── UDP 广播 5002 ─────────────►│ 维护在线表（15s 超时）
   │── POST heartbeat ────────────►│ 更新状态
   │◄── 200 {lock_state:ROSTER} ───│ 下发策略
   │  （每 3s 重复；失败则按 ttl 进入安全锁）
```

### 8.2 开课与发码

```
老师               中心                         车 01                 学生
 │  选课程包+车辆    │                            │                     │
 │──POST /sessions ─►│ 生成 session，push LESSON   │                     │
 │                   │──heartbeat 响应(策略) ─────►│ Guard 生效           │
 │  投屏课堂码 4821   │                            │                     │
 │                   │◄──── 扫码 /s/pc-01 ───────────────────────────────│
 │                   │  验证课堂码 → 签发令牌       │                     │
 │                   │──────────────── 302 ?t=token ────────────────────►│
 │                   │                            │◄─ GET /?t=token ────│
 │                   │                            │  验签 → Set-Cookie   │
 │                   │                            │── 受限积木页 ──────►│
```

### 8.3 学生越权

```
学生 curl /api/base/move
  → Guard: 有令牌? 无 → 401 {"error":"need_token"}
  → 有令牌但 caps 无 drive → 403 {"error":"capability_denied","cap":"drive"}
  → 有 drive 但 lock_state=LOCKED → 423
  → 电机不动，审计 blocked_request +1
```

### 8.4 下课

```
老师点放学
  → sessions.status=ended，grants 全撤销，policy_ver+1
  → 心跳下发 lock_state=LOCKED + lesson=null
  → 车端立即停车、清空令牌、OLED 睡着
  → 审计落库，导出本节课报告
```

## 9. 界面设计

### 9.1 教师端车况墙

- 顶部：教室名、在线/总数、当前课程与倒计时、`全部锁定`、`开课`、`放学`
- 车辆网格（每卡一行关键信息）：
  ```
  ┌──────────────────────────────┐
  │ 01 号车        ● 在线  已锁  │
  │ 10.1.1.121   温度 52℃ 负载 31%│
  │ 状态：待机    摄像头：关       │
  │ [解锁] [查看详情] [改名]      │
  └──────────────────────────────┘
  ```
- 颜色语义：灰=离线，蓝=待机/锁，绿=上课中正常，橙=被占用/高温，红=异常/失联
- 详情抽屉：最近 20 条审计、当前程序、会话、一键踢下线、单独下发提示语
- 开课弹窗：课程包、选车（全选/按组）、时长、是否自动锁、限速覆盖
- 审计页：筛选 + 导出 CSV

### 9.2 学生端

- 未授权：锁屏页（车号、班级、大按钮"扫码/输入课堂码"、可爱插画、不暴露任何 API 状态）
- 已授权且 `ui.mode=blocks_only`：直接进积木页，隐藏中控面板入口；顶部横幅"第 3 课 · 红绿灯 · 剩余 12:30"
- 被课程包禁用的积木**不出现在工具箱里**（体验层），即使手工导入 JSON 也会在编译期被拒（安全层）
- 锁定/下课：整页覆盖"这节课结束啦，小车要休息了"

### 9.3 视觉与文案

面向小学生：错误提示不要出现 403/423，统一转成拟人句；锁定页不显示 IP、版本、日志等运维信息。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 教室 Wi-Fi 开了 AP 隔离 | 中心发现不到车，学生也连不上车 | 按 4.4.3 关闭 AP 隔离；专用 SSID；兜底为网段扫描 |
| 学校交换机端口安全 / 禁止私接 | 路由器上联被封，整组设备断网 | 提前报备网管；优先使用空闲信息点；不在端口安全端口后挂多个 MAC |
| 路由器忘关 DHCP | 干扰机房网段，可能大面积掉线 | 先关 DHCP 再接线；接完复查管理页 |
| LAN 口回接交换机形成环路 | 广播风暴，整层断网 | 只允许 LAN→墙口、LAN→教室机，不把两个 LAN 接回同一网络 |
| 学校 DHCP 池不足 / MAC 白名单 | 小车拿不到 IP 或频繁换 IP | 申请足够地址段；按 MAC 做 DHCP 保留 |
| 10 台车同时推视频，2.4G 拥塞 | 画面卡顿、控制指令延迟 | 640×480@10fps、按需开流；教师笔记本走 5G |
| DHCP 换 IP | 车况墙地址失效 | `device_id` 稳定 + 心跳带新 IP，中心自动更新 |
| 教师机休眠/断电 | 全班车被安全锁 | 宽限期可调（默认 180 s）+ 本地 PIN 应急；建议教师机接电源、关闭休眠 |
| 中心是单点 | 全教室不可用 | 中心只做控制面；已开课的令牌与策略在车端本地生效，短时可用 |
| 学生拿到教师 PIN | 越权 | PIN 每车独立、贴车底、使用留痕、10 分钟自动过期；可远程轮换 |
| 令牌泄露到班群 | 其他班蹭玩 | 绑课时 + 车辆 + 座位，下课即失效；课堂码轮换 |
| 1 GB/低配板的额外负载 | 影响视频与积木 | 心跳 3 s 仅几 KB；Guard 只做字典查表；审计异步写盘 |
| 时间未同步导致令牌误判 | 学生被踢 | 令牌用中心时间签发，车端用"启动时长 + 上次同步"换算；容忍 ±5 min 漂移 |
| 老师嫌操作多 | 不用 | 默认全锁 + 一键开课 + 固定车身码，整节课老师只需点 3 次 |
| 强管控影响备课/创客活动 | 体验下降 | `UNLOCKED` 自由模式与 `boot_state` 可配；管理 PIN 进管理模式 |

## 13. 已确认前提与待确认问题

### 13.1 已确认（2026-11-17）

- 教室新增一台路由器，以 **AP 模式**接入机房局域网；路由器关闭 DHCP，小车与教师笔记本从学校 DHCP 获取同网段地址。具体接法与验证见 4.4。
- 单教室 **10 台以内**小车。
- 学生使用**机房有线台式机**，教师使用笔记本（Wi-Fi）。
- 控制信令与视频流均为浏览器直连车端，中心只做授权与观测。

### 13.2 待确认

1. **端口安全**：学校交换机是否开启端口安全/802.1X？是否允许在教室私接路由器？
2. **地址分配**：学校 DHCP 池是否够用？是否按 MAC 白名单分配？能否为 10 台小车和教师笔记本做 DHCP 保留？
3. **VLAN**：机房墙面口是否为 access 口、与机房电脑同 VLAN？小车是否只需 2.4G？
4. **身份**：是否需要学号/姓名登录，还是"座位/小组"匿名即可？
5. **课程包来源**：课程包由谁维护（老师自建 / 教研组统一 / 随固件内置）？
6. **硬件外设**：是否有电池电量采样、物理急停按钮或按键？（影响状态字段与兜底方式）
7. **监管要求**：学校是否要求操作留痕、数据本地存储、不得上云？（当前方案全本地，天然满足）
8. **交付形态**：中心做成绿色版 Windows 程序（双击运行），还是 Python 包由部署脚本安装？

## 14. 一句话总结

在每台车上加一个**默认拒绝的管控闸门**（`ClassroomGuard`），在教师机上放一个**只做授权与观测的中心**（`classroom_console`）：老师看得见所有车、锁得住所有车、只放开本节课该用的能力；学生扫码即用、越权即挡；断网即停车、下课即收车。
