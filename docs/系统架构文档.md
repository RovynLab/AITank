## 一、系统定位与总体分层

AI Tank 由两条产品线共用同一套硬件与底层驱动：

| 产品线 | 代码位置 | 目标 |
|---|---|---|
| 教学实验 | `labs/lab01~lab12`、`demos/` | 知识点逐个剥离，每个实验自包含、可单独运行 |
| 集成应用 | `petcar/` | 中控面板 + 语音对话 + 大模型 + 视觉 + 积木编程 |

`petcar` 采用**单进程、多线程、分层解耦**的结构。层与层之间只允许上层依赖下层，驱动层不反向依赖业务层。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 交互层  petcar/main.py  ·  api/flask_app.py  ·  core/voice_io.py     │
│         api/block_api.py  ·  student_api/  ·  static/dashboard.html  │
├──────────────────────────────────────────────────────────────────────┤
│ 能力层  core/chat_agent  ·  core/llm_backends  ·  core/skill_manager │
│         core/emotion_engine  ·  core/mood_engine  ·  core/pid_tracker│
│         core/runtime_config                                          │
├──────────────────────────────────────────────────────────────────────┤
│ 工具层  skills/move · ptz · photo · face_detect · face_track         │
│         weather · alarm · emote · express                            │
├──────────────────────────────────────────────────────────────────────┤
│ 积木层  blocks/catalog → compiler → service(ProgramRunner) → runtime  │
│         blocks/perception（快照缓存）                                 │
├──────────────────────────────────────────────────────────────────────┤
│ 驱动层  drivers/mecanum · ptz · oled · camera · detectors · gesture  │
│         drivers/asr · tts                                            │
├──────────────────────────────────────────────────────────────────────┤
│ 硬件层  PCA9685(0x60) · 麦轮四驱 · 2 轴云台 · USB 摄像头             │
│         SSD1306 OLED(0x3C) · USB 麦克风 · USB/板载声卡               │
└──────────────────────────────────────────────────────────────────────┘
```

### 1.1 目录职责

| 目录 | 职责 | 关键说明 |
|---|---|---|
| `petcar/main.py` | 进程入口、装配所有模块 | 只做“组装 + 启动 + 清理”，不含业务逻辑 |
| `petcar/config.py` | 静态默认配置 | 硬件地址、通道、模型名、音色、VAD 等，全部支持 `PETCAR_*` 环境变量覆盖 |
| `petcar/core/` | 与硬件无关的能力 | 对话、LLM 后端、情感、心情、PID、配置热更新 |
| `petcar/drivers/` | 硬件/系统能力封装 | 每个驱动都提供“真机实现 + Mock/降级” |
| `petcar/skills/` | 给大模型调用的本地工具 | 统一 `BaseSkill` 契约 |
| `petcar/blocks/` | 积木解释器 | 白名单编译 + 单实例运行 + 运动租约 |
| `petcar/api/` | Flask HTTP 层 | 中控面板、REST API、MJPEG 视频流 |
| `petcar/student_api/` | 学生极简接口 | `EmojiRobot` / `Face`，屏蔽线程与硬件细节 |
| `deps/` | Adafruit PCA9685 驱动副本 | 全项目唯一副本，通过 `sys.path` 注入 |
| `data/config_local.json` | 面板保存的运行时配置 | 放在仓库根 `data/`，避免部署时被 `rm -rf petcar/` 清掉 |

## 二、进程与线程模型

`petcar` 是**单 Python 进程**，靠线程完成并发。理解线程分布是排查卡顿、抢资源问题的前提。

| 线程/执行体 | 创建位置 | 周期/触发 | 职责 |
|---|---|---|---|
| 主线程 | `main.py:main()` | 常驻 | 装配模块；启动 Flask 线程后阻塞在语音循环或空转 |
| Flask HTTP 线程 | `main.py` `_run_flask()` | 常驻 | `debug=False, use_reloader=False`，daemon |
| VoiceIO 循环 | `core/voice_io.py:start()` | 常驻 | `ASR → ChatAgent → Emotion → TTS` 串行闭环 |
| EmotionEngine 渲染 | `core/emotion_engine.py:_loop()` | 8 FPS | 绘制表情、眨眼、说话嘴型、思考动画 |
| MoodEngine 衰减 | `core/mood_engine.py` | 1 Hz 左右 | valence/arousal/intensity 衰减与空闲行为 |
| Camera 采集 | `drivers/camera.py:_frame_loop()` | 摄像头帧率 | 持续读取最新帧到 `_latest_frame` |
| ASR 识别 | 调用方线程（VoiceIO / Flask job） | 按需 | 录音 + VAD + faster-whisper 转写，`_lock` 串行 |
| TTS 播放 | 调用方线程 / `speak_async` | 按需 | edge/piper/espeak 合成与 `aplay` 播放 |
| 动作播放器 | `skills/express.py:ExpressionPlayer` | 按需 | 底盘 + 云台组合动作序列 |
| 积木解释器 | `blocks/service.py:ProgramRunner` | 每次运行 | 顺序解释 IR，最长 600 s |
| 积木看门狗 | `blocks/runtime.py:_watchdog_loop()` | 0.2 s | 运动租约超时自动停车 |
| 感知快照 | `blocks/perception.py:_loop()` | 0.3 s | 给人脸/网球/颜色生成布尔快照 |
| PID 追踪 | `core/pid_tracker.py:_loop()` | ~0.06 s | 检测目标 → 视觉伺服 → 云台 |
| MJPEG 生成器 | `flask_app.py:gen()` | 15 FPS 上限 | 画检测框并输出 JPEG 流 |

### 2.1 关键资源争用与仲裁

| 资源 | 冲突场景 | 现有仲裁机制 |
|---|---|---|
| I2C-1 总线 | OLED 8 FPS 重绘会拖慢 PCA9685 电机/舵机写 | `EmotionEngine._render()` 渲染去重：画面无变化不推 I2C |
| 麦克风 | 语音主循环与面板“对话测试”同时录音 | `ASRDriver._lock` 串行；面板测试期间 `asr.paused=True` |
| 扬声器回声 | TTS 播报被自己麦克风拾取 | `TTSDriver.is_speaking()` 期间不收音；`VoiceIO` 文本重合判回声 + 播后 `sleep(0.5)` |
| 底盘 | 积木程序与手动面板同时发运动指令 | 积木运行中手动接口返回 `409`；`BlockRuntime` 运动租约 |
| 底盘 | 宠物动作与手动指令抢电机 | 手动控制前 `_cancel_action()` 中断动作播放器 |
| 检测器 | 多标注并发调用同一 OpenCV 检测器 | `CameraDriver._det_lock`；DNN 结果按 `frame_id` 缓存、每 2 帧推理一次 |

## 三、大模型部署架构

### 3.1 后端抽象

所有后端实现同一个抽象基类（`petcar/core/llm_backends.py`）：

```python
class LLMBackend(ABC):
    @abstractmethod
    def chat(self, messages: list[dict], tools: list[dict]) -> dict:
        # 返回 {"content": str, "tool_calls": [{"name": str, "arguments": dict}]}
```

| 后端 | 类 | 运行位置 | 协议 | 适用场景 |
|---|---|---|---|---|
| Ollama | `OllamaBackend` | 板端本地（也可指向局域网 PC） | HTTP `POST /api/chat` | 断网可用、隐私好、速度受板卡限制 |
| Doubao | `DoubaoBackend` | 火山引擎云端 | Ark API，OpenAI 兼容 `/api/v3/chat/completions` | 更聪明，需联网 + API Key |
| Mock | `MockBackend` | 板端 | 无网络，纯正则规则 | 演示、无模型环境、只做指令控制 |

工厂函数 `create_llm_backend()` 负责**可用性探测与自动回退**：

```
选择 llm_backend
  ├─ ollama → GET {host}/api/tags (3s 超时)
  │            ├─ 200 → OllamaBackend
  │            └─ 失败 → MockBackend
  ├─ doubao → 有 DOUBAO_API_KEY ? DoubaoBackend : MockBackend
  └─ mock   → MockBackend
```

### 3.2 本地 Ollama 部署

| 项目 | 值 |
|---|---|
| 二进制 | `~/bin/ollama`（`ollama-linux-arm64`，用户级安装，无需 sudo） |
| 服务地址 | `http://localhost:11434`（`PETCAR_OLLAMA_HOST` 可指向局域网 PC） |
| 默认模型 | `qwen2.5:0.5b`（`petcar/config.py`），部署脚本会拉 `qwen2.5:1.5b` |
| 请求参数 | `stream=false`；`temperature=0.7`；`num_predict=150`；`timeout=180s` |
| 工具调用 | 请求体带 `tools`，解析响应 `message.tool_calls[].function.arguments` |

部署脚本 `deploy_petcar.py` 的 Ollama 步骤：

1. 确认 aarch64 架构；
2. 下载 `ollama-linux-arm64` 到 `~/bin/ollama` 并 `chmod +x`；
3. `nohup ~/bin/ollama serve > ~/ollama.log 2>&1 &` 后台启动；
4. `ollama pull qwen2.5:1.5b`；
5. 用 `POST /api/chat` 做直连自测，再用 `PETCAR_LLM_BACKEND=ollama python3 -c ...` 做 `ChatAgent` 联调。

**模型选型权衡（Pi 4B 2GB）**：

| 模型 | 内存 | 速度 | 稳定性 | 建议 |
|---|---|---|---|---|
| `qwen2.5:0.5b` | 小 | 约 7 token/s | 工具调用不稳定，易跑偏 | 默认；对话 + 本地规则直连技能 |
| `qwen2.5:1.5b` | 约 1.5 GB | 更慢 | 语义理解更好 | 面板可切换，注意与视觉/Whisper 抢内存 |

### 3.3 云端 Doubao 部署

- Endpoint：`https://ark.cn-beijing.volces.com/api/v3/chat/completions`
- 鉴权：`Authorization: Bearer $DOUBAO_API_KEY`
- 请求：`model`（模型名或推理接入点 ID）、`messages`、`tools`、`tool_choice=auto`
- Key 只保存在板端 `data/config_local.json`，面板回显掩码。

### 3.4 提示词与输出协议

`ChatAgent._build_system_prompt()` 组装：

1. 身份与人格：`PET_NAME` + `PET_PERSONALITY`；
2. 输出格式：强制 `<reply>…</reply>` 与 `<emotion>…</emotion>`；
3. 工具调用：`<tool_call>{"name": ..., "args": {...}}</tool_call>`（文本协议，兼容小模型）；
4. 工具清单：由 `SkillManager.list_tools_prompt()` 生成；
5. Few-shot 示例。

解析侧 `_extract_reply_and_emotion()` 做正则提取；若小模型不按格式输出，会剥离标签后兜底为正文，并校验 emotion 白名单。

### 3.5 小模型兜底策略（重要）

0.5B 模型无法稳定输出 `tool_calls`，因此 `ChatAgent` 在调用 LLM 之前先走**本地规则直连**（`_LOCAL_RULES`）：

```
用户文本 → 繁简归一 → 正则匹配
  ├─ 命中（摇头/点头/跳舞/抬头/左转/前进/停止/拍照…）
  │    → SkillManager.execute(name, **args) → 立即返回固定话术
  └─ 未命中 → 进入 LLM + tool calling 循环
```

这让“动作类指令”在弱模型、断网、甚至 Mock 模式下都能稳定执行。

## 四、核心调用流程

### 4.1 语音对话主链路

```
用户说话
  │
  ▼
ASRDriver.listen(timeout=15)
  ├─ 48kHz 可用? 否则 16kHz
  ├─ VAD：前 0.5s 噪声基线 → 动态阈值 → 200ms 起录 → 1.2s 静音结束
  ├─ 峰值归一化到 0.9
  ├─ 落盘 petcar_asr.wav（让 faster-whisper 按文件头重采样到 16k）
  └─ transcribe(language=zh, vad_filter=True)
       ├─ avg_logprob < -1.0 → 丢弃
       ├─ 整句重复 → 截半
       └─ 纯数字 token → 过滤
  │
  ▼
VoiceIO._loop()
  ├─ 跳过：TTS 正在播 / asr.paused
  ├─ 思考表情 start_think(3s)
  ├─ 回声判定（识别文本 ⊆ 上次播报）
  │
  ▼
ChatAgent.chat(text)
  ├─ 写入 history（最多 20 条）
  ├─ 本地规则命中 → 直接执行 Skill 并返回
  └─ 否则最多 3 轮：
       messages(system + history) + tools
         → LLMBackend.chat()
         → 有 tool_calls：去重 → SkillManager.execute → tool 消息回填 → 下一轮
         → 无 tool_calls：结束
  │
  ▼
ChatResponse{reply, emotion, tools_called}
  │
  ├─ EmotionEngine.set_emotion(emotion)
  ├─ EmotionEngine.start_speak(duration≈字数×0.15)
  ├─ TTSDriver.speak(reply)   ← 阻塞，播完才继续
  └─ MoodEngine.trigger(emotion, 0.8)
```

### 4.2 Web 面板对话链路

```
浏览器 GET /api/chat?text=...&speak=1
  → ChatAgent.chat()
  → emotion.set_emotion + start_speak
  → 后台线程 tts.speak()（不阻塞 HTTP）
  → 返回 {reply, emotion, tools_called, spoke}
```

面板“对话测试”`POST /api/voice_test` 是完整闭环：`TTS 提示音 → ASR 录音 → ChatAgent → TTS 回复`，并在 `voice_job` 中返回峰值、阈值、录音时长、logprob，便于现场调 VAD。

### 4.3 积木程序链路

```
Blockly 页面（本地打包，无 CDN）
  │  workspace JSON
  ▼
POST /api/blocks/run
  ▼
compiler.compile_program()
  ├─ 只允许 1 个 event_start
  ├─ 白名单 11 种积木；最多 300 块、嵌套 15 层
  ├─ 字段范围校验（速度 50~255、时间 0.1~30s 等）
  └─ 输出 IR：{version, block_count, hats:[{event, body}]}
  ▼
BlockService.run()
  ├─ 已有程序运行 → BusyError → HTTP 409
  ├─ state=running，启动 PerceptionCache
  └─ ProgramRunner（后台线程）
       ├─ 顺序解释 IR
       ├─ move_start(owner) → 每 0.6s 续租
       ├─ 看门狗 0.2s 检查租约，超时自动停车
       ├─ if_sees 只读感知快照，不阻塞控制循环
       └─ 结束/异常/超时/急停 → release_all()
  ▼
GET /api/blocks/status?since=N → 状态 + 增量日志 + 当前积木高亮
```

### 4.4 视觉检测与视频流链路

```
CameraDriver._frame_loop()  ── 最新帧 ──►  _latest_frame
                                            │
        ┌───────────────────────────────────┼──────────────────────────┐
        ▼                                   ▼                          ▼
  /api/video_feed                     /api/faces                 PIDTracker
  annotators 逐个检测                  YuNet/Haar                 target=face/color/tennis
  画框 + ASCII 标签                   返回人脸框                  绝对角度视觉伺服 → PTZ
  JPEG(70) → MJPEG 15fps
```

`annotators` 注册表（面板复选框逐个开关）：

| key | 标签 | 来源 | 说明 |
|---|---|---|---|
| `person` | 人 | TFLite SSD / NanoDet COCO | class 0 |
| `pet` | 宠物 | COCO | class 14/15/16 |
| `cup` | 水杯 | COCO | class 39/41 |
| `ball` | 网球 | COCO | class 32 |
| `tv` | 屏幕 | COCO | class 62 |
| `tennis` | 网球·色 | HSV + 形状门限 | 无模型，秒开 |
| `motion` | 运动 | 帧差 | 跨帧状态 |
| `color` | 颜色 | HSV 可调 | P1 面板参数，P2 复用 |
| `gesture` | 手势识别 | MediaPipe / OpenCV 凸包 | 框上叠加手势英文标签 |
| `face` | 人脸 | YuNet / Haar | 与 `/api/faces` 共用 |

## 五、工具（Skills）体系

### 5.1 契约

`petcar/skills/base_skill.py` 定义统一接口：

```python
class BaseSkill(ABC):
    name: str
    description: str
    parameters: dict          # JSON Schema
    def execute(self, **kwargs) -> str: ...
    def on_register(self): ...
    def on_unregister(self): ...
    def get_tool_prompt(self) -> str: ...
    def get_openai_tool_spec(self) -> dict: ...
```

`SkillManager` 只做四件事：注册/注销、按名执行、生成 system prompt 文本、生成 OpenAI function-calling 规格。执行异常统一转成字符串返回给 LLM，避免打断对话。

### 5.2 已注册工具清单

| name | 类 | 能力 | 主要参数 |
|---|---|---|---|
| `move` | `MoveSkill` | 麦轮底盘运动 | `direction`（8 方向 + stop）、`duration` |
| `look` | `PTZSkill` | 云台转动 | `direction`（up/down/left/right/center）、`delta` |
| `take_photo` | `PhotoSkill` | 拍照存盘 | 无 |
| `detect_face` | `FaceDetectSkill` | 统计人脸数量 | 无 |
| `track_face` | `FaceTrackSkill` | 云台追脸 30 s | 无 |
| `weather` | `WeatherSkill` | wttr.in 免费天气 | `city` |
| `set_alarm` | `AlarmSkill` | 倒计时 / 绝对时间闹钟 | `seconds` / `time_str` |
| `show_emotion` | `EmoteSkill` | OLED 表情 | `emotion` |
| `express` | `ExpressSkill` | 宠物组合动作 | `action` |

### 5.3 宠物动作库

`skills/express.py` 的 `ACTIONS` 是纯数据表，共 12 个动作：

`nod`（点头）、`shake`（摇头）、`tilt`（歪头）、`wag`（摆尾）、`twist`（扭腰）、`spin`（转圈）、`nuzzle`（蹭蹭）、`hop`（蹦跳）、`droop`（委屈低头）、`lean_in`（凑近）、`look_around`（张望）、`stretch`（伸懒腰）。

步骤原语：

```python
("ptz_h", 角度, 保持秒)          # 水平轴绝对角度
("ptz_v", 角度, 保持秒)          # 垂直轴绝对角度
("ptz_hv", 水平, 垂直, 保持秒)   # 双轴
("chassis", 方向, 速度, 秒)      # 底盘短脉冲，结束立即停
("wait", 秒)
```

`ExpressionPlayer` 在后台线程顺序执行，`stop()` 会中断并回中；`action_player.play()` 不阻塞。面板手动控制前会先 `_cancel_action()`。

## 六、驱动层

驱动层的统一约定：

1. **构造即降级**：依赖缺失时打印提示并切换 Mock，不抛异常阻断启动；
2. **线程安全**：涉及共享状态的公开方法加锁；
3. **配置现读**：关键参数在调用时读取 `petcar.config`，便于面板热更新；
4. **可独立自测**：每个驱动文件底部有 `if __name__ == "__main__"` 自测入口。

### 6.1 麦轮底盘 `drivers/mecanum.py`

| 项目 | 值 |
|---|---|
| 控制器 | PCA9685 @ `0x60`，50 Hz |
| 电机通道 | 1=FR、2=FL、3=TL、4=TR |
| 默认速度 | 150 / 255 |
| 依赖 | `deps/Adafruit_MotorHAT`（`sys.path` 注入） |
| 降级 | 库缺失 → 只更新状态，不驱动硬件 |

运动由 `_MOTION_TABLE` 的四电机方向组合决定：

| 指令 | m1 | m2 | m3 | m4 |
|---|---|---|---|---|
| forward | F | F | F | F |
| backward | B | B | B | B |
| leftSlide | B | F | F | B |
| rightSlide | F | B | B | F |
| turnLeft | F | B | B | F |
| turnRight | B | F | F | B |
| spin | B | F | F | B |

`move_for_duration()` 用 `threading.Timer` 到时自动 `stop()`；`current_command` 供面板显示。

### 6.2 云台 `drivers/ptz.py`

| 项目 | 值 |
|---|---|
| 水平舵机 | 通道 0，0°~180°，初始 90° |
| 垂直舵机 | 通道 1，45°~135°，初始 90° |
| 脉宽映射 | `pulse_ms = angle / 90 + 0.5`（0.5~2.5 ms） |
| 12 位刻度 | `tick = pulse_ms × 204.8`（50 Hz，20 ms 周期 4096 tick） |
| 方向约定 | **垂直角增大 = 向上**，减小 = 向下（已与实车机械方向对齐） |

接口：`h_rotate/v_rotate`（绝对角）、`h_increase/v_increase`（增量）、`look_left/right/up/down/center`（语义化）、`init()`（回中）。

### 6.3 OLED `drivers/oled.py`

| 项目 | 值 |
|---|---|
| 屏幕 | SSD1306 128×64，I2C @ `0x3C` |
| 依赖 | `luma.oled` + `Pillow`，缺失自动 `MockOLEDDriver`（终端 ASCII 预览） |
| 表情 | 12 种：neutral/happy/sad/angry/surprised/sleepy/love/thinking/wink/laugh/scared/confused |
| 绘制 | 眼睛 6 种形态、嘴巴 7 种形态、眉毛 4 种、装饰（泪/zzz/汗/问号） |
| 接口 | `show_expression`、`show_custom_face(face, offset_y)`、`show_text` |

`EmotionEngine` 在其上叠加动画与渲染去重：

| 动画 | 效果 |
|---|---|
| `blink` | 双眼变横线 0.25 s |
| `speak` | 嘴巴在 open / arc_top 之间交替 |
| `think` | 一只眼变问号 |
| `happy_bounce` | 整体上下偏移 ±2 px |

### 6.4 摄像头 `drivers/camera.py`

- 采集：独立线程持续 `cap.read()`，只保留最新帧，避免业务层读到旧帧；
- `latest_frame()` 非阻塞拷贝；`capture()` 最多等 1 s；
- 人脸检测优先级：`FaceDetectorYN`（YuNet ONNX，score 0.9）→ Haar 级联 → 空结果；
- 检测器非线程安全，`_det_lock` 串行；
- 内置简化追脸：取最大人脸，像素误差 → 角度增量，死区 40/30 px。

### 6.5 目标检测 `drivers/detectors.py`

| 检测器 | 实现 | 输入 | 特点 |
|---|---|---|---|
| `TFLiteSSD` | TFLite SSD MobileNet 量化，COCO 80 类 | 300×300 | 默认首选，Pi 上约 100~200 ms/帧 |
| `NanoDet` | OpenCV DNN，NanoDet-Plus-m | 320×320 | TFLite 缺失时回退，约 1~2 FPS |
| `detect_color` | HSV 阈值 + 形态学 | 原图 | 支持红色跨 0° 双段 |
| `detect_tennis_ball` | HSV + 长宽比 + 圆形度 + 填充率 + 面积 | 原图 | 四重门限压误报 |
| `detect_motion` | 帧差 + 阈值 + 膨胀 | 跨帧灰度 | 需外部传入 `state` |

统一输出：`[(x, y, w, h, score, cls_id), ...]`，坐标为原图系。

TFLite 运行时三级回退：

```
tflite_runtime.interpreter
  → ai_edge_litert.interpreter
  → tensorflow.lite.python.interpreter
```

### 6.6 手势识别 `drivers/gesture.py`

引擎选择是**运行时自动决策**，不是配置项：

```
CPU 支持 ARMv8 AES ?
  ├─ 是 → mediapipe 可导入 && models/hand_landmarker.task 存在
  │        ├─ 是 → MediaPipe HandLandmarker（VIDEO 模式，最多 2 手）
  │        └─ 否 → OpenCV 凸包
  └─ 否 → OpenCV 凸包（Pi 4B Cortex-A72 无 AES，MediaPipe 1.x 会 SIGILL）
```

| 引擎 | 算法 | 输出 |
|---|---|---|
| MediaPipe | 21 关键点 → 指尖/指节到腕距离 → 手指伸直；拇指单独用夹角 + 距离判定 | 框 + `FIST/ONE/PEACE/THREE/FOUR/OPEN PALM/THUMB UP/THUMB DOWN/OK` |
| OpenCV | YCrCb 肤色 → 最大轮廓 → 凸包缺陷数指缝 + 实心度 | 同上（单目标更粗） |

结果用最近 5 帧多数投票平滑；MediaPipe 运行异常会热切到 OpenCV。

### 6.7 语音识别 `drivers/asr.py`

| 项目 | 值 |
|---|---|
| 模式 | `whisper`（默认）/ `mock`（终端输入） |
| 模型 | `faster-whisper`，默认 `small`，CPU + `int8` |
| 采样率 | 优先 48000 Hz，`check_input_settings` 失败回退 16000 Hz |
| 设备选择 | `PETCAR_ASR_DEVICE` 序号或名字片段 → 自动找 `USB/UAC/Mic/Microphone` |
| VAD | 前 5 块（0.5 s）噪声基线，阈值 `min(0.08, max(0.005, mean×1.8))`；200 ms 起录；1200 ms 静音结束 |
| 前处理 | 峰值归一化 0.9；写临时 WAV 交给 Whisper 重采样 |
| 后处理 | `avg_logprob < -1.0` 丢弃；整句重复截半；纯数字 token 过滤 |
| 并发 | `_lock` 保证同一时刻只有一路录音；`paused` 供面板测试让路 |

### 6.8 语音合成 `drivers/tts.py`

| 模式 | 依赖 | 说明 |
|---|---|---|
| `edge`（默认） | `edge-tts` + 网络 | 童声 `zh-CN-XiaoyiNeural`，`pitch=+15Hz`；合成结果按 MD5 缓存；超时 `EDGE_TIMEOUT=10s` |
| `piper` | 本地 `piper` + ONNX 模型 | 常驻进程只加载一次模型；`--output_dir` 输出 wav；`PIPER_PITCH=1.15` 用 ffmpeg `asetrate+atempo` 变调 |
| `espeak` | `espeak` + `aplay` | 机械音兜底 |
| `pyttsx3` | `pyttsx3` | 可选离线引擎 |
| `mock` | 无 | 只打印文本 |

播放链路：`ffmpeg 解码 → aplay -D <device>`。设备自动探测顺序：`USB-Audio` → `bcm2835_headpho`；可用 `PETCAR_TTS_DEVICE` 显式指定。

**降级链**：`edge 失败/超时 → piper → espeak`。`is_speaking()` 供语音循环避让，防止自激回声。

## 七、感知与追踪子系统

### 7.1 PID 追踪（`core/pid_tracker.py`）

当前实现不是增量式 PID，而是**绝对角度视觉伺服**：

```
err_px = 目标中心 − 画面中心
err_s  = 0.5 × err_px + 0.5 × err_prev      # EMA 抗抖
gain   = kp × 25
step   = clamp(err_s / 10.0 × gain, ±10°)   # PX_PER_DEG=10, MAX_STEP=10
h_cur  = h_cur − step_x                     # 目标在右 → 水平角减小
v_cur  = v_cur − step_y                     # 目标在下 → 垂直角减小
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `kp` | 0.14 | 面板滑条 0~0.3，对应增益 0~7.5；1.0 增益=一步对准 |
| `ki` / `kd` | 0 / 0 | 当前控制律不参与，面板禁用 |
| 死区 | 12 px | 小于死区不动 |
| 丢目标 | 3 s | 超过则清空 EMA 与红框 |
| 频率 | ~16 Hz | `sleep(0.06)` |

目标类型：`face`（YuNet/Haar）、`color`（P1 HSV 参数）、`tennis`（荧光网球检测）。

### 7.2 积木感知缓存（`blocks/perception.py`）

- 3.3 Hz 低频采样，避免检测阻塞解释器；
- 只缓存布尔值 `{face, tennis, color, ts}`；
- 超过 1.2 s 标记 `stale`；
- `abort()` 只置位不等待，保证急停快速返回。

## 十三、已知约束与常见坑

| 现象 | 根因 | 处理 |
|---|---|---|
| 手势识别按钮点击后无结果/进程崩溃 | Pi 4B 无 AES，MediaPipe 1.x 预编译包 SIGILL | 代码自动降级 OpenCV 凸包；模型放 `models/hand_landmarker.task` |
| 语音识别完全失效 | USB 麦克风 48 kHz，Whisper 按 16 kHz 读数组导致语速慢 3 倍 | 必须落 WAV 文件再交给 faster-whisper 重采样 |
| 识别率低 | 麦克风音量过低 | 录音峰值归一化到 0.9 |
| 一直听不到人声 | VAD 阈值被扬声器回声抬高 | 阈值上限 0.08；TTS 期间不收音；播后等待 0.5 s |
| 板子有声音但喇叭不响 | 默认输出走 HDMI | `raspi-config` 切 3.5 mm，或设置 `PETCAR_TTS_DEVICE` |
| 电机四个轮子依次启动、间隔约 1 s | OLED 8 FPS 全帧重绘占满 I2C 总线 | `EmotionEngine` 渲染去重，画面不变不推 I2C |
| 小模型不调用工具 | 0.5B 的 tool_calls 不稳定 | `ChatAgent._LOCAL_RULES` 本地正则直连技能 |
| 对话很慢或超时 | 板端推理 + 生成长度过大 | 降 `num_predict`、换 0.5B、调大 `LLM_TIMEOUT` |
| 后台运行无日志 | Python 输出缓冲 | `PYTHONUNBUFFERED=1` |
| 面板配置部署后被清空 | 部署脚本会 `rm -rf petcar/` | 运行时配置存 `data/config_local.json` |
| 积木程序与手动控制打架 | 两条指令同时驱动底盘 | 积木运行中手动接口返回 409；急停统一入口 |

2. **感知调度统一**：把 `annotators` 的 DNN 缓存、PID 追踪、积木感知合并为一个“帧级感知调度器”，避免多线程重复推理。
3. **LLM 工具协议双轨**：保留文本 `<tool_call>` 兼容小模型，同时对支持原生 function calling 的模型走结构化 `tools`，减少解析歧义。
4. **可观测性**：把现有 `EventLog` 扩展为带耗时、线程名、错误码的结构化日志，便于现场排障。
5. **配置分层**：将硬件相关配置与产品人格配置拆成两个文件，避免教学实验误改产品参数。
