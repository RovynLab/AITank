## 三、设计问题（全局变量 / 阻塞 sleep / 状态不一致）

### 3.1 全局变量滥用：每个方法要写 12 行 global 声明

以 `exp3_1_2_MecanumChasis.py` 的 `forward()` 为例：

```python
def forward():
    global _spd1    # ←
    global _spd2    # ← 8 行 global
    global _spd3    # ← 只为了改 8 个变量
    global _spd4    # ←
    global _dir1    # ←
    global _dir2    # ←
    global _dir3    # ←
    global _dir4    # ←
    _spd2 = _normalSpeed
    _spd3 = _normalSpeed
    _spd1 = _normalSpeed
    _spd4 = _normalSpeed
    _dir2 = Adafruit_MotorHAT.FORWARD
    _dir3 = Adafruit_MotorHAT.FORWARD
    _dir1 = Adafruit_MotorHAT.FORWARD
    _dir4 = Adafruit_MotorHAT.FORWARD
    run()
```

**问题**：
- 2000 行代码里有 50+ 个 global 声明
- 函数没有参数、没有返回值、只改外部状态
- 单元测试几乎不可能写（测试前必须手动设置 8 个全局变量）
- Flask 下并发请求时，状态被多线程同时修改 → 竞态条件

**v1 类版本稍微好一点**，但 `run()` 里那个 sleep(1) 把它毁了。

### 3.2 `run()` 里硬编码的 `time.sleep()` —— 整个系统最大的性能杀手

这是**最致命的性能问题**，存在于所有版本的 MecanumChasis：

| 文件 | run() 里的 sleep | 后果 |
|------|------------------|------|
| `exp3_1_MecanumChasis.py` 类版 | `time.sleep(1)` | 每次运动指令延迟 1 秒 |
| `exp3_1_2_MecanumChasis.py` 全局版 | `time.sleep(0.5)` | 每次运动指令延迟 0.5 秒 |
| `Flask/MecanumChasis.py` | `time.sleep(0.5)` | Flask **同步阻塞**，整个 Web 服务卡死 0.5 秒 |

**影响链**：
1. Flask app.py 的 `/base/<motion>` 路由 → 调用 `Mecan.forward()` → 内部调用 `run()` → sleep(0.5)
2. 浏览器每次点"前进"按钮，要等 **0.5 秒** 才收到 HTTP 响应
3. Flask debug 模式的 reloader 重载时，电机初始化 + sleep 会让服务启动极慢
4. 如果有两个用户同时操作（虽然 Flask 默认单线程），sleep 会让整个服务停转

**正确做法**：`run()` 应该是"即写即生效"，不应该 sleep。sleep 应该放在**调用者**那里，或者完全去掉。

### 3.3 Flask app.py 的 `debug=True`

**文件**：[Flask/app.py](file:///e:/work/ev3/trunk/doc/code/aiTank/2.%20课程代码%20%20v4/综合实验/Flask/app.py#L107)

```python
app.run(host='0.0.0.0', debug=True, port=5000)
```

**问题**：
1. `debug=True` 会启用 Werkzeug 的 reloader，每次检测到文件变化就重新启动进程 → 电机驱动板反复初始化，PWM 频率反复被设置
2. debug 的交互式调试器允许任意 Python 代码执行 → 安全风险（虽然只是教学用）
3. reloader 会 fork 子进程 → I2C 总线可能被两个进程同时占用

**修复**：生产/教学环境应该关闭 debug：

```python
# ✅ 修复
app.run(host='0.0.0.0', debug=False, port=5000, threaded=True)
```

另外 Flask app.py 应该加 `atexit.register(turnOffMotors)` 和 try/finally 保护，目前没有。

### 3.4 Flask app.py 缺少初始化顺序保护

当前 `app.py` 结构：
```python
PTZ.PTZInit()     # ← 模块顶层，import 时就执行
app.run(...)
```

问题：如果 `PTZInit()` 失败（I2C 没插好），Flask 根本启动不了。应该用 `before_first_request` 或延迟初始化。

## 四、代码质量问题

### 4.1 树莓派 4B 上 TensorFlow 导入方式错误

**文件**：[TFLite_detection_video.py](file:///e:/work/ev3/trunk/doc/code/aiTank/2.%20课程代码%20%20v4/人工智能/TensorFlow/TFLite_detection_video.py#L10-L11)

```python
from tensorflow.lite.python.interpreter import Interpreter    # ❌ 需要完整 tensorflow
# from tflite_runtime.interpreter import Interpreter           # ✅ 树莓派上应该用这个
```

树莓派 4B 2GB 运行完整 TensorFlow 非常困难（需 aarch64 编译包）。`tflite_runtime` 才是官方推荐的轻量版，ARM 架构有预编译 wheel（v3 文件里已经自带了 `tflite_runtime-1.14.0-cp37-cp37m-linux_armv7l.whl`）。

### 4.2 所有 OpenCV 程序缺少 headless 适配

`ball_track_simple.py`、`face_recognition.py`、`finger.py`、`ball_track.py`、`TFLite_detection_video.py`、TrafficSign `main.py` 全部用了 `cv2.imshow()` 和 `cv2.waitKey()`。

当树莓派作为后台服务运行（无显示器）时，`cv2.imshow()` 直接崩溃：

```
error: (-215:Assertion failed) size.width>0 && size.height>0 in function 'imshow'
```

**修复**：加一个环境变量开关，开发模式显示窗口，服务模式跳过：

```python
import os
HEADLESS = os.environ.get('HEADLESS', '0') == '1'

if not HEADLESS:
    cv2.imshow("Frame", frame)
    key = cv2.waitKey(1) & 0xFF
    if key == ord("q"): break
```

### 4.3 `imutils` 缺失依赖

以下文件都 `import imutils`，但 `requirements.txt` 没包含：
- `ball_track_simple.py`
- `ball_track.py`
- TrafficSign `main.py`
- TrafficSign `classification.py`

### 4.4 所有 OpenCV 程序缺少摄像头失败处理

```python
camera = cv2.VideoCapture(0)
# 没有检查 camera.isOpened()
while True:
    (grabbed, frame) = camera.read()
    # 没有检查 grabbed
```

摄像头没插好时，程序会空跑一晚上。至少应该：

```python
camera = cv2.VideoCapture(0)
if not camera.isOpened():
    print("❌ 摄像头打开失败！")
    sys.exit(1)
```

### 4.5 `finger.py` 使用了 OpenCV 旧版 findContours 返回格式

**文件**：[finger.py](file:///e:/work/ev3/trunk/doc/code/aiTank/2.%20课程代码%20%20v4/人工智能/finger.py#L86)

### 4.6 TrafficSign `main.py` 中 HoughLinesP 参数写反了

### 4.7 `face_recognition.py` 中 `haarcascade_eye.xml` 检测会把镜头反光当眼睛

### 关键架构决策

1. **PCA9685 用 pip 安装**：`pip3 install adafruit-circuitpython-pca9685`，彻底消除 6 份复制
2. **单例驱动**：`drivers/__init__.py` 初始化一次，所有模块 import 同一个实例
3. **Class 封装**：`MecanumChasis` 和 `PTZControl` 都写成 Class，状态不再是全局变量
4. **config.py 集中管理**：I2C 地址 (0x60)、速度常量、电机编号顺序都在一个文件里
5. **demos/ 独立运行**：每个 demo 可以 `python3 demos/flask_control.py` 独立启动

### 统一的 MecanumChasis Class 示例

```python
# drivers/mecanum.py
class MecanumChasis:
    def __init__(self, motor_hathat=None, addr=0x60):
        from Adafruit_MotorHAT import Adafruit_MotorHAT
        self._mh = motor_hathat or Adafruit_MotorHAT(addr=addr)
        self._motors = [self._mh.getMotor(i) for i in range(1, 5)]
        self._normal_speed = 150
        self._setup_directions()   # 一次性配置电机方向映射

    def forward(self, speed=None):
        speed = speed or self._normal_speed
        self._set_all_forward(speed)

    def backward(self, speed=None):
        speed = speed or self._normal_speed
        self._set_all_backward(speed)

    def stop(self):
        self._motors[0].setSpeed(0)
        ...
        # ❌ 没有任何 sleep！立即生效

    def turn_off(self):
        for m in self._motors:
            m.run(Adafruit_MotorHAT.RELEASE)
```
