# PetCar 高中 12 节课课程设计方案

> 面向对象：高中学生（含零编程基础）
> 课程载体：AI-PetCar（树莓派 4B + 麦轮底盘 + 二自由度云台 + 摄像头 + OLED + 麦克风/音箱）
> 文档性质：课程设计分析 + 工作分解，不含具体教案正文
> 关联文档：[详细设计文档](../petcar/docs/详细设计文档.md)、[积木编程引擎设计文档](../petcar/docs/积木编程引擎设计文档.md)、[使用说明](../petcar/docs/使用说明.md)

---

## 0. 结论摘要

1. **petcar 可以支撑 12 节课，但不能按"源码导读"的方式上。** 项目自身定位已明确：petcar 是集成体验应用，代码量大、分层多，不是 Python 教学材料；教学应走"体验 → 积木 → 极简 Python 接口 → 最小原理例程"的路线。
2. **课程主线建议用"作品驱动 + 三层递进"**：先用中控面板和积木建立直观体验（低门槛），再用 `EmojiRobot` 过渡到 Python（可迁移），最后用最小例程讲原理（有深度）。
3. **12 节课的骨架是"感知—决策—执行"闭环**，每节课都产出一个可见、可演示的小成果，避免变成硬件参数背诵课。
4. **最大的工作量不在写教案，而在补齐教学资产**：12 个与课程一一对应的独立例程、稳定的教学 API、积木库最小扩展、课堂安全与分组机制、离线模型环境。
5. **现有 `labs/lab01`–`lab12` 不建议直接作为主线。** 它们偏底层（LED、PWM、舵机、运动学），与"AI 宠物车"的课程叙事不匹配，应降级为原理拓展包或选修内容。

## 1. 现状盘点

### 1.1 petcar 已经具备的能力

| 能力域 | 具体能力 | 对应模块 |
|---|---|---|
| 底盘运动 | 前进/后退/左移/右移/左转/右转/原地旋转、调速 | `drivers/mecanum.py` |
| 云台 | 上下左右转动、回正，二自由度舵机 | `drivers/ptz.py` |
| 表情 | OLED 128×64，12 种表情，眨眼/说话/思考等动画 | `drivers/oled.py`、`core/emotion_engine.py` |
| 情绪 | valence-arousal 二维情绪模型，情绪影响表情与回复 | `core/mood_engine.py` |
| 语音 | ASR（whisper）、TTS（edge-tts / Piper 离线）、唤醒词、VAD | `drivers/asr.py`、`drivers/tts.py`、`core/voice_io.py` |
| 视觉 | 摄像头、颜色识别、人脸检测、人脸追踪、手势识别、目标检测 | `drivers/camera.py`、`drivers/detectors.py`、`drivers/gesture.py` |
| 闭环控制 | PID 人脸/颜色追踪，可实时调参 | `core/pid_tracker.py` |
| 大模型 | Ollama 本地模型 / 豆包，人格设定、工具调用、情绪标签 | `core/chat_agent.py`、`core/llm_backends.py` |
| 技能系统 | 移动、云台、拍照、天气、闹钟、表情、人脸追踪等可调用技能 | `core/skill_manager.py`、`skills/*` |
| 积木编程 | Blockly 图形化编程，11 类积木，车端解释执行，运行高亮/急停 | `blocks/*`、`api/static/blocks` |
| 中控面板 | 视频流、方向控制、云台、颜色识别、PID 追踪、技能按钮、设置 | `api/flask_app.py`、`api/static/dashboard.html` |
| 学生接口 | `EmojiRobot` 极简 Python API（表情/动作/云台/说话/拍照/检测/对话） | `student_api/emoji_robot.py` |
| 安全机制 | 急停、运动租约、看门狗、程序超时、单实例运行 | `blocks/runtime.py`、`api/block_api.py` |

### 1.2 petcar 不适合直接当教材的部分

- **分层太深**：驱动层、核心层、应用层共几十个模块，学生读源码会淹没在工程细节里。
- **依赖真实硬件**：Windows 开发机无法初始化电机 HAT，纯逻辑测试可以，完整运行必须在树莓派上。
- **大模型输出不确定**：0.5B 小模型响应快但会答非所问，需要课程设计上用"人格卡 + 规则兜底"控制预期。
- **积木能力仍有缺口**：当前只有顺序、循环、条件（"如果看到 X"）、等待，缺少变量、条件分支、传感器读数、循环直到等，支撑 12 节课需要小幅扩展。

### 1.3 现有 labs 与课程的错位

| 现有实验 | 内容 | 与课程的关系 |
|---|---|---|
| lab01–lab04 | LED、电机方向、PWM、舵机 | 硬件原理拓展，不进主线 |
| lab05–lab07 | 轮测试、麦轮类版/全局版 | 可支撑第 6 课"底盘运动学"的拓展 |
| lab08 | 逆运动学公式 | 第 6 课原理推导的良好素材 |
| lab09 | pygame 手柄控制 | 选修/社团拓展 |
| lab10–lab11 | 云台控制、舵机测试 | 可支撑第 7 课"云台与组合动作" |
| lab12 | OpenCV 凸包手势识别 | 第 5 课/第 11 课的挑战拓展 |

结论：**保留 labs 作为"原理拓展包"，主线另建 `lessons/lesson01`–`lesson12` 独立例程。**

## 2. 课程定位与设计原则

### 2.1 课程定位

不是"机器人硬件课"，也不是"Python 语法课"，而是**面向高中生的 AI 素养与工程实践入门课**：

- 让学生理解"感知—决策—执行"这一智能系统的基本结构；
- 让学生能用图形化和 Python 两种方式表达自己的设计；
- 让学生对视觉、语音、大模型的能力边界有真实体感，而不是停留在概念。

### 2.2 六条设计原则

1. **作品驱动**：每节课必须有一个 5 分钟内可演示的产出，不以"讲完知识点"为结束。
2. **低门槛高天花板**：基础任务人人能完成，挑战任务给学有余力的学生（同一节课两档任务单）。
3. **体验先于原理**：先让车"动起来、说起来、看起来"，再解释为什么。
4. **不读产品源码**：课堂只读 `lessons/` 下的最小例程和 `EmojiRobot` 接口，不要求读 `petcar/` 内部实现。
5. **安全优先**：所有涉及运动的课必须先讲急停、限速、场地边界；程序必须有兜底停止。
6. **一课一闭环**：每节课都回到"感知—决策—执行"框架上定位，帮助学生建立整体认知。

### 2.3 教学条件假设（需开课前确认）

| 项目 | 建议值 | 说明 |
|---|---|---|
| 课次 | 12 课次 × 90 分钟（2 课时） | 可按 45 分钟拆为"核心课 + 拓展课" |
| 班额 | 40 人以内 | 4–5 人一组 |
| 车辆 | 理想 1 组 1 车；最低 1 班 4 车 | 不足时用轮换 + 视频演示 + mock 模式 |
| 场地 | 平整地面 ≥ 4m × 4m，带围挡 | 避免跌落、缠线、撞人 |
| 网络 | 局域网，最好有外网 | 无外网时切换离线模型（见第 7 节） |
| 学生基础 | 零 Python 亦可 | 第 8–10 课承担编程入门 |
| 教师 | 1 主讲 + 1 助教 | 助教负责设备与安全 |

## 4. 每节课详细设计

> 每节课统一结构：核心问题 → 知识目标 → 对应模块 → 课堂流程 → 学生产出 → 评价点。

### 第 1 课 认识我的 AI 宠物车

- **核心问题**：一台会说话、会看、会动的车，由哪些部分组成？
- **知识目标**：能说出"感知—决策—执行"三层；认识摄像头、OLED、云台、麦轮、麦克风/音箱；掌握急停与场地规则。
- **对应模块**：`main.py`、`api/flask_app.py`、`api/static/dashboard.html`、`core/chat_agent.py`、`drivers/mecanum.py`、`drivers/ptz.py`
- **课堂流程**：开箱与安全讲解（20 min）→ 中控面板巡览（15 min）→ 与车对话、看表情、遥控走一圈（35 min）→ 小组画系统组成图（20 min）
- **学生产出**：小组《系统组成图》+ 安全承诺书
- **评价点**：能指出三层的输入与输出；能正确使用急停

### 第 2 课 表情与情绪：让车"有表情"

- **核心问题**：128×64 的点阵如何画出情绪？情绪怎样变成表情？
- **知识目标**：像素与坐标、基本图元（圆、弧、线）、表情状态机、valence-arousal 情绪模型。
- **对应模块**：`drivers/oled.py`、`core/emotion_engine.py`、`core/mood_engine.py`、`blocks/catalog.py`（12 种表情）
- **课堂流程**：观察 12 种表情（10 min）→ 讲解点阵绘制与情绪映射（20 min）→ 积木拼"开心→说话→大笑"（30 min）→ 挑战：设计一个新表情（30 min）
- **学生产出**：表情设计稿（眼睛/嘴/装饰）+ 一段表情序列程序
- **评价点**：表情与情绪语义匹配；序列时序合理

### 第 3 课 声音：让车"会听会说"

- **核心问题**：声音怎样变成文字，文字又怎样变成声音？
- **知识目标**：采样率、VAD 静音检测、ASR 识别、TTS 合成、唤醒词、噪声对识别率的影响。
- **对应模块**：`drivers/asr.py`、`drivers/tts.py`、`core/voice_io.py`、`petcar/config.py`
- **课堂流程**：TTS 试听不同音色/音调（15 min）→ 讲解语音链路（20 min）→ ASR 对比实验：安静/嘈杂/远距离（30 min）→ 设计 3 句自我介绍并让车说出（25 min）
- **学生产出**：声音实验记录表（识别率 vs 距离/噪声）+ 自我介绍语音程序
- **评价点**：能画出 ASR→LLM→TTS 链路；能解释识别失败的两类原因

### 第 4 课 视觉入门：颜色识别与 HSV

- **核心问题**：摄像头看到的是数字，怎样从数字里找到"红色"？
- **知识目标**：像素、RGB 与 HSV、色相/饱和度/明度、阈值分割、掩膜、目标中心。
- **对应模块**：`drivers/camera.py`、`drivers/detectors.py`、`api/flask_app.py`（`/api/color_cfg`）、`core/pid_tracker.py`
- **课堂流程**：面板 P1 调 HSV 找色（25 min）→ 讲解颜色空间与阈值（20 min）→ 用色卡测试 7 种预设色（20 min）→ 积木"看到颜色→前进"，挑战"追色块"（25 min）
- **学生产出**：HSV 参数记录表 + 追色程序
- **评价点**：能解释为什么 HSV 比 RGB 更适合找颜色；能调出稳定阈值

### 第 5 课 人脸检测与自动追踪

- **核心问题**：机器如何"盯住"一个人？
- **知识目标**：检测与追踪的区别、边界框、中心偏差、比例控制（Kp）、闭环控制、抖动与超调。
- **对应模块**：`drivers/camera.py`（`detect_faces`）、`core/pid_tracker.py`、`drivers/ptz.py`、`api/flask_app.py`（`/api/track`）
- **课堂流程**：面板 P2 启动人脸追踪（15 min）→ 讲解"测量—比较—执行"（20 min）→ Kp 调参实验（30 min）→ 遮挡/快速移动/多人场景测试（25 min）
- **学生产出**：PID 调参记录（Kp 值 vs 追踪表现）+ 结论
- **评价点**：能解释偏差如何驱动云台；能说出 Kp 过大/过小的现象

### 第 6 课 麦轮底盘与运动学

- **核心问题**：四个轮子怎样让车横着走、原地转？
- **知识目标**：麦轮结构、速度分解、逆运动学、PWM 与占空比、速度与时间的关系。
- **对应模块**：`drivers/mecanum.py`、`petcar/config.py`、`labs/lab06`–`lab08`
- **课堂流程**：面板方向控制观察轮子转向（15 min）→ 讲解麦轮原理（20 min）→ 纸上推导 vx/vy/ω → 四轮速度，对照 `lab08`（25 min）→ 挑战：走正方形、绕桩、画 8 字（30 min）
- **学生产出**：运动学推导单 + 路径挑战视频
- **评价点**：能解释横移时四个轮子的转向；能根据速度与时间估算位移

### 第 7 课 云台与组合动作

- **核心问题**：如何让车做出"点头、张望、打招呼"这类拟人动作？
- **知识目标**：舵机角度与方向、二自由度云台、动作序列、时序编排、动作与表情/语音的协同。
- **对应模块**：`drivers/ptz.py`、`skills/emote.py`、`skills/express.py`、`student_api/emoji_robot.py`（`nod`/`twist`/`look_up`）、`labs/lab10`–`lab11`
- **课堂流程**：云台角度范围实验（20 min）→ 讲解舵机与角度映射（20 min）→ 分析内置组合动作（20 min）→ 设计 5 秒"打招呼"动作（30 min）
- **学生产出**：一个 5 秒动作编排（云台 + 表情 + 语音）
- **评价点**：动作流畅、无卡顿；时序与语义匹配

### 第 8 课 积木编程入门

- **核心问题**：不会写代码，怎样让车按我的想法行动？
- **知识目标**：事件、顺序、循环、条件、参数；程序执行顺序；运行与停止。
- **对应模块**：`blocks/catalog.py`、`blocks/compiler.py`、`blocks/runtime.py`、`api/block_api.py`、`/blocks` 页面
- **课堂流程**：认识积木页面（15 min）→ 第一个程序"前进 1 秒→开心→说你好"（25 min）→ 循环画正方形（25 min）→ 条件"看到人脸→打招呼"（25 min）
- **学生产出**：3 个递进积木程序（顺序 / 循环 / 条件）
- **评价点**：程序可运行；能说清每块积木的作用

### 第 9 课 积木综合：感知-决策-执行

- **核心问题**：怎样让车自己完成一件"有用的事"？
- **知识目标**：感知条件、状态与轮询、超时与急停、运动租约、调试方法（当前积木高亮、控制台、日志）。
- **对应模块**：`blocks/runtime.py`（租约/看门狗）、`blocks/perception.py`、`api/block_api.py`（SSE、`/api/blocks/estop`）
- **课堂流程**：发布任务卡（10 min）→ 小组设计（15 min）→ 实现与调试（40 min）→ 小组互测与记录（25 min）
- **任务卡示例**：迎宾员（看到人脸→靠近→打招呼）、巡逻员（循环巡逻→看到颜色→报警）、找球手（找网球→靠近→停下）
- **学生产出**：可演示的积木作品 + 测试记录（正常/遮挡/超时三种情况）
- **评价点**：功能完成度、鲁棒性、是否使用兜底停止

### 第 10 课 从积木到 Python

- **核心问题**：积木背后的代码长什么样？
- **知识目标**：函数、对象与方法、`import`、变量、循环、条件、时间控制、常见报错（拼写/缩进/参数）。
- **对应模块**：`student_api/emoji_robot.py`、`student_api/face.py`、积木页的 Python 视图/导出
- **课堂流程**：积木一键切 Python 视图对照阅读（20 min）→ 讲解 `EmojiRobot` 常用方法（20 min）→ 用 Python 重写第 8/9 课作品（35 min）→ 改参数实验与报错排查（15 min）
- **学生产出**：一个 `.py` 程序 + 积木/Python 对照表
- **评价点**：能独立改参数；能根据报错定位问题

### 第 11 课 大模型与技能系统：给车一个"人格"

- **核心问题**：大模型怎样从"聊天"变成"做事"？
- **知识目标**：token 与上下文、提示词、温度、工具调用（function calling）、技能注册、幻觉与能力边界。
- **对应模块**：`core/chat_agent.py`、`core/llm_backends.py`、`core/skill_manager.py`、`skills/*`、`petcar/config.py`（`PET_NAME`/`PET_PERSONALITY`）
- **课堂流程**：修改人格并对比效果（20 min）→ 讲解提示词与工具调用链路（25 min）→ 观察 LLM 调用 move/weather 技能（20 min）→ 设计并注册一个自定义技能（25 min）
- **学生产出**：人格卡 + 提示词对比实验 + 1 个自定义技能
- **评价点**：能解释"提示词→工具调用→执行"链路；能识别并举例说明幻觉

### 第 12 课 综合项目与展评

- **核心问题**：如何做一个"能解决问题"的 AI 宠物车作品？
- **知识目标**：需求分析、方案设计、迭代测试、展示表达、团队协作。
- **对应模块**：全部（底盘、云台、表情、语音、视觉、积木/Python、LLM、技能）
- **课堂流程**：选题与方案评审（20 min）→ 分组实现（40 min）→ 3 分钟路演 + 答辩（20 min）→ 互评与总结（10 min）
- **选题方向**：校园导览车、独居老人陪伴提醒、教室安防巡逻、表情互动游戏、找物小车
- **学生产出**：项目文档 + 演示 + 代码/积木文件
- **评价量规**：功能完成度 30%、技术运用 25%、创意 20%、表达 15%、协作 10%

## 6. 要做的事：工作分解

按六条线组织，每条线给出交付物清单和验收标准。

### 6.1 课程内容线

| 交付物 | 数量 | 说明 |
|---|---|---|

| 教案 | 12 份 | 每课含时间分配、提问设计、板书/PPT 要点、易错点 |
| 学生任务单 | 12 份 | 基础任务 + 挑战任务 + 记录表 + 自评 |

**关键动作**：先写第 1、8、12 课的完整样章（分别代表体验课、技能课、项目课），教研组评审通过后再批量展开其余 9 课，避免 12 课一起返工。

### 6.2 教学代码线

> 代码必须从 petcar 中拆出来单独成立，不能让学生读集成框架。详细拆解方案见 [PetCar-课程代码拆解方案](./PetCar-课程代码拆解方案.md)：采用"`lessons/lib/` 最小驱动库（约 1100 行）+ 每课 40–100 行脚本"的结构。

| 交付物 | 数量 | 说明 |
|---|---|---|
| `lessons/lib/` 最小驱动库 | 9 个模块 | 从 petcar 驱动层抽取瘦身，统一 mock，不 import petcar |
| `lessons/lesson01`–`lesson12` 独立脚本 | 12 套 | 每课一个 40–100 行主脚本，可单独运行、10 秒内可见现象 |
| 教学 API 稳定层 | 1 套 | 基于 `EmojiRobot` 抽出教学子集，固定签名并配文档 |
| 示例作品源码 | ≥ 12 个 | 每课一个"标准答案"版本，供教师演示和学困生参考 |
| 积木库扩展 | 1 批 | 变量、条件分支、传感器读数、循环直到（按第 8–9 课需要，保持最小集） |
| 积木→Python 视图对齐 | 1 项 | 导出的 Python 必须能在 `EmojiRobot` 上直接跑通 |
| 教学模式开关 | 1 项 | mock（无硬件）、离线、限速、演示脚本 |

**原则**：遵守项目既定的"两套代码、两种用途"——`petcar/` 保持工程完整，不为教学加简化分支；教学例程单独放在 `lessons/`，允许删繁就简。

## 7. 关键风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 车少人多 | 学生动手时间不足 | 4–5 人一组轮换角色（操作/记录/观察/汇报）；配 mock 模式做无车练习；关键实验录视频 |
| 断网或模型不可用 | LLM 对话、云端 TTS 失效 | 全离线包（Ollama + Piper + 本地 whisper）；课前自检；准备"无 LLM 版"脚本 |
| 小模型答非所问 | 学生对 AI 失望 | 人格提示词约束 + 规则兜底；把"幻觉"设计成第 11 课的教学内容而非故障 |
| 硬件损坏 | 课程中断 | 教学限速、围挡、急停常驻、备件（舵机/轮子/电源/摄像头） |
| 学生基础差异大 | 进度两极分化 | 每课双档任务单；第 8–10 课设"编程补丁课"；高年级学生做助教 |
| 课时紧张 | 原理讲不透 | 每课只保留一个核心原理，其余放拓展包；45 分钟版砍掉挑战任务 |
| 现有 labs 不匹配 | 教师误用旧材料 | 明确 labs 为拓展包；主线统一用 `lessons/`；教师培训中讲清两者区别 |
| 代码更新导致教案失效 | 教学习题跑不通 | 教学 API 固定签名；每轮课前跑一遍 12 个 lesson 的冒烟测试 |

## 8. 实施顺序建议

按"先通后全、先难后易"的顺序推进，不按课次顺序：

1. **定框架**：确认课时、班额、车辆数、网络条件、学生基础（本文第 2.3 节）。
2. **做样板**：完成第 1 课（体验）、第 8 课（积木）、第 12 课（项目）三份完整样章 + 对应 lesson 例程。
3. **试讲验证**：用真实班级试讲三节样课，记录设备、节奏、难度问题。
4. **补平台**：根据试讲暴露的问题，优先做安全加固、离线包、一键自检、多组作品管理。
5. **批量生产**：按单元展开其余 9 课教案、任务单、课件、例程。
6. **补拓展**：把 labs 中的运动学、云台、手势内容整理为选修拓展包。
7. **教师培训与全量试运行**：完成培训后整班开课，收集数据。
8. **迭代定版**：根据前测/后测、作品量规、课堂观察表修订，形成 v1.0 课程包。

## 9. 课程交付验收标准

一份"可开课"的课程包应同时满足：

- [ ] 12 份教案、12 份任务单、12 套课件齐全，且每课有明确产出与评价点。
- [ ] 12 个 `lessons/` 例程在目标板卡上全部可运行，且有 mock 模式。
- [ ] 积木→Python 导出的示例程序能在 `EmojiRobot` 上直接运行。
- [ ] 离线环境下，第 3、11 课的核心活动可完整完成。
- [ ] 急停、限速、超时、看门狗在课堂默认配置下全部生效。
- [ ] 一键自检能覆盖 I2C、摄像头、音频、模型、端口五项。
- [ ] 至少 4 辆车可同班同时上课，作品互不干扰。
- [ ] 教师手册覆盖 Top 10 故障及处理步骤。
- [ ] 完成至少一轮真实班级试讲并形成迭代记录。

## 10. 一句话总结

petcar 的 12 节课不应做成"源码拆解课"，而应做成**以车为载体的 AI 素养课**：用面板和积木降低门槛，用 `EmojiRobot` 衔接 Python，用最小例程讲清原理，用综合项目收口。真正的工作量在**教学例程、课堂安全、离线环境和分层任务单**这四件事上，教案本身反而是最后一步。
