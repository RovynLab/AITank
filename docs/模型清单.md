# AI Tank / AI-PetCar 模型清单

> 适用范围：`e:\work\AITank` 仓库中的 `petcar/` 集成应用（整车运行时实际会加载的模型）。
> 文档定位：回答“**这个小车里到底用了哪几个模型、各管什么、放在哪、什么时候加载、占多少资源**”。
> 逐条部署步骤见 [安装部署指南](./安装部署指南.md)；线程与加载时机排障见 [进程与启动控制](./进程与启动控制.md)。

---

## 一、概览

整车**没有多模态大模型**，AI 能力由四类互相独立的模型拼起来：

```
麦克风 ──► faster-whisper ──► 文本 ──► 本地规则 / Qwen2.5 / Doubao ──► 回复文本
                                                                  │
摄像头 ──► OpenCV 视觉模型（TFLite SSD / NanoDet / YuNet / MediaPipe）│
                                                                  ▼
                                                              edge-tts / Piper ──► 扬声器
```

- **大模型只处理文本**，不接触图像；物体、人脸、手势全部由 OpenCV/MediaPipe 系列模型完成。
- 默认配置**以本地为主**：LLM 用 Ollama 的 `qwen2.5:0.5b`，ASR 用 faster-whisper，视觉用 TFLite；只有 TTS 默认走云端 edge-tts。
- 每一层都有**降级路径**：Ollama 连不上 → Mock 规则引擎；TFLite 模型缺失 → NanoDet；MediaPipe 不可用 → OpenCV 凸包；edge-tts 超时 → Piper。

## 三、对话模型（LLM）

### 3.1 Qwen2.5-0.5B（默认）

| 项目 | 值 |
|---|---|
| Ollama 名称 | `qwen2.5:0.5b` |
| 参数规模 | 约 0.49B，纯文本模型（无视觉编码器） |
| 配置位置 | `petcar/config.py` 的 `OLLAMA_MODEL`，可用 `PETCAR_OLLAMA_MODEL` 覆盖 |
| 调用方式 | `POST {OLLAMA_HOST}/api/chat`，`stream=false` |
| 生成参数 | `temperature=0.7`、`num_predict=150`（面板可调）、超时 180 s |
| 实测速度 | Pi 4B 上约 **7 token/s** |
| 上下文 | 请求未显式设置 `num_ctx`，使用 Ollama 默认上下文窗口 |

**能力**：中文短对话、人格化应答、简单意图理解。

**已知短板**：`tool_calls` 输出不稳定，容易跑偏。因此 `ChatAgent` 在调用模型前先做**本地规则直连**
（`petcar/core/chat_agent.py` 的 `_LOCAL_RULES`）：前进/后退/左转/右转/抬头/低头/拍照/跳舞等指令直接命中技能，
不经过模型；未命中才进入 LLM + tool calling 循环。

### 3.2 Qwen2.5-1.5B（可选）

| 项目 | 值 |
|---|---|
| Ollama 名称 | `qwen2.5:1.5b` |
| 内存 | 约 1.5 GB |
| 特点 | 语义理解、工具调用明显好于 0.5B，但更慢 |
| 使用方式 | 面板切换模型，或 `PETCAR_OLLAMA_MODEL=qwen2.5:1.5b` |

在 2 GB 的 Pi 4B 上，1.5B 与 Whisper、视觉检测同时运行容易触发 swap，需按需开启。

### 3.3 Doubao（云端备选）

| 项目 | 值 |
|---|---|
| 模型 | `doubao-pro-32k`（`PETCAR_DOUBAO_MODEL` 可改） |
| 服务 | 火山引擎 Ark，OpenAI 兼容 `/api/v3/chat/completions` |
| 鉴权 | `DOUBAO_API_KEY`，只保存在板端 `data/config_local.json` |
| 适用 | 需要更强理解力与稳定工具调用时 |

### 3.4 Mock 规则引擎（不是模型）

`petcar/core/llm_backends.py` 的 `MockBackend` 是一组正则规则，用于：

- Ollama 探测失败（`/api/tags` 3 s 超时）；
- 没配 Doubao Key；
- 课堂演示只要指令控制、不想加载模型。

它能覆盖打招呼、表情、天气、运动、云台、拍照、闹钟等固定句式，超出范围的输入只做固定兜底回复。

## 四、语音识别（ASR）

| 项目 | 值 |
|---|---|
| 引擎 | `faster-whisper`（CTranslate2 后端） |
| 模型规格 | `tiny` / `base` / `small`，默认配置为 `small` |
| 配置位置 | `petcar/config.py` 的 `WHISPER_MODEL`，可用 `PETCAR_WHISPER_MODEL` 覆盖 |
| 推理设备 | CPU，`compute_type="int8"` |
| 语言 | 固定中文（`language="zh"`），`beam_size=1`，`vad_filter=True` |

各规格取舍：

| 规格 | 相对速度 | 识别质量 | 适用 |
|---|---|---|---|
| `tiny` | 最快 | 一般，噪声下易出数字串 | 板端默认保存值，内存紧张时 |
| `base` | 中 | 可用 | `./petcar/start.sh --voice` 使用 |
| `small` | 最慢 | 最好 | `config.py` 默认值，`--full` 模式 |

**运行时约束**（代码已处理）：

- USB 麦克风常见 48 kHz，而 Whisper 需要 16 kHz，直接把数组喂进去会被误读，所以先落 WAV 再交给 faster-whisper 按文件头重采样；
- 录音峰值归一化到 0.9，提升低音量识别率；
- `avg_logprob < -1.0` 的整段结果直接丢弃，避免噪声“瞎编”；
- 整句重复时截半，纯数字 token 过滤。

## 五、语音合成（TTS）

| 模式 | 模型/服务 | 联网 | 特点 |
|---|---|---|---|
| `edge`（默认） | edge-tts `zh-CN-XiaoyiNeural`，音调 `+15Hz` | 需要 | 童声自然，10 s 超时后自动降级 Piper |
| `piper` | `zh_CN-huayan-medium.onnx`（VITS） | 不需要 | 本地离线童声，音调倍率 1.15；首次说话拉起常驻子进程 |
| `espeak` | 系统 espeak | 不需要 | 机械音，能出声的兜底 |
| `pyttsx3` | 系统 TTS | 不需要 | 备选 |
| `mock` | 无 | 不需要 | 只打印文本，调试用 |

Piper 模型路径由 `PETCAR_PIPER_MODEL` 指定，默认 `/home/pi/piper/zh_CN-huayan-medium.onnx`；
可执行文件由 `PETCAR_PIPER_BIN` 指定。

> 严格说 TTS 不是“大模型推理”的重头，但在本项目里 Piper 是唯一常驻的本地神经网络进程，空闲约 130 MB 内存。

## 六、视觉模型

视觉检测统一输出 `(x, y, w, h, score, cls_id)`，由视频流标注层画框；面板上的“人 / 宠物 / 水杯 / 网球 / 屏幕”只是对 COCO 类别做过滤。

### 6.1 通用物体检测：TFLite SSD MobileNetV2（主）

| 项目 | 值 |
|---|---|
| 文件 | `~/.opencv/models/detect.tflite` + `labelmap.txt` |
| 输入 | 300 × 300 RGB |
| 输出 | 归一化 boxes / classes / scores |
| 类别 | COCO 80 类（人、猫、狗、杯子、瓶子、球、电视等） |
| 阈值 | `conf=0.5` |
| 速度 | Pi 4B 上约 100~200 ms/帧 |
| 代码 | `petcar/drivers/detectors.py` 的 `TFLiteSSD` |

为控制 CPU，视频流里**每 2 帧才真跑一次推理**，其余帧复用缓存结果。

面板映射关系：

| 面板项 | COCO 类别 ID |
|---|---|
| 人 | 0 |
| 宠物 | 14（鸟）、15（猫）、16（狗） |
| 水杯 | 39（瓶子）、41（杯子） |
| 网球 | 32（sports ball） |
| 屏幕 | 62（tv） |

### 6.2 通用物体检测备选：NanoDet-Plus-m

| 项目 | 值 |
|---|---|
| 文件 | `~/.opencv/models/object_detection_nanodet_2022nov.onnx` |
| 输入 | 320 × 320 |
| 类别 | COCO 80 类 |
| 阈值 | `conf=0.35`、NMS `0.6` |
| 速度 | Pi 4B 约 1~2 fps（已限频） |
| 触发 | `get_detector()` 在 TFLite 加载失败时自动回退 |

### 6.3 人脸检测：YuNet

| 项目 | 值 |
|---|---|
| 文件 | `~/.opencv/models/face_detection_yunet_2023mar.onnx` |
| 输入 | 320 × 320（运行时按帧尺寸 `setInputSize`） |
| 阈值 | `score=0.9`、`nms=0.3` |
| 用途 | 人脸检测、人脸追踪（PID 视觉伺服）、积木感知快照 |
| 代码 | `petcar/drivers/camera.py` 的 `detect_faces()` |

YuNet 缺失时回退 OpenCV 自带 `haarcascade_frontalface_default.xml`（传统 Haar 级联，无需下载模型）。

### 6.4 手势识别：MediaPipe HandLandmarker

| 项目 | 值 |
|---|---|
| 文件 | `models/hand_landmarker.task`（可用 `PETCAR_HAND_MODEL` 指定） |
| 输入 | VIDEO 模式，最多 2 只手 |
| 输出 | 21 个手部关键点 → 手势标签 |
| 支持手势 | 拳头、1、剪刀手、3、4、张开手掌、点赞、踩、OK |
| 启用条件 | CPU 支持 ARMv8 AES + mediapipe 可导入 + 模型存在 |

**重要的硬件限制**：树莓派 4B（Cortex-A72）没有 AES 指令，MediaPipe 1.x 预编译包初始化会 SIGILL，
因此在 4B 上会自动降级为 **OpenCV 凸包缺陷法**（肤色分割 → 最大轮廓 → 凸包缺陷数指缝），
该兜底方案**不使用任何模型**；树莓派 5 才会真正跑 MediaPipe。

### 6.5 无模型的传统视觉

| 功能 | 算法 | 代码 |
|---|---|---|
| 颜色识别 | HSV 阈值 + 轮廓 | `detect_color()` |
| 网球识别 | 颜色 + 形状/面积 | `detect_tennis_ball()` |
| 运动检测 | 帧差 + 阈值 | `detect_motion()` |
| 手势兜底 | 肤色 + 凸包缺陷 | `gesture.py` |

## 七、模型文件存放位置

| 模型 | 默认路径 | 覆盖方式 |
|---|---|---|
| Ollama LLM | Ollama 模型库（`ollama list` 可见） | `PETCAR_OLLAMA_MODEL` / 面板 |
| Whisper | Hugging Face 缓存（`~/.cache/huggingface`） | `PETCAR_WHISPER_MODEL` |
| Piper | `/home/pi/piper/zh_CN-huayan-medium.onnx` | `PETCAR_PIPER_MODEL` |
| TFLite SSD | `~/.opencv/models/detect.tflite`、`labelmap.txt` | `PETCAR_MODEL_DIR` |
| NanoDet | `~/.opencv/models/object_detection_nanodet_2022nov.onnx` | `PETCAR_MODEL_DIR` |
| YuNet | `~/.opencv/models/face_detection_yunet_2023mar.onnx` | 路径写死，缺失时用 Haar |
| MediaPipe 手部 | `models/hand_landmarker.task` 或 `~/.opencv/models/` | `PETCAR_HAND_MODEL` |

`PETCAR_MODEL_DIR` 默认 `~/.opencv/models`，TFLite 与 NanoDet 都从这里找。

获取方式：

```bash
# LLM
ollama pull qwen2.5:0.5b
ollama pull qwen2.5:1.5b

# NanoDet / YuNet：从 opencv_zoo 下载到 ~/.opencv/models
# MediaPipe：从 mediapipe-models 下载 hand_landmarker.task 到 models/
# Piper：下载 zh_CN-huayan-medium.onnx 与 piper 可执行文件
```

> 仓库里**不存放**这些模型文件，`models/` 目录按需创建。换机器部署时最容易被遗漏的就是这一步。

## 八、加载时机与资源占用

| 模型 | 谁加载 | 何时进内存 | 何时释放 | 典型占用 |
|---|---|---|---|---|
| Ollama `qwen2.5:0.5b` | Ollama 服务（systemd 常驻） | 第一次 `/api/chat` | 闲置约 5 分钟后卸载 | runner 约 597 MB |
| faster-whisper | petcar 进程 | `ASRDriver()` 构造时 | petcar 退出 | 计入 petcar 进程，识别时占 1 核数秒 |
| Piper | petcar 子进程 | 第一次 `speak()`（启动欢迎语） | petcar 退出 | 约 130 MB，空闲 0% CPU |
| TFLite / NanoDet | Flask 检测线程 | 首次点开对应识别项时 | 进程退出 | 单帧 100~200 ms，每 2 帧一次 |
| YuNet / Haar | `CameraDriver` | 摄像头驱动初始化 | 进程退出 | 很轻 |
| MediaPipe | `GestureDetector` | 首次手势识别 | 进程退出 | Pi 5 可用，Pi 4B 走兜底 |

内存参考（Pi 4B 2 GB，实测）：Ollama runner 597 MB + petcar 341 MB + Piper 130 MB。
**换 1.5B 模型后 Ollama 部分明显增大，2 GB 板容易触发 swap。**
关掉不用的识别项、把 Whisper 降到 `tiny`，是最有效的两条省内存手段。

## 九、各模型如何协作

以“你好小强，前面有人吗？”为例：

```
ASR        faster-whisper            → "前面有人吗"
意图       _LOCAL_RULES 正则命中      → 直连 detect_face 技能（不经过 LLM）
视觉       YuNet / Haar              → 人脸框数量
回复       技能固定话术 / LLM 润色    → "看到啦，前面有 1 个人～"
TTS        edge-tts 或 Piper         → 播放
```

再看“给我讲个笑话”：

```
ASR → whisper → 文本
    → 未命中本地规则
    → Qwen2.5-0.5B（Ollama）生成 <reply>…</reply><emotion>happy</emotion>
    → 正则提取正文与表情
    → OLED 切表情 + TTS 播报
```

关键点：**感知结果不进入大模型的图像通道，而是以文本形式（类别、数量、位置）传给技能层或提示词**。
所以 0.5B 也能“知道”画面里有没有人，但它自己并没有看图。

## 十、能力边界与选型建议

| 需求 | 建议 |
|---|---|
| 只想稳定控制小车动作 | 用固定指令（本地规则），不依赖 LLM |
| 想要自然闲聊 | `qwen2.5:0.5b` 够用；回答限制在 30 字内 |
| 想要更聪明的问答/工具调用 | 面板切 `qwen2.5:1.5b` 或 Doubao（注意内存/联网） |
| 断网演示 | LLM 会退 Mock；TTS 切 `piper`；ASR 与视觉本地可用 |
| 识别画面物体 | 依赖 TFLite/NanoDet，不是 LLM；只支持 COCO 80 类 |
| 自由描述画面内容 | 本地做不到，需要云端 VLM 或局域网 PC 上的多模态模型 |
| 2 GB 内存板卡 | 0.5B + whisper `tiny` + 只开必要识别项 |

## 一句话总结

**四类模型、一条降级链**：Qwen2.5（`0.5b`/`1.5b`，可换 Doubao）负责说话，faster-whisper 负责听，
edge-tts / Piper 负责发声，OpenCV 系模型负责看；任何一环不可用都有本地兜底，整车不会因为某个模型缺失而起不来。
